# 用户自定主题浮窗编辑器与实时预览计划

> 本文记录将现有“用户自定主题”编辑器改为游戏界面上的浮窗式工作台，并让编辑过程直接作用于当前运行时预览的设计与落地结果。本文不改变主题权限来源、用户主题数据协议或安全边界。

## 1. 目标

- 编辑器停留在当前游戏界面上，以浮窗或窄屏底部抽屉形式打开。
- 预览直接复用真实游戏界面的顶部栏、中部信息栏、左右面板、轮盘、背景和允许覆盖的组件。
- 颜色、图层、组件锚点和相对偏移修改后，当前游戏界面实时更新。
- 未保存的编辑只存在于运行时预览层，不写入 `PlayerState`、不进入存档。
- 保存、取消、关闭、切换场景和剧情演出时，主题层级保持可预测。
- 继续要求至少一个 Active Affector 提供 `user-theme.editor` 能力；不绑定具体 GlobalEnh ID。

## 2. 当前问题

| 问题 | 现状 | 影响 |
|---|---|---|
| 编辑器与游戏界面脱节 | 旧版弹窗内部使用独立的 `user-theme-preview` 模拟区域 | 玩家无法直接判断真实界面效果 |
| 预览范围过小 | 主要展示中部信息栏示例 | 顶栏、左右栏、轮盘和背景层的效果不可见 |
| 颜色更新不完整 | 颜色输入主要更新模拟预览 CSS 变量 | 实际游戏界面不会同步变化 |
| 编辑器承载方式不自然 | 主题编辑器依附通用 Modal | 容器与原生游戏工作区的关系弱，容易产生“外置工具”感 |
| 结构更新成本偏高 | 编辑控件、模拟预览和真实主题运行时边界不清晰 | 组件增多后容易整块重绘或布局抖动 |

## 3. 设计原则

### 3.1 视觉主题

采用“真实游戏界面 + 轻量浮层检查器”的方向：当前游戏场景是主体，编辑器是贴在右侧的紧凑、可拖动工具浮窗；删除装饰性模拟预览、压缩间距，优先复用已有主题、间距、边框与动效系统。浮窗不使用背景虚化，避免遮挡玩家对真实界面的观察。

### 3.2 内容结构

浮窗只承担四项职责：

1. 展示能力状态和当前编辑会话；
2. 编辑颜色 Token；
3. 编辑受控图层和组件位置；
4. 取消、重置、保存并应用。

真实游戏界面承担所有预览职责，不再维护第二套模拟界面。

### 3.3 交互动效

- 打开时浮窗从右侧轻量滑入，背景游戏界面保持稳定；
- 颜色变化使用即时 CSS 变量过渡，不重建游戏页面；
- 取消或关闭时预览层平滑移除，恢复已应用主题；
- 支持 `Esc` 关闭，存在未保存改动时先显示确认状态。

## 4. 目标布局

### 4.1 桌面端

```text
┌──────────────────────────────────────────────┐
│ 当前游戏界面                                  │
│                                              │
│                         ┌──────────────────┐ │
│                         │ 用户自定主题      │ │
│                         │ 能力状态 / 关闭    │ │
│                         ├──────────────────┤ │
│                         │ 颜色 / 图层 / 组件 │ │
│                         │ 独立滚动检查器     │ │
│                         ├──────────────────┤ │
│                         │ 撤销  重置  应用   │ │
│                         └──────────────────┘ │
└──────────────────────────────────────────────┘
```

- 默认右侧停靠；
- 建议宽度 `360–420px`；
- 高度使用 `min(760px, calc(100vh - 32px))`；
- 浮窗内部独立滚动，不改变主游戏工作区布局；
- 提供收起按钮，收起后保留一个可识别的主题编辑入口。

### 4.2 窄屏端

- 浮窗改为底部抽屉；
- 高度使用 `min(70vh, 620px)`；
- 导航改为横向滚动；
- 预览继续显示在抽屉后方的真实游戏界面中；
- 避免页面横向溢出。

## 5. 编辑内容

### 5.1 状态区

显示以下信息：

- `用户自定主题`；
- `编辑服务已开放` 或 `编辑器只读`；
- Active Affector 能力来源数量；
- 草稿是否存在未保存修改；
- 当前主题是否已启用；
- `取消`、`重置`、`保存并应用`。

没有 Active Affector 时仍可打开入口查看当前主题，但所有修改控件只读，且不能建立可写预览会话。

### 5.2 颜色 Token

继续使用固定白名单：

`primary`、`primaryStrong`、`bg`、`bgAlt`、`panel`、`panelAlt`、`text`、`muted`、`accent`、`danger`。

每个 Token 提供：

- 原生颜色选择器；
- 当前色值；
- “清空”操作；清空后删除当前层的 Token 声明，由上一层颜色接管；
- 影响范围提示。

颜色输入只更新当前编辑会话的 draft，并通过预览层同步到真实页面。

### 5.3 图层

只允许编辑已声明且已通过校验的图层：

- 图层所属区域；
- 图层顺序；
- 图层类型；
- 已注册图片资源；
- 受控颜色值；
- 显示/隐藏状态。

不开放任意 CSS、HTML、Selector、脚本、`url(...)` 或未注册图片地址。

### 5.4 组件位置

继续支持组件相对父级的定位编辑：

- 父级：整体、顶部栏、中部信息栏、左右栏、剧情区等；
- 锚点：左上、右上、左下、右下、中心；
- X/Y 偏移；
- 受控单位：`percent` 或有限范围的 `px`；
- 恢复默认位置。

组件位置变化应直接作用于真实页面中允许用户主题覆盖的组件，不再只改变模拟预览节点。

## 6. 运行时预览层

### 6.1 层级

用户主题编辑预览应接入现有 `RuntimeThemeManager`，推荐层级为：

```text
默认主题
  → 玩家主题
  → 用户已应用主题
  → 用户编辑预览层
  → 剧情/演出临时层
```

编辑预览层优先级高于已应用用户主题，但低于剧情演出等临时层，避免编辑器遮蔽必须优先显示的演出主题。

### 6.2 生命周期

建议增加以下运行时能力：

```ts
beginPreview(draft): PreviewSession
updatePreview(sessionId, patch): void
clearPreview(sessionId): void
commitPreview(sessionId): void
```

具体命名可按现有 Runtime API 调整，但必须满足：

- 预览层不写入 `PlayerState`；
- 不进入存档和导出数据；
- 关闭、取消、异常和切换场景时可清理；
- 保存仍通过 `UserThemeService.apply()` 和 `StateMutationService`；
- 正式保存后由状态事件重新同步已应用主题。

## 7. 实时更新边界

| 修改 | 更新范围 | 是否整页重渲染 |
|---|---|---|
| 颜色 Token | CSS 变量、背景和受影响面板 | 否 |
| 背景图层 | 背景层 DOM | 否 |
| 图层顺序 | 背景层容器局部重排 | 否 |
| 组件锚点 | 当前组件定位样式 | 否 |
| X/Y 偏移 | 当前组件 `transform` 或定位变量 | 否 |
| 区域选择 | 浮窗选中状态与目标区域 | 否 |
| 保存 | 服务校验、正式状态、只读视图 | 是，可接受 |
| 取消 | 移除预览层并恢复主题 | 否，优先局部恢复 |

颜色选择器和连续拖动输入使用 `requestAnimationFrame` 合帧；组件定位输入只修改当前组件，避免触发 `ctrl.render()`。

## 8. 安全与校验

编辑器不得把用户输入直接拼接为可执行内容，继续采用三层防护。

### 8.1 控件层

- 颜色只能通过原生颜色控件或严格格式输入；
- 图层、区域、父级和锚点只能从枚举选项选择；
- 数值控件设置最小值、最大值和步进；
- 资源选择只展示已注册资源。

### 8.2 服务层

`UserThemeService.validateDraft()` 继续检查：

- Token 是否属于白名单；
- 颜色格式是否合法；
- 偏移是否在范围内；
- 父子组件是否形成循环；
- 图层与组件数量是否超限；
- 图片是否为已注册资源；
- 文本长度是否超限。

### 8.3 渲染层

- 文本统一经过 `escapeHtml`；
- 图片统一通过 `PicService` 解析；
- 主题值只写入 CSS 变量或受控 DOM 属性；
- 不执行任意 CSS、HTML、Selector 或脚本；
- 预览与正式应用使用同一套安全渲染器。

## 9. 实施阶段

### 阶段一：浮窗承载

- 新增游戏页面内的主题编辑浮窗挂载点；
- 将现有主题编辑器从通用 Modal 迁移到浮窗/底部抽屉；
- 保留现有入口、能力判断和保存服务；
- 完成关闭、取消、只读和响应式布局。

### 阶段二：真实界面预览

- 为 `RuntimeThemeManager` 接入临时预览层；
- 打开编辑器时创建预览会话；
- 颜色、图层和组件修改实时反映到真实游戏界面；
- 取消和关闭时清理预览层。

### 阶段三：局部更新与性能

- Token 修改只写入对应 CSS 变量；
- 组件定位只更新当前节点；
- 背景变化只更新背景层；
- 连续输入使用动画帧合并；
- 编辑过程不调用完整页面渲染。

### 阶段四：测试与回归

- Active Affector 能力闸门测试；
- 预览层创建、更新、清理测试；
- 颜色实时更新测试；
- 取消不修改 `PlayerState` 测试；
- 保存后正式主题与预览一致测试；
- 预览层不覆盖剧情临时层测试；
- 恶意颜色、图片、结构和偏移输入校验测试；
- 桌面、平板、手机布局测试。

## 10. 验收标准

- 主题编辑器可在当前游戏界面上以浮窗方式打开；
- 玩家无需离开当前场景即可观察主题变化；
- 修改颜色后真实界面即时变化；
- 预览不写入正式状态，不影响存档；
- 取消后主题恢复到编辑前状态；
- 保存后正式主题与预览结果一致；
- 剧情/演出临时主题优先级不被编辑器破坏；
- 未获得 Active Affector 时仍完全只读；
- 输入不存在直接注入路径；
- 编辑过程不触发整页重渲染；
- 移动端无横向溢出；
- `npm test`、`npx tsc --noEmit`、`npm run check:architecture` 和 `npm run build` 通过。

## 12. 当前落地状态

已落地核心链路：

- 主题编辑器改为非阻塞右侧浮窗，窄屏时改为底部抽屉；
- 增加独立的运行时草稿预览层，优先级低于剧情演出层；
- 颜色修改直接刷新运行时主题变量；
- 图层与组件修改刷新真实游戏界面；
- 关闭/取消会清理预览层并丢弃编辑会话；
- 增加浮窗外壳与预览层优先级测试。
- 浮窗默认宽度收紧为 `420px`，桌面端右上停靠，可拖动；窄屏端为底部抽屉。
- 移除独立的大型 LIVE PREVIEW、装饰性预览节点与背景虚化，真实游戏界面始终作为背景参照。
- 颜色 Token 支持清空，清空结果以未声明字段保存，并显示“跟随上一层”。

后续可继续细化未保存关闭确认和更细粒度的组件局部更新。
