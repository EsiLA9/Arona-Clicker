# 信息可知系统

> 本文档定义"玩家能知道多少"的分层机制。
> 核心：可见性、数值揭示与解锁条件统一由 `revealTriggers` 系统表达——
> `reveal: 'existence'` 目标决定**实体是否出现**（原 `visibilityCondition` 的职责，已并入本系统），
> `reveal: 'unlock'` 目标决定**实际解锁 / 自动解锁条件**（原 `unlockCondition` / `autoUnlockCondition` 的职责，engine 直接消费），
> 其余目标决定**数值是否揭示**。未满足 existence 门槛的实体不出现，
> 出现但未满足揭示条件的实体以遮挡形式呈现。

## 动机

传统实现只区分"看得到 / 看不到"。但放置类游戏需要更细腻的信息节奏：

- 看到存在但不知道数值 → 产生好奇与目标感
- 知道数值但未拥有 → 形成购买/升级动机
- 拥有并完整展示 → 操作与反馈

如果直接隐藏所有未拥有实体，玩家无从规划；如果全部展示，则丧失探索感。
信息可知系统在两者之间提供分层。

## 分层模型

每个实体的信息状态由两层独立决定：

### 第一层：实体可见性（Entity Visibility）

决定实体**是否出现在界面**。由 [[04-systems-modules#VisibilityEngine]] 依据 `revealTriggers` 中
`reveal: 'existence'` 的 Trigger 判定（无 existence 门槛 = 默认可见）。

- `visible = false` → 实体完全不渲染（Hidden）
- `visible = true` → 实体可渲染，但具体能看多少由第二层决定

### 第二层：数值揭示度（Value Reveal）

决定实体**已揭示多少具体数值**。由持有状态/解锁状态控制。

| 揭示度 | 语义 | 界面表现 |
|--------|------|----------|
| `Hidden` | 实体不存在于界面 | 不渲染 |
| `Obfuscated` | 实体可见，但未满足揭示条件 | 名称/描述/标签可见；具体数值显示 `???` |
| `Revealed` | 满足揭示条件 | 全字段完整展示 |

### 判定规则（当前原型）

- **Spot**：`持有（level > 0）` → `Revealed`；否则 `Obfuscated`
- **Enhancement**：`已激活` → `Revealed`；否则 `Obfuscated`
- 所有实体：existence 门槛不满足 → `Hidden`（无 existence 门槛默认可见）

## 玩法优先级原则（重要）

Obfuscated 不等于"全部数值遮挡"。**字段级揭示**依据玩法优先级决定哪些信息必须可见：

> 玩家决定"要不要获得/购买"时，最需要的信息是：**如何达成（解锁条件）、成本（价格）、收益（倍率/作用范围）**。
> 这些必须始终可见。只遮挡**运行期数值细节**（如最大叠加层数、附带效果明细）。

### Enhancement 字段优先级

| 优先级 | 字段 | 未拥有时 | 已拥有时 | 理由 |
|--------|------|---------|---------|------|
| P0 | 名称 / 描述 | 可见 | 可见 | 身份信息 |
| P0 | 状态 | 未获得 | 已激活 | 持有状态 |
| P1 | 解锁条件 | **可见** | 可见 | 玩家需知道如何达成 |
| P1 | 购买花费 | **可见** | 可见 | 玩家需知道成本 |
| P1 | 产出倍率 | **可见** | 可见 | 玩家需知道收益 |
| P1 | 作用范围 | **可见** | 可见 | 玩家需知道影响哪些 Spot |
| P2 | 最大叠加 | ??? | 可见 | 运行期数值细节 |
| P2 | 附带效果明细 | ??? | 可见 | 运行期数值细节 |

### Spot 字段优先级

| 优先级 | 字段 | 未拥有时 | 已拥有时 | 理由 |
|--------|------|---------|---------|------|
| P0 | 名称 / 描述 / 标签 | 可见 | 可见 | 身份信息 |
| P1 | 获取条件 | **可见** | 可见 | 玩家需知道如何获得 |
| P2 | 等级 / 产出 / 容量 / 升级 | ??? | 可见 | 拥有后才揭示数值 |

## 与现有系统的关系

| 系统 | 职责边界 |
|------|----------|
| VisibilityEngine | 第一层：实体是否出现（`revealTriggers` 的 `existence` 目标） |
| 揭示度判定 | 第二层：数值是否揭示（持有/解锁状态，由 UI 层计算） |
| Affector 的 VisibilityInfluence | 可强制/压制实体可见性，间接影响第一层 |
| Hover 详情面板 | 按揭示度渲染 `???` 或真实值 |

> 说明：揭示度是**展示层**概念，不参与引擎逻辑判定。
> 引擎始终拿到完整数值；只有 UI 渲染时按揭示度遮挡。这样未来可扩展
> "揭示道具"（如情报强化使未持有 Spot 数值可见）而无需改动引擎。

## 克制边界

- 揭示度不持久化到存档（由持有状态推导）
- 不实现逐字段可配置的揭示条件（当前为整实体二档）
- 不实现"探索揭示"动画等展示特效
