# ai/guide/conventions/doc-maintenance — 文档分层与维护

> 本文回答：机制说明、Agent 约定、计划记录和历史材料分别应放在哪里。

## 内容归属

| 位置 | 责任 |
| --- | --- |
| `AGENTS.md` | 仓库级任务入口、稳定边界与必要约束；保持精简并导向专题页 |
| `docs/docs-830/` | 当前项目的 Wiki 式机制说明、架构、数据生命周期、领域流程、呈现与工具机制 |
| `ai/guide/` | Agent 路由、工程约定、上下文包、提示词和模板 |
| `ai/plan/` | 当前 Task、调查报告与验收资料 |
| `ai/archive/` | 退役计划与旧版文档系列；只供追溯，不作为当前事实或进行中任务 |
| `ui-style/` | 可跨项目复用的视觉约定与样式入口 |

机制页以源码和测试为准，解释稳定职责、主要数据流、边界及核对入口。Agent 指引规定协作方式，不重复维护机制正文；计划记录表达意图和阶段状态，不替代实现事实。

## 页面写法

- 用中文解释，保留代码/API 英文名；重要代码事实给出源码符号和路径。
- 机制页说明职责、协作关系、适用测试和深入阅读入口；关系图标注静态依赖、运行时调用、数据流或事件协作中的实际关系。
- 按稳定职责拆页，不按源文件或单次任务拆页；同一机制只保留一个正文权威点，其余使用 WikiLink。
- Agent 指引说清适用场景、步骤或边界；计划页记录目标、裁定、范围和状态，不把提案写成已实现事实。

## 链接、归档与退役

- 链向 `docs/docs-830/` 的机制页时，先检查 Obsidian 仓库中是否有同名 Markdown：唯一时使用 `[[文件名]]`；存在同名时使用 `[[从仓库根开始的完整路径|显示名称]]`。项目若是仓库的子目录，完整路径须包含该子目录。已有自定义显示名称和标题锚点应保留；无法确定裸名实际指向时，人工核实后改成明确路径。
- 名称碰撞检查包含归档和仓库中的其他笔记；归档正文不参与自动改写。Agent 指引使用 `[[ai/guide/...]]`；计划链接使用 `[[ai/plan/...]]`；退役材料使用 `[[ai/archive/...]]`。
- 执行 `npm run format:doc-links` 批量规范化现行文档中的机制 WikiLink；`node scripts/format-doc-links.mjs` 只预览，`--check` 在存在待规范化链接或不明目标的同名裸链接时返回失败。脚本自动定位最近的 `.obsidian` 仓库；不在仓库中时按项目目录检查同名。
- 只有当新页面完整接替旧页的职责和关键事实时，才标为已取代。局部更新只修正文相关部分。
- 归档保留当时状态和来源；恢复旧方向前，重新核对源码、测试和当前 Wiki，不直接把旧计划恢复为当前任务。
- 归档文档可保留历史结论，但其链接应指向新的有效位置。快照若被明确设为只读，不改写其正文。

## 静态核验

`npm run check:docs` 检查现行文档的 Markdown 路径、WikiLink 的目标、名称歧义和规范写法，以及文档结构规则，跳过归档正文；现行文档指向归档的完整路径仍检查目标是否存在。它不能判断机制解释是否符合当前实现。维护机制事实时仍需核对对应源码与测试，并明确报告实际运行过的检查。
