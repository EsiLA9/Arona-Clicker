# 调查 / 施工 Task 模板

> 需要持久跟踪、分派或交接时，复制到 `ai/plan/task-<全局编号>-<主题>.md` 并登记 `ai/plan/00-index.md`。普通小需求可直接完成。字段按任务需要增减，但需保留目标、范围、验收和实际结果。

```markdown
# Task：<可独立验收的结果>

状态：<待处理 / 进行中 / 完成 / 受阻> — <当前进展>

## 目标与范围

- 目标：<要交付的结果和需要解决的问题>
- 范围与明确非目标：<必要边界、依赖和约束>
- 验收：<可观察的完成条件>

## 当前进度

- [ ] <步骤及可观察结果；完成后记录关键结果或依据>
- [ ] <步骤及可观察结果>
- 正在进行：<当前工作及做到哪里；尚未开始则写明>
- 下一步：<具体要处理的工作及入口；完成后写无>

## 相关文件与资料

| 路径或链接 | 用途 | 当前状态 |
| --- | --- | --- |
| <源码 / 测试 / 文档 / 产物> | <需要读取、修改、验证或交付的原因> | <待定位 / 待核对 / 已核对 / 已修改 / 待验证等，并注明关键结果> |

文件表用于定位和记录进展，不是修改白名单；调查发现新的直接相关文件时按授权范围补充。不要把仅供参考的文件标成已修改。

## 事实与决定

| 问题 / 决定 | 已核实事实及源码、测试或文档依据 | 待解决问题 |
| --- | --- | --- |
| ... | ... | ... |

## 分工与整合（按需）

- <有分工时记录负责的具体工作、相关文件、交付结果及是否已整合、核对；无分工可省略>

## 验证与结果

| 检查对象与方式 / 命令 | 实际结果 | 失败后的排查与处理 / 未执行原因 |
| --- | --- | --- |
| ... | <通过 / 失败 / 未执行及证据> | ... |

- 当前结果：<实际修改的文件或调查结论、已知限制；区分已完成和待验证>

## 剩余工作与交接

- <未完成事项、阻碍和下一步；没有则写无>
- <文件变更时，记录地图只读复核及授权内维护情况或未完成原因>
```

根据 [[ai/guide/task-workflow]] 执行、记录和收尾；相关机制与状态边界以源码、测试和命中的规范页为准。
