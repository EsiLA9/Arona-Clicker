# Task 0436 · Datapack 拆合与快速层级化

状态：待验收

## 1. 任务目标与范围

为 Datapack 作者提供一套可先预览、再输出副本的文件转换服务。它能把混在同一 JSON 中的定义按表或按实体拆开，把指定内容或全包合并，也能按类型、Init、角色、故事系列或自定义规则重组目录。每次成功输出都可作为下一次操作的输入，作者可以逐步完成全拆、分组、选合和全合。

这是 [M01 文件组织能力（§4、M01-B）](../../docs/prototype-blueprints/AC-module-blueprints-v3/01-project-source.md) 的 B1/B2。交付公共计划和目录、ZIP 副本输出能力，先验收拆合，再在同一个服务上扩展层级化。

## 2. 当前实现

`src/data-services/datapack/fragment-parser.ts` 中的 `parseFragment` 识别顶层列表、三个单例、`extras` 与 `name/version`，`mergeFragments` 按输入片序拼接各表，后片覆盖同名单例和 `extras` 键。单靠合并后的 Datapack 无法找回被覆盖的声明、未知顶层字段或每条定义的位置。现有 `parsePack` 从 `PackSource.list()` 取得条目，独立读取根清单、JSON 分片和图片，再检查清单与合并内容的包名和版本。

`scripts/base-datapack-export.mjs` 的 `exportBaseDatapackFolder` 按顶层字段写盘，并复制资产、改写资产引用。`tools/datapack-editor/ui/io.ts` 的 `createDatapackPackage` 组装单内容分片的 ZIP。二者各自从已有数据组织输出，都没有可用于预览、选取原始声明和改派目录的共同计划。现有 `src/data-services/archive/archive-writer.ts` 能校验并写出 ZIP 条目，`validateArchivePlan` 会按路径排序，不能表达跨文件的逻辑声明次序。

## 3. 目标设计

### 转换计划与输出

公共 Datapack 服务接收一次完整的 `ProjectRead`。计划以该次读取的原值和 `occurrenceId` 为依据。一个文件可混合多表，一张表也可分布在多个文件。同 ID 的两条声明仍按各自源位置参与操作。包内位置只标识作者文件中的这次声明，实体游戏 ID 沿用原值。

| 入口 | 操作参数及结果 |
| --- | --- |
| `planSplit` | 完整读取结果、按表或按实体模式、可选路径覆写。返回拆分预览所需的计划。 |
| `planMerge` | 完整读取结果、全包或选中的源文件与声明、目标相对路径。选择文件表示选择它携带的内容；只选某些声明时，同文件剩余内容仍由原分片承载。 |
| `planGroup` | 完整读取结果、分组方式、需要的显式映射或自定义规则、可选路径覆写。返回各声明移动原因和待分组或共享候选。 |

下表规定计划需要承载的信息。字段名可随公共服务的既有类型调整。

| 计划内容 | 数据形状与用途 |
| --- | --- |
| 输入 | 本次读取的项目与包标识、快照引用。输出所需的声明原值和原文件字节来自该次读取。 |
| 声明放置 | 每条含 `occurrenceId`、表名、同表源序号 `ordinal: number`、源路径与源 Pointer、目标相对路径与目标片内 Pointer、移动原因。 |
| 输出文件 | 生成分片的目标路径和内容来源；保留文件的源路径、目标路径、保留原因；资产的路径和原始字节读取入口。保留原路径的文件或资产以原字节复制。 |
| 局部顺序 | 受影响表名及按逻辑次序排列的目标路径、片内 Pointer 和可取得的声明键。无须恢复的表没有此项。 |
| 诊断与预览 | 错误或待确认事项提供受影响的表、路径、可用的源位置及原因。预览由计划列出目标目录和文件、移动原因、共享或待分组候选和兼容输出排除项。 |

手动按声明或文件覆盖目标路径时重新规划，再由同一套校验检查路径越界、规范化后重名、文件与目录占用冲突及大小写碰撞。输入不完整、路径非法或选定合并无法无损完成时返回可定位诊断，停止受影响输出。预览和取消均不写盘。确认后把计划编译为现有 `ArchivePlan.entries`，由目录适配或共同 ZIP writer 生成新副本。

### 拆分与合并规则

| 操作 | 文件和内容如何处理 |
| --- | --- |
| 按表拆 | 各顶层列表用原表名包装为 JSON 分片；包元数据、`gearConfig`、`characterPersistConfig`、`affectionConfig` 和 `extras` 各有明确承载位置。保留可无损携带的未知字段。 |
| 按实体拆 | 每条定义连同原表名一起移动，例如一个 Spot 放入 `{"spots":[…]}`。无可靠名称时用安全、稳定且可回读的文件名，无法保证时留在表文件供作者处理。内部节点、边、条件、效果和池子项随宿主整体移动。 |
| 选中合一 | 选中内容合成一个标准分片。完全未选的文件以原字节带出；只选中部分声明的混合文件重写剩余内容，保留它的其余字段。 |
| 全包合一 | 合出一个内容 JSON，沿用输入形式应有的根清单与包身份，资产及应保留的其他文件独立随附。单 JSON 输入沿用其已有身份，发行所需身份按现有打包要求提供。 |

重复 ID 保留各条声明及其源位置。重复单例、冲突的 `extras` 键或未知字段不能无损合一时，指出发生冲突的两个源位置，保留原分片并拒绝该合一。未知顶层字段留在原结构或可无损携带的分片中，保持原键。资产的包内相对路径和原始字节保持一致。任何输出均保留输入原件。

### 快速层级化

类型模式按顶层表安排文件。Init 模式以 `Area.initId` 为直接归属，Spot 通过 `Spot.areaId` 查所属 Area；Story 可读 `Story.initId`、`Story.directoryId`，Entry 用 `storyId` 关联 Story，并参考 `availableInits`。角色可经 `StoryDirectoryDef.characterId` 或显式映射确定。故事系列使用作者已声明的目录路径、存在时的 `hierarchyString` 或显式映射。缺归属进入待分组，多归属进入共享候选，作者可在预览中明确去向。

自定义规则可匹配表、源路径或显式选中的 `occurrenceId`，并指定目标相对路径。预览显示每个目标文件的来源和采用该规则的原因；作者可覆盖文件或单条声明的目标后再校验。分组只调整作者文件位置，实体 ID、Story 游戏目录、条件和父子引用保持原值。

### 顺序与回读

实体内部数组保持原值原序。顶层表默认保持读入时的逻辑次序。只有从真实消费者证明该表按稳定键消费，或排序有稳定次级键且重复或覆盖不受次序影响时，才允许换序。已有行为证据是 `PassivePoolSystem.pick` 按 `passivePools` 根和 `passiveStories` 的枚举累积权重，换序可能改变同一随机输入命中的条目。Trigger 同 ID 后挂载覆盖和显示项的同值排序也要对照；其余未判定表保持原序。

先用现有枚举和片内顺序表达逻辑次序。若 A 与 C 放进同一文件、B 放进另一文件，任一文件先读都会打乱 A/B/C。这时仅为受影响的表记录按逻辑次序排列的目标相对路径和片内 Pointer，例如 `chapter-1.json#/stories/0`、`chapter-2.json#/stories/0`、`chapter-1.json#/stories/1`。局部记录可放在旧读取器会忽略的非 JSON 附属文件，首轮采用按需记录的方式。共享读取验证覆盖范围、重复位置、目标存在性及可获得的声明键。记录损坏时按 0435 返回不完整诊断，保留可查看的来源，停止生成严格合并投影。下一次转换根据回读后的逻辑投影重算记录。

如果无法可靠恢复原序，预览给出受影响的表和顺序差异。作者可以保留相关分片或修改目标重试，也可以显式确认输出带提示的作者副本；该副本不标为运行兼容产物。需要给旧解析器使用时，生成已按核实顺序合一的标准分片。会被旧解析器误读的作者附属文件按实际角色排除，并在兼容输出预览中列出；作者副本仍保留这些文件。

## 4. 施工方案

先承接 0435 的包清单、来源记录、原值、快照字节和每表源序号，建立公共计划及对分片外形的复用。把按表拆与全包合一作为首个闭环：同一份计划先供预览，再生成目录和 ZIP 条目，输出后用公共读取入口复核定义、清单、顺序和资产。复用 Base 输出已有的顶层分片经验和归档模块的路径校验、序列化与 ZIP 写出；目录适配遵守同样的计划校验，并只接受新输出位置。

在同一计划中引入来源选择及目标覆盖，完成按实体拆和选中合一。通过声明位置定位选中内容，重建目标分片和源混合文件余量；对完全未选文件直接复制字节。补齐重复声明识别、单例和 extras 冲突定位、未知字段保留与预览拒绝。重读每次输出，建立下一次操作需要的新来源位置。

拆合闭环通过后接入类型、Init、角色、故事系列和自定义分组，把规则计算和作者手工覆写转换为同一组声明放置记录。对路径合法却发生顺序交错的输出，在共享读取链路接入局部位置校验与恢复，再对照旧解析器的有序合一输出。完成后将同一读入、计划、预览和副本输出入口交给 0437 的独立编辑器及 CLI。

## 6. 验收标准

用 `datapack-dev/addition_test/` 的副本走公共服务，按表拆、按实体拆、分组、选合、全合。每步完成后重新读取该步输出，再执行下一步。对照原定义值、应保留的表顺序、未选文件、混合文件余量以及资产字节。用 Base 副本验证同一入口能处理现有表规模。

用交错 A/B/C、同值排序及固定随机输入下可观察到的 Passive Entry 结果验证保序。目录和 ZIP 都能重读并恢复逻辑顺序。损坏局部顺序记录时可定位诊断，严格投影不可用。旧解析器能读取有序合一产物。另以有具体消费者依据的无序表验证可自由分组。

重复声明仍可按位置选择，未知字段在可无损处理时完整带出，无法合并时能定位冲突。取消预览、路径越界、重名和大小写碰撞不产生副本；显式接受顺序差异时能在预览和产物用途上识别作者副本。现有分片、归档和 Base 导出测试用作兼容对照，并为连续转换补定向测试。
