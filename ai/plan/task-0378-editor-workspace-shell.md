# Task：编辑工作区外壳与 Story／StoryEntry 首批接入

状态：待处理

## 目标与验收

在现有 Workspace 上增加可选的编辑器外壳。首批接入 Story 正文和 StoryEntry，统一命令、浏览视图和状态展示。为 Area 等编辑类型预留同样的装配入口，实际接入另行安排。

- 左侧 SVG 切换**工作类型**。Story／StoryEntry 属于同一个「故事编辑」工作类型。故事目录、发出方和 Story／Entry 筛选继续放在这个工作类型自己的导航栏。首批图标栏只显示可用的「故事编辑」入口。
- 顶部支持**命令页**和**浏览视图**。命令页决定看见哪组工具，浏览视图决定看见哪几栏。切换任一项都保留当前文档、草稿及节点选择。
- 三栏之间用可拖的细分隔线控制宽度。底栏用一行显示已载入来源、对象位置和草稿状态。正文输入区仍固定在中栏底部。

## 布局与行为草案

| 区域 | 首批设计 |
| --- | --- |
| 顶部固定行 | 左侧返回、工作类型和当前文档，右侧常驻「保存草稿」「试播」。保留全局游戏顶栏的职责。 |
| 顶部命令行 | 建议按「编写／试播／管理」分组。编写放新建与插入，试播放入口选择与直接试播正文，管理放检查、保存到编辑态包、应用到当前游戏和数据包管理。沿用原命令与禁用原因，迁移后清理列底部的重复入口。Flag 绑定、节点改名等行内动作继续就地操作。 |
| 顶部浏览视图 | 使用独立的「浏览视图」选择器。建议首批提供「三栏」「双栏查阅」「专注内容」。「三栏」显示导航、内容和检查器，「双栏查阅」保留导航与内容，「专注内容」只显示中栏。左侧工作类型栏和顶部视图入口在三种模式下均可用。StoryEntry 的「基本信息／奖励信息／详细门控」及 StoryNode 的属性页属于当前栏内部。 |
| 左侧工作类型栏 | 用小型 SVG 按钮、选中态和悬停名称表示切换目标。后续工作类型由宿主声明其图标、名称、可用性和导航动作。故事编辑的左列标题按钮继续负责目录／发出方切换。 |
| 三栏及分隔线 | 复用三栏的独立滚动区。可见分隔线建议 1px，拖动命中区约 8px。先沿用左 300px、右 320px，正文占剩余宽度。限制边栏宽度，避免挤压正文。双击分隔线恢复默认，按工作类型记住最近尺寸。 |
| 底部状态栏 | 左侧显示来源与编辑态／只读／保留草稿，中间显示当前 Story、Entry 或选中节点，右侧显示保存状态和已有诊断。仅在有诊断时提供定位入口，详情沿用已有错误位置。 |

## Workspace 接入方式

- 在 `workspace-page-content` 内提供可选的编辑外壳，安排命令区、工作类型栏、Frame 宿主和底栏。三栏根仍是 `WorkspaceFrame` 的直接子项，现有列 key、Presentation 宿主、`bodyOverlay` 和刷新机制继续使用。
- 外壳管理列宽、可见状态、命令页和浏览视图。Story Controller 提供内容、命令、权限和状态。按工作类型存布局偏好，与 Story／StoryEntry 作者数据、游戏存档分开。
- 分隔线只调整当前工作区的网格轨道。浏览视图隐藏某栏后，保留它的最近宽度、滚动和内部选项，恢复时回到原位。命令切换只更新命令区域。文档切换继续采用当前的前进／后退和导航定位机制。
- 现有目录管理和隔离试播应能从新外壳进入并返回。首批沿用它们原有内容及交互，目录和试播各栏的专用重排另行评估。
