# Task：编辑器左栏目录定位、管理与树形行统一

状态：待验收

## 目标与验收

- 切换 Story／StoryEntry 浏览实例后，左侧目录定位到对应来源中的文件，展开真实祖先，滚动到可见并聚焦。目录管理保留实例条，能查看当前实例的目录，也能从目录管理切回任一实例。
- Story／StoryEntry 和世界目录共用行高、缩进、空心 Chevron、辅助线和选中背景。Story／Entry 左侧使用各自 SVG，目录行的「管理」胶囊改为常显齿轮。
- 世界仍使用一个只读实例。中栏父子链接、左栏选中项和「定位选中项」定位同一个世界节点。三栏、双栏和专注继续沿用现有框架。

## 当前依据与改动方案

### 1. 浏览实例恢复后定位目录

- `src/ui/story-editor/controller.ts` 的 `restoreBrowseInstance()` 清空待定位状态，恢复文档后安排 `restoreInstanceScroll`，没有安排高级模式下的目录定位。「定位」命令已有同步左栏资料来源、切回目录模式和设置 `sidebarReveal` 的入口。提取这段状态准备给定位命令和成功激活实例共用。已激活标签再次点击也作为定位请求。新建／打开文档实例在目标确认后接入同一入口。左栏发起的普通选档保留当前按钮焦点。
- 定位以恢复后的 **来源 + kind + id** 为准。先切到合法的实例来源并同步左栏目录投影，再用 `sidebarReveal` 让目标通过临时筛选，保留输入框里的搜索词、分类、Init 筛选和其他枝条的折叠选择。沿用 `sidebar-tree.ts` 的 Init 优先规则消解同一个 Entry 的多处放置，并让选中标记、祖先展开和聚焦使用同一条实际路径。正在定位时只覆盖该路径的手动闭合，处理跨 Init 和延迟挂载的目录，避免选中同名或同 ID 的其他来源。
- 在现有 `refresh()` 的 DOM 协调中，先恢复实例的滚动，再完成目录显露。让 `revealSidebarSelection()` 只操作左栏滚动宿主，展开后重新取得仍连接的真实行，按最近边缘滚动，最后 `focus({ preventScroll: true })`。显式定位和实例条激活时允许打开左栏，三栏状态保留。保存失败或实例不可用时保留既有判定和反馈，不启动错误目标的定位。弹窗预览、正文输入和普通区域刷新沿用当前焦点行为。
- `src/ui/controller/controller.ts` 的 `bindWorldBrowser()` 已使用 `worldTreePath()` 处理世界中栏链接和「定位选中项」。将两处重复的展开、更新选中、滚动与聚焦集中在此绑定内，保留按节点 key 区分同一 Area／Spot 多个目录位置的规则。中栏链接在专注模式先打开双栏再定位，三栏模式保持原视图。点击世界的单实例标签时，通过同一入口定位当前节点。

### 2. 目录管理兼容浏览实例

- `src/ui/story-editor/view.ts` 目前将目录管理和试播同时标记 `temporaryView`。`src/ui/workspace/editor-workspace.ts` 据此隐藏实例条，`bindWorkspace()` 的目录管理分支也只处理返回。给现有框架传入明确的独立可见条件，使高级模式的目录管理继续渲染浏览实例条，仍使用临时三栏和「返回编辑」工具。试播维持原可见性。目录管理期间实例条只提供激活与关闭，隐藏新增／复制等当前分支不受理的操作。
- 先让实例激活／关闭事件走已有 `activateBrowseInstance()` 和 `closeBrowseInstance()`，再进入目录管理的专用工具分支。切换到另一实例或关闭活动实例时，先通过原保存门禁，再由 `restoreBrowseInstance()` 收起旧管理页、恢复目标实例并定位。点击当前实例标签等同「返回编辑」并定位一次。关闭后台标签时保留当前目录管理页。保存失败保留实例、列表及管理页；目录管理自身的表单退出语义沿用现有返回路径。
- `editStoryDirectory()` 已区分 `story`、`entry`、`folder` 和 `browse`。「目录」按钮在存在可用活动文档时，改为用其实际 kind 打开正文／入口的目录上下文，保留当前来源、资料包归属和只读判定。此时默认定位该文档在选中 Init 下的实际目录。目录行齿轮继续走带 `directoryInitId`、`directoryFolderId`、`directoryOwner` 的明确位置，空实例仍进入通用目录浏览。返回编辑恢复原实例、节点及中右栏滚动。世界的目录管理范围仍是只读资料查看。

### 3. 共享目录行、图标和层级线

- 从 `src/ui/workspace/editor-directory.ts` 的 `renderEditorDirectoryRow()`／`renderEditorDirectoryToggle()` 开始。目录节点统一为 `li > 行容器 + 可选的子 ul`，行容器内顺次排列 Chevron 或等宽占位、名称按钮及可选类型图标、尾随说明与独立操作。保留稳定的 `data-editor-key`、选择和管理数据属性。Story 文件按钮、世界节点和管理区可展开目录接入同一个 Chevron 模板。保留原可点击的折叠命令，叶节点用同宽占位。用一枚描边 SVG 随 `aria-expanded` 旋转。`setEditorDirectoryExpanded()` 只更新 `aria-expanded` 与直属子列表的 `hidden`，管理区仍由自己的导航状态驱动。
- 在 `src/ui/css/story-editor.css` 给共享行定义一个行高、一档逐级缩进和固定箭头操作宽度。由真实子 `ul` 绘制 1px 纵线，线位对齐直接父节点的 Chevron，中间不中断，不画横向连线。活动路径用选中后代或已有路径状态提高线条对比；折叠列表及无子节点不出线。选中背景覆盖整行，沿用主题表面与对应文字角色，取消边框和左侧内阴影。普通行 hover 比选中色略浅，选中行 hover 保持选中色，焦点仍清晰。让名称可省略，尾随状态和齿轮不挤占箭头，规则应用到任意深度。
- `sidebar-tree.ts` 的行尾「管理」使用 `editorToolIcon()` 系列的齿轮 SVG，可在现有图标表补一个 gear 路径。按钮常显，改用同宽的独立无边框操作位，默认较浅，仅在齿轮自身 hover 时加深；保留 `aria-label`、`title`、点击范围和管理事件。共用齿轮呈现方式处理同类行内管理入口，带明确文字命令的工具栏按钮维持原形态。
- `view.ts` 的 Story／Entry 实例条当前使用 CSS 着色方块。将现有 Story 书本 SVG 提取为文档图标定义，核对 Entry 是否已有独立 SVG，有则复用，否则补一个区分明确的 Entry SVG。由实例条和文件行共同调用，保留目录名、标签和来源提示。样式规则限定在目录行和这两类图标，条件树及关系卡使用原样式。
