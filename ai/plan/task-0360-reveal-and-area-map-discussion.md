## 玩法关注点与候选体验

用户关注的是便利移动与渐进探索的平衡。以下是助手提出的体验方案，尚待讨论确认：

- 地图提供方向感与行动便利，但浏览地图不自动记录到访、调查或领取。知道地点名称、看见布局，也不等于已经探索其中内容。
- 商场导览可以提前公开大厅、电梯和走廊；电梯开放后可以首次抵达二楼，但二楼仍标记未到访。走廊尽头可以只显示匿名店铺，首次经过保留告示、剧情与支路发现；探索后可便捷返回。
- 内容可以处于“知道但不可达”“可达但未到访”“已到访但目前道路中断”“可领取但尚未领取”“曾获得但已消耗”等不同组合，不应被压成一个解锁阶段。
- 到访、调查、领取彼此独立；进入房间不等于调查全部物件，也不默认公开隐藏用途与所有条件。仅在玩法需要时记录对应经历，不给每个对象强加全套状态。

用户补充：部分 Area / Node 天生适合轻松探索，可以在进入所属地图，或更简单地在可知后直接前往，不必逐段挪动；希望作者能通过简单的节点 Reveal 设置表达这种便利。地图被获得后，应能便捷前往其中相应节点；未来地图界面还将提供已获得地图的快速切换指引。同时需要安排步调，避免所有内容都变成同一种直达结构。具体获得、揭示与移动条件之间的关系继续讨论，不把这一需求固定为全局默认行为。

助手补充例子：获得海滨导览后，沙滩、咖啡馆与灯塔可直接前往，但仍标记未到访；灯塔地下室在调查后才出现，并可保留沿通路探索。一张图内允许不同移动节奏。

## Reveal 候选语义

- 分开处理三条轴：玩家知道什么；当前能做什么；实际做过什么 / 拥有什么。“曾获得”与“当前持有”也应区分。
- 信息暂按存在、身份、内容、方法四个信息面讨论，彼此不强制构成阶梯。例如先知道北侧有门及所需通行证，之后才知道门后是研究所与其用途；知道要求不等于满足要求。
- 已学会的知识通常保留；营业状态、道路是否完好等当前事实随世界变化。资源达标可以成为一次知识获得契机，不应因花掉资源自动遗忘名称。改名、伪装揭穿或遗忘等特殊玩法需明确表达。
- 知识可由获得导览、实际进入、调查告示、剧情告知或首次满足进度条件授予。导演安排的介绍应能同步形成可被各界面使用的知识；进入后默认认识地点身份只是候选便利规则，更深信息由内容安排。
- 候选拆分：把进入 / 获取等动作许可从 Reveal 的 `unlock` 中分出；把世界中存在、玩家知道其存在、当前地图是否画出分别表达。具体替代名称与迁移方式未定。

## Map 与移动候选语义

- Area 是世界位置，Map 是经过编排的观察窗口，不拥有 Area。节点与画线本身不自动授予通路，但作者明确声明的导览直达节点可以提供移动能力。多个地图可引用同一地点；开子图、返回、查看楼层只改变浏览状态，不改变实际位置。
- 实体知识与地图表达分开：地图可省略已知地点，也可用“异常信号”等局部提示指向未知目标。提示文字不自动公开目标真实身份；若导览确实告知名称，应明确授予知识。
- 作者可安排完全隐藏、匿名线索、已知但受阻、地图切换、普通说明和可前往地点等节点表现；隐藏目标是否留下匿名节点取决于内容意图。
- 节点暂按“沿通路探索”与“导览直达”两种移动设定讨论。前者按真实连接与探索进度推进：普通直接连接允许首次进入，已探索通路允许便捷移动，未知普通中间地点暂建议需要停下；后者可在地图已获得且节点达到指定揭示程度后直接前往，不要求已到访或逐个走完中间普通节点。电梯 / 列车 / 传送也可提供首次抵达能力。以上名称与默认规则均待裁定，不能把所有首次探索统一要求为逐段经过。
- 便捷移动只产生实际目的地的本次进入，不重播中间地点进入事件，也不自动调查沿途内容。“穿过未知路线并在途中遭遇事件”若需要，应作为有过程的旅行另行讨论。
- 导览直达省略的是途中移动，不自行越过目标明确要求的钥匙、剧情封锁等限制；若获得地图本身就代表通行许可，应明确使其满足相应要求。候选能力依赖地图获得事实，而不依赖当前正打开哪张图；由旅行查询统一识别，地图与侧栏保持一致。
- 世界连接、玩家已知连接和本次可通行路线分开；可用、受阻、未知和未确认线索应有可理解的表现。已知桥梁损坏可保留为受阻连接；交通网络不必展开成所有成员两两连线，选中目的地时再说明此次抵达方式。

## 地图获得与简单作者设置（候选）

- “地图已获得”是本轮拟引入的持久概念，不把现有临时浏览会话当成已经支持。可称“已收录”，不要求一定对应背包物品；地图可知、已获得与当前可查看应分清。
- 进入区域、获得导览、剧情介绍或首次打开公开地图都可成为获得契机，由内容安排；仅预览不必自动获得。获得地图后加入地图界面的快速切换指引；获得地图不等于到访图中地点，也不自动公开全部隐藏内容。
- 用户希望简单设置节点 Reveal 即能表达直达。助手提出的编辑体验是一个“揭示后允许导览直达”选择：底层仍区分信息揭示与移动能力，不把所有揭示默认解释为直达，也不要求作者反复配置整条移动逻辑。
- “地图已获得 + 节点存在已揭示”可作为直达生效条件的候选；也可在玩法需要时等到身份揭示。允许前往匿名地点，真实名称 / 用途不必全部公开。进入地图即可直达与可知即可直达如何统一成最简单的作者设置，尚未裁定。
- 候选最小增量是地图获得事实与节点移动设定；直达能力按获得、揭示和当前进入要求派生，不另外保存每个节点的永久直达解锁。获得地图 ≠ 已到访，节点可直达 ≠ 已抵达，可获取 ≠ 已获取。

## 潜在抽象数据模型（非字段规格）

| 候选结构 | 可能承担的内容 |
| --- | --- |
| 世界与内容定义 | Area、物品、奖励、真实连接、交通及具体动作要求 |
| 地图定义 | 节点布局、目标引用、局部提示、连接表达与开图入口；节点可声明沿通路探索或导览直达及其生效要求 |
| 玩家事实 | 到访、调查、领取、曾获得、已掌握的知识，以及已获得 / 收录的地图；仅保存玩法实际需要的事实 |
| 当前运行状态 | 位置、资源、持有物、门禁、活跃交通和剧情阻塞 |
| 统一玩家查询 | 合成当前是否展示、各信息面公开程度、动作可用性、可公开的受阻原因、经历状态、导览直达等旅行方式与可切换的已获得地图；地图、侧栏和详情共同使用，执行动作时重新校验 |

作者操作可按“何时告诉玩家什么”“何时允许进入 / 获取”“实际行动产生什么经历”“地图怎样提示”组织，尽量复用既有能力，不为候选划分预建新系统。

## 后续讨论入口

- 永久知识与即时信息如何划界；到访默认公开哪些信息，哪些必须调查或经剧情告知？
- 地图提供的提示何时成为实体知识，何时只属于局部表现；未知节点允许公开哪些动作与方法？
- 哪些节点适合导览直达，哪些首次经过必须停留，怎样混合安排步调；什么才算通路已探索？
- 直达从存在、身份还是其他揭示程度开始生效；怎样把进入地图即可前往、可知即可前往等需求做成简单设置，而不混淆 Reveal 与行动许可？
- 地图获得契机、快速切图与开图准入如何配合；已打开后失去查看许可应如何表现？
- 最小模型能否复用现有知识事实、经历、条件与旅行查询；如以后实施，再讨论旧 Reveal、默认内容及存档语义，不在此预定迁移方案。
