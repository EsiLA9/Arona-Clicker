# Story／StoryEntry 编辑器界面语言调查

## 范围

调查游戏内 `src/ui/story-editor/`，覆盖左侧浏览、中栏 Story 节点流和 Entry 表单、右侧属性与目录管理，以及试播和常用选择器。记录以当前工作区源码、样式和相关用例为依据。尺寸为 CSS 声明或默认值，实际字体回退、主题色和空间占用留待宽屏浏览器核对。末节是后续统一升级的讨论底稿。

## 数据实体与显示位置

| 数据或语义 | 主要显示位置 | 当前内容语言与信息层级 |
| --- | --- | --- |
| `Init`、目录路径、`StoryDirectoryDef` | 左栏目录树；目录管理中栏「目录设计／内容概览」，右栏「层级与手动资料」 | 左栏主行先给世界线或目录名，同行小注给「自动／手动／路径／兼容」、资料数和直接内容数，最右是「管理」。右栏把当前路径、构造来源、手动资料候选及应用状态分开。路径可由内容自然构成，手动资料另有 ID、公开标题、简介、主题及其他字段。 |
| `StoryDef`、Story 草稿 | 左栏 Story 行；中栏标题及节点流；右栏「概述／关系／Flag表／其他工具包」 | 编辑时用作者名称识别 Story，ID 用于定位，目录行按需显示「草稿」。起始场景、公开简介、目录归属、调用关系各有自己的位置。中栏工具与草稿、检查、写包和应用等状态相邻。 |
| `StoryEntryDef`、激活方式、抽取池 | 左栏 `入口` 行；中栏「基本信息／奖励信息／详细门控」；右栏关系和 Flag 表 | Entry 以开幕标题识别，可回退到起始 Story 名或 ID。「主动接取／随机抽取／好感阶段」描述启动方式；「关联剧情」引用首个 Story，目录归属独立。「允许重读／不开放重读」以用户行为表达。奖励、触发、限制、抽取池分组，运营配置集中在对应页。 |
| `StoryNode`、`StoryAction`、Choice 选项 | 中栏可选、可拖动的节点；右栏节点类型、基础字段及演出设置 | Talklet 用角色名和正文，Click 与 Choice 用作者撰写的选项文字。Operation、Transfer、场景移动以系统或动作语气描述。引用按钮显示目标名称，必要时附完整 ID。字段属性、节点顺序、可选结构与旧数据诊断是作者工具。 |
| 局部 Flag、存档标记、回传 | 流上局部 Flag 按钮；右侧 Flag 表；条件字段与候选选择器 | 流上每颗按钮只显示一个 Flag ID，读取方放左侧，Choice 提供的标记放右侧。点击展开右栏对应项。右栏表达作用域、提供方、需求方、移除和回传声明。拖拽的「可绑定／已绑定／不可绑定」为临时反馈。存档标记在条件编辑中有独立名称。 |
| Story／Entry 引用、声明调用、剧情包 | 右栏「调用表／被调用表」、Entry 的「潜在调用集」、Story 的「剧情包」 | 调用行以 `Story／Entry · 名称` 为标题，独立一行 ID，再给调用原因。完整字段路径置于提示。剧情包以「直接起始／经剧情转移」说明 Entry 来源；该列表表达静态可达性，分支的真实结果由试播显示。 |
| 条件组、比较式、门控、奖励效果 | 正文属性、Entry 门控及奖励、条件树弹窗、试播条件记录 | 编辑侧按语义显示「判断对象、比较方式、比较值」，不同资源带各自名称和数值角色。试播把 AND／OR 表成「全部满足／任一满足」，同时区分真实结果「满足／未满足／未取得结果」与本次采用结果。资源、设施、角色、区域、强化等引用可用选择器定位。 |
| 发出方、Area、角色空间、ThemeDesign、图片 | 左栏「发出方」、中栏场景卡及演出、属性与目录设计 | 发出方以头像和名称识别；场景卡以地点或角色名称识别。主题、图片和背景资源是作者配置项。目录和演出预览可解析这些配置，呈现给玩家看的标题、简介和正文。 |
| 内容来源、数据包版本、草稿、编辑权限 | 左栏「内容来源」；工具、页尾状态与选包弹窗 | 来源涉及「当前游戏／本地包库／保留草稿」，写入时还有普通态、编辑态、是否已应用及目标包校验。保存草稿、保存到编辑态包、应用正文与关联内容是三个不同结果，动作文字应保留落点。 |

数据入口见 `src/data-services/contracts/story-node.ts`、`story-node-actions.ts`、`story-entry.ts`、`story-directory.ts` 和 `src/ui/story-editor/model.ts`。界面入口见 `view.ts`、`sidebar-tree.ts`、`directory-management.ts`、`property-fields.ts`、`authoring-view.ts`、`flag-catalog-view.ts`、`relations-view.ts`、`condition-fields.ts` 和 `preview-view.ts`，均位于 `src/ui/story-editor/`。

## 当前字体、字形与间距

| 语义层级 | 当前字号、字形和形态 | 当前间距与相关构造 |
| --- | --- | --- |
| 工作区标题和当前模式 | `.workspace-title` 用粗体标题；左栏模式是紧凑按钮加下拉箭头；Story 中栏历史导航与标题共行，Entry 有独立编辑页签。 | 标题宿主和 `header/body/footer` 来自共享 Workspace。Story 与试播左栏声明 `300px`，中右栏走 Workspace 宽度变量。面板内容内边距与区块间距的默认变量分别为 `14px`、`8px`。 |
| 目录名、行注、工具按钮 | 目录行 `13px`，分支 `600`；来源短注 `10px`、`400`，入口类型和管理按钮约 `11px`。树行文本可省略，提示补齐名称或 ID。 | 树行最小 `25px`、内边距 `2px 5px`。前几级可见缩进按 `9px`，展开按钮和管理键同行。左栏模式按钮最小 `26px`、`3px 7px`，正文侧与右栏工具还有自己的尺寸。 |
| 玩家正文、作者预览 | 全局 body 声明本地 Manrope／sans-serif。聊天气泡另声明 `方正兰亭圆简体_中`，NPC／玩家正文 `13px/1.7`，发出方 `11px`、`600`。Choice 选项 `13px/1.5`、`600`。仓库内 `@font-face` 注册了 Manrope 与 DM Mono，中文气泡实际使用的字形仍需看本机回退和主题。 | 聊天气泡 `6px 10px`、圆角 `8px`；Choice 选项 `10px 12px`、圆角 `6px`。编辑流还加可选节点外框、插入位、定位演出浮层与局部 Flag。正文由共享聊天组件决定，表单标签有独立密度。 |
| 表单标签、标题、提示 | 普通字段标签 `12px`，Entry、关系、工具和演出区常见小标题 `14px`，门控小标题常见 `13px`。字段值、行内教学与状态由各组件继承或局部覆盖。 | 属性列表常见 `10px` 间距，可选／属性组 `8px` 间距及 `10px` 内边距；Entry 区段间距和分隔为 `12px`，表单 Grid 为 `10px 14px`。性质相同的字段组现有边框卡、竖线分组、平铺分隔等多种构造。 |
| ID、字段路径、关系行 | 本地 **DM Mono** 已用于流上 Flag ID、关系 ID、Flag 明细及共享引用选择器 ID，多数为 `11px`。只读身份字段仍有 `14px` 继承样式，试播 ID 多是 `12px`，`<code>` 的标签语义与实际字体配置有差异。 | 关系行由 `14px` 名称、`11px` ID、`13px` 说明组成，行内 `3px` 间距、`6px 8px` 内边距，长 ID 可换行。流上 Flag ID 单行省略，`title` 补全；Flag 表展开后用 `11px` 等宽 ID 和紧凑来源行。 |
| 操作、状态与临时反馈 | `.mini-action` 基线 `10px`，编辑流工具局部用 `12px`，Entry 关联新增及试播检查点可到 `13px`。选中、不可用、错误、拖放与真实门控结果各有自己的属性或文案。 | 共享操作组间距 `6px`，编辑流紧凑组 `4px`。关系行、目录行、Flag、内容选择器分别使用边线、主题表面、颜色或透明度区分状态。Flag 配色按 ID 生成，侧栏 Flag 表用细色边，试播和跳转有独立反馈。 |

样式入口为 `src/ui/css/variables.css`、`workspace-controls.css`、`cards.css`、`editor-shared.css`、`story-editor.css`、`chat.css` 和 `chat-input.css`。共享布局与标题见 `src/ui/components/shared/workspace-frame.ts`、`workspace-titlebar.ts` 与 `tabs.ts`。基础主题角色见 [[ui-style/foundations]]，控件用法见 [[ui-style/patterns]]。

## 统一升级时优先核对

1. **先定文案角色。** 把玩家作者正文、编辑界面标签、技术 ID、运行诊断分开。明确「Story／正文」「Entry／入口」「Init／世界线」「Flag／标记」各在什么场景出现。实体可用中文动作提示出入口，术语和完整 ID 在需要精确定位时保留。例子可从「关联剧情／起始 Story」「内容来源／目标数据包」「被调用表／剧情包」开始。
2. **为名称、ID、说明和状态建立可复用排版。** 气泡正文以可读性为先，工具区域按内容密度定尺寸。同一实体在树行、关系卡与选择器都应用同一个名称和 ID 优先级。统一 ID 的字体和字重，按位置决定单行省略或可复制换行。优先核对只读身份字段、试播路线和目录候选。
3. **为行、字段组和卡片明确适用范围。** 导航、候选、引用及来源优先用紧凑行。普通字段按语义平铺。只有需要独立操作、预览或折叠的区块才使用边框卡片。规范同一组内、组间、栏间三种间距，并处理「管理」右对齐和固定操作栏。
4. **统一状态表达和控件用词。** 选中、只读、目标缺失、待保存、拖放可用性和试播评估各用可读文字配合主题颜色。明确「选择」是改引用，「打开」是导航，「管理」是进入编辑面板，「应用」是更新当前运行内容。状态放到它控制的对象旁，长说明留给提示或展开内容。
5. **用真实操作比较改造前后。** 选一条含多层目录、长 ID、Choice 多 Flag、缺失引用和复合条件的剧情。对照检查目录浏览、节点编辑、Flag 定位与拖放、Entry 写包、试播门控。重点比对常显信息、工具分组、主题对比度，以及展开或切页后的滚动和输入焦点。
