# Task：Story／StoryEntry 三栏隔离试播与条件决策

状态：待处理

## 目标与验收

- 作者从 Story「其他工具包」选择关联 StoryEntry，或从 StoryEntry 直接进入同一个三栏试播工作区，使用当前草稿验证正文、选择分支、场景、转移和父子接续。
- 播放遇到本文所列的条件时，在决定路线前暂停。作者可以查看当时真实的条件结果与推导过程，再决定按真实结果、视为满足或视为不满足。即使一个 Choice 的全部选项在真实状态下都会被隐藏，作者也能打开并实际选择其中一个。
- 条件覆盖只影响这一次试播判断。退出后回到原编辑目标，草稿、编辑态包、玩家存档与正式播放均保持原有数据和规则。具体通过下文验收矩阵确认。

## 三栏试播工作区

进入试播前捕获当前 Story／Entry、节点选中、属性页和各栏滚动。Story 工具页保留关联 Entry 选择，StoryEntry 入口直接使用当前 Entry。候选编译或试播初始化失败时，在触发入口显示原因并保留编辑页。成功进入后维持一个活动试播，退出、切换编辑目标或离开编辑器时从同一清理入口释放。进入与退出沿用编辑器路由生命周期，编辑器前进／后退记录仅用于 Story／Entry 导航。

| 栏位 | 主要内容与行为 |
| --- | --- |
| 左栏 · 试播路线 | 初始 Entry、当前 Story 和实际已走到的转移／父子接续。当前项随实际运行游标更新。循环再次经过同一 Story 时保留实际发生次序，避免把潜在调用集当成已走路线。 |
| 中栏 · 播放 | 复用聊天条目、选项、入口卡、开幕横幅、背景和随流／定位演出的渲染。聊天流独立滚动，继续、加速和对应交互放在既有作用位置。使用隔离投影提供的主题与场景，推进动作走试播接口；选择候选来自隔离播放器。 |
| 右栏 · 条件记录 | 顶部为当前判断，下方为本次已决定的判断。每条显示来源、真实结果、采用结果，可展开原条件树并回查真实结果。试播结束或被阻止时保留已产生的输出和判断，供作者检查。 |

复用 `WorkspaceFrame`、共享标题和项目当前主题角色。三栏使用稳定列身份，播放、路线和条件分别按投影变更更新；同一条件等待期间保留小窗和 Hover 锚点。悬浮详情随锚点移除或离开关闭。聊天原本贴底时跟随新内容，上方阅读时保持位置。轮询若继续沿用，读取必须无副作用，且条件标识、决策状态及子通道变化能够单独触发更新。布局与滚动按 [[workspace-columns-and-layout]]、[[ui-refresh-focus-scroll]] 和 [[ui-style/00-index]] 核实。

## 哪些判断会暂停

| 判断 | 暂停位置与默认规则 | 采用「不满足」后的行为 |
| --- | --- | --- |
| 根 Entry 入口资格 | 起始 Story 开播前检查 `availableInits` 和 `triggerCondition`。空 Init 列表、缺省限制和空 AND 组成的无门槛入口直接开播。存在实际配置的启动门槛时，即使真实满足也可改判。 | 显示入口被阻止并保留诊断。玩家 Init 和试播场景按各自已有生命周期处理。 |
| 带接续的子 Entry 入口资格 | 作者触发入口卡，并通过结构／接续规则后，在安装子 Run 或进入父等待之前检查子 Entry 的入口资格。同一父窗口展示具体目标及失败部分。 | 保留父 Run 在原入口卡的可操作位置，显示被阻止原因。作者可再次尝试或退出；再次尝试有新的判断标识。 |
| Choice 出现条件 | 节点自身 `requiresFlag` 通过后，在筛掉选项之前暂停。对有实质 `showWhen` 的候选收集判断，单条存档 Flag、资源或已读条件同样纳入。选项若另有 `requiresFlag`，显示 `showWhen AND 局部标记存在` 的合并判断。同一 Choice 按作者顺序合并到一窗。 | 该候选隐藏。全部候选经决策仍不可用时，沿用播放器的整组跳过与清理本组旧 marks 行为。候选已有选择时才按正常流程写入 marks。 |
| 重读分支守卫 | 在实际执行 `goto`／`insert` 及改变栈、游标和 visited 之前，显示目标 Story 与该 Entry 的匹配 `branchGuard`。前置条目显示相应 Talklet 已读检查，`talkletIndex = -1` 按现有全篇已读规则判定。 | 保持现有分支拒绝结果，显示已有拒绝文案，停在可检查的试播结果。 |

只有一个局部存在性要求的节点或选项继续自动判断。`false`、`0`、空字符串或 `null` 作为局部标记值仍表示键存在。Choice 有两层门槛时，节点门槛决定是否到达 Choice，作者改判的范围是各候选的出现要求。恒真空 AND 外层和单个局部标记组合仍按局部存在性自动判断；空 OR 是配置过的恒假条件。

这里的入口资格仅覆盖实际启动时消费的 `availableInits` 和 `triggerCondition`。随机抽取／好感推送、目录揭示、完结奖励、正式 Area 到场和后台反应按现有重读用途处理。文档、引用与接续结构校验继续先行。资源、存档 Flag、已读记录、当前 Init、Entry 局部标记及虚拟场景各自保留原义，强制结果仅影响当前门槛的分流。

## 小窗、Hover 与决策

1. 当前判断出现后，暂停自动推进和普通继续输入。小窗锚定当前选项组、入口卡或转移提示；没有可用锚点时显示在中栏演出区的固定提示位置。弹窗标题表明影响的动作，例如「决定哪些选项出现」或「进入子 Entry 前」。
2. 每项显示自然语言条件摘要及真实结果。悬停摘要展开组和叶子，显示各自的满足状态，保留 `全部满足／任一满足` 的嵌套、内容名称及比较符。布尔／存在性目标按现有 Runtime 语义翻译。能显式取得当前值时可显示支持判断的值；缺少真实诊断的条目注明原因。空 AND 与空 OR 分别显示「恒成立」和「恒不成立」。
3. 作者可选「按真实结果」「本次视为满足」「本次视为不满足」。Choice 逐候选可选，默认均为按真实结果，确认一次提交本组。采用结果与真实结果并存，Hover 在确认后仍读取原求值记录。弹窗被动消失或失去锚点时保持等待，右栏可回到待决项；「关闭试播」明确结束会话。
4. 条件采用为真只让相应入口、候选或转移通过该门槛。Choice 通过后仍需作者点击已显示的选项，按原流程接纳输入、写 marks 和展示所选文本。未配置条件的同组候选保持正常可用。

## Runtime 接线与状态归属

1. **试播策略由隔离实例拥有。** 在 `createStoryAuthoringPreview()` 装配试播专用的观察、暂停与决策能力，跟随同一次试播创建的父子会话。沿现有 `GameCommands` 和 `StoryAuthoringPreview` 从 Controller 发命令。普通重读与正式播放直接走现有路径。界面只拿只读投影和解析当前判断的命令，草稿、Registry 和存档字段沿用现有合同。
2. **在门槛所在层挂等待点。** 入口资格由 `StoryService` 生成，根入口首个决定在创建后、开播前可见；子入口拒绝前保留父输入。Choice 等待要早于 `drain()` 清理 marks、跳过节点或创建正常输入。转移等待处于游标、转移次数、插入栈与 visited 更新之前；已执行的前序 Operation 和演出只交付一次。暂停应有明确的进行中状态，供播放协调器、继续命令和完成判定区分。
3. **真实求值使用门槛自身的上下文。** Choice 用该 Run 的 `visited` 和局部表，入口用隔离状态的 Init 和共享入口条件求值，守卫用原已读前置检查。用同一套目标读取和比较逻辑给出真实组／叶结果。短路规则仍决定真实根结果；逐叶诊断只读，复用同一暂停时刻的上下文。读取或诊断失败时保留现有失败语义，并明确记录失败位置。场景投影作为演出背景，Area 型条件继续读取求值器实际使用的 Area，二者有差异时在详情写明数据来源。
4. **决定和续播是一次操作。** 等待投影至少包含一次性标识、Entry／Story／节点或入口位置、可决策项、原条件树及真实结果。使用会话和当前等待标识验收提交，接受后消耗标识，再从原边界继续。一次组判断产生的候选集合用于后续显示和两处提交校验，直至这一输入被消费。循环、再次进同一节点、子 Run 及返回后的新判断使用新标识。过期、重复、来源错位或无效项拒绝推进。
5. **路线与条件属于试播输出。** 从实际会话／游标切换和通过的转移讲述路线，条件历史只收录已发生的检查，Hover 展示暂停时取得的快照。同步首个判断、收尾、快速连续转移及子通道切回，避免只靠轮询当前页推断过去经过哪些节点。完成、失败或被阻止后可查记录；关闭从同一路径取消定时器、订阅、浮层、演出宿主与隔离运行，结束未决输入。

实现前重点核对 `story-service.ts` 的 `initializeSession`、`syncPresentation`、`advanceNode`、`advanceResultFromCommand`、`handleTerminal` 与子 Entry 接续路径。现有回执以待输入、待交付或终态为主，新增试播等待须贯通启动、自动交付、手动推进和关闭，避免被误报为 `NoActiveStory` 或被协调器自动确认。涉及跨层契约和只读状态投影，按 [[ai/guide/conventions/architecture-discipline]] 核对调用方和依赖。

## 验收矩阵

| 场景 | 通过条件 |
| --- | --- |
| 真实全部隐藏 | 在任何选项被自动跳过前弹一次窗。只对其中一项强制满足后仅出现所选项；Hover 仍显示真实未满足。点击一次才写入该项 marks。 |
| 混合组、空组与局部标记 | 一个 AND 内含混合 OR、存档 Flag、经过 Story 和局部存在性要求。诊断与原树、真实求值一致；覆盖前后真实结果一致。空 AND／OR 的文案及结果准确。单一局部标记自动判断，值为 `false` 或 `0` 也属存在。 |
| 拒绝及默认路径 | 对真实已满足项视为不满足会隐藏该项；按真实结果与现有播放一致。全组隐藏时只清理本组 marks，后续节点按原规则推进。 |
| 根／子入口 | 根入口展示 Init 与触发条件。根拒绝时不开播，强制通过时场景数据正确。子入口拒绝后父 Run 仍停在原卡；通过后左栏跟随子 Run，完成后返回父位置，仅回传原白名单标记。 |
| 重读守卫 | 分别覆盖已读指定 Talklet 和全篇、缺失读记录、`goto` 和 `insert`。拒绝时保留现有原因，强制通过时进入正确 Story、插入返回点正确，前序动作与输出各一次。 |
| 时间与会话 | 在自动交付后遇到判断、待决时继续／加速、重复确认、关闭再打开、循环重进同一节点和子通道切换。每次真实经过只决策一次，旧标识和旧 Hover 均无法推进新会话。 |
| 隔离与回归 | 未发布草稿可播，正式玩家资源、Flags、已读进度、存档、主题与作者草稿保持原值。普通重读和正式播放的候选、分支守卫、接续与奖励仍按既有用例通过。 |
| 宽屏鼠标 | 两个入口均能启动，背景、定位演出、横幅、入口卡和长条件树在三栏中可用。小窗不挡住当前操作，Hover 可移入阅读；连续播放保持聊天滚动，退出恢复原编辑目标和位置。 |

Runtime 回归从 `tests/engine/story/story-authoring.test.ts`、`story-node-player.test.ts`、`story-replay.test.ts`、`story-continuation.test.ts` 选择直接相关入口，UI 回归从 `tests/ui/story/story-editor-authoring.test.ts`、`story-editor-workspace.test.ts` 选择。通过 `npm test -- <定向文件>` 执行，日志归入 `.test-artifacts/`。跨层接线完成后运行类型检查、架构边界检查和文档检查。宽屏用真实鼠标走查，优先用内置千年「游戏危机」验证重读守卫，另用最小候选补丁稳定覆盖复杂 Choice 和根／子入口。
