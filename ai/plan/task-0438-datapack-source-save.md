# Task 0438 · 按来源保存 Datapack 原文件

状态：待处理

对应 [M01 原地保存与失败边界](../../docs/prototype-blueprints/AC-module-blueprints-v3/01-project-source.md) 和 D2。属后续作者工具建设。依赖首批 [[ai/plan/task-0437-datapack-layout-tools]] 及 M04 的 D1 草稿核心。已有 M02 来源定位与 M03 诊断可接入，完整检查和生产构建不作为单文件保存的门槛。

## 当前依据与施工

- `PackSource` 负责列举与读字节，`tools/datapack-editor/ui/io.ts` 用下载导出，`DatapackFileImport` 无写宿主。基于 Task 0435 的源路径、Pointer、原文件做文件级补丁。M04 把同一文件的草稿改动聚齐交给 M01，优先接一个真实 Spot 名称和同文件另一实体字段，保留其余定义、未知字段和资源。对源 JSON 无法可靠定位的结构化改动返回冲突并留草稿。
- 增加可写目录宿主及保存计划。先验真实路径、文件摘要和新文件不存在，再写回并重读。前置试验选择一个可实际写回的桌面宿主，必要时使用 Node 终端适配。ZIP 和只读依赖走副本导出。摘要用于源文件冲突，以实际写入消费者为限。
- 单文件验收后用同一计划承载移位时的创建和删除。只有唯一来源可建议重定位，歧义时由作者选择。多文件返回已写、未写、冲突和恢复位置。失败时 M04 只推进成功项的底稿，其余保留。备份、暂存和逐文件结果满足首轮恢复，强化事务或协作能力另行评估。

## 可用交付与验收

从实际可写目录打开同文件两实体，修改、保存、重开，两处值都更新。制造外部修改、源移动、只读 ZIP 和第二文件写入失败，核对原件、诊断、恢复位置及草稿。覆盖可保存但暂有缺引用的定义，并验证正式构建可在自己的检查阶段拒绝。
