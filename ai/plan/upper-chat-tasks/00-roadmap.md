# Editor Workbench Convergence · 第二轮细粒度施工总合同

本目录包含八份独立施工指令。将它们作为本地 Task 建设的依据，而非另行摘要为八个简短工作项。以远程 a2ab35e997d3541a27837f1239152c412ea0e5bb 及当前本地源码为依据；本地尚有 0421 未提交工作，必须先检查差异，不回退它。最近一次报告为 94 项中 85 通过、9 失败，类型、架构、文档检查通过；该数字是前序报告，不是新的验证结果。

## 目标及权威

- Workbench 持有 activeExplorerType 和公共会话；BrowseInstanceManager 独占实例集合、活动 ID 和通用生命周期；EditorLayoutService 持有基础布局；EditorExplorerService 持有各 Explorer 通用状态；WorkspaceColumns 持有实际栏位挂载与释放。
- 左栏的资源调查与活动实例相互独立。目录管理也是普通可恢复实例，不是锁住 Story 的特殊模式。试播等真正临时场景不被机械迁入普通目录实例。
- 公共 Explorer 必须接收未经过自由文本过滤的领域节点，并实际负责搜索、树投影、渲染与通用行为。不得仅提供 Interface、HTML 原语或事件绑定而让 Story 和 World 各自执行完整流程。
- 业务 Provider 保留领域查询、权限、数据操作、资源身份、节点信息和专属筛选；不得重新装配整个 Workbench。
- 图标是角色明确的表现资源；未裁定的实例图标缺省，不借用操作图标或任意 Logo。

## 共同施工规则

遵循 AGENTS.md、Task 工作流、Read Set 路由、frontend-design Skill 和当前 Authoring 视觉记录。调查当前代码后直接实施，不交付下一份空泛计划代替代码。每个节点应列出真实变更、读写权威、已迁移调用方、尚未退出的旧路径及明确退出任务。阶段中可保留单向适配，迁出的职责不得再有两个写入者。后继任务的验收不能被前序任务提前冒领；允许已经自然完成的工作以证据关闭。

检查点应保留实际测试命令/结果、工作区差异、未完成问题和下一步具体动作。按项目规则归档并确保活动索引能找到归档。仅在已有明确授权时创建本地 checkpoint commit，选择当前任务相关文件，不擅自 push/reset/rebase 或覆盖用户修改。无提交授权时只记录实际差异与恢复信息，不冒充代码快照。
