# Task 0350：故事续播、受限子调用与游标结构综合思考

状态：设计已进入 [[ai/plan/task-0351-story-continuation-implementation]] 实施。创建于 2026-11-03。下文保留当时背景和提案措辞；当前合同、实现与验证以 0351、源码及 [[story-and-effects]] 为准。

承接 [[ai/plan/task-0349-story-multi-cursor-discussion]] 与 [[ai/plan/report-0349-story-cursor-topologies]]。本页是后续统一讨论入口；0349 保留阶段推演，100 个玩法样本作为边界资料，不逐项重复。本文区分期望结果、当前事实和修改提案；拟议字段尚不能直接导入数据包。

## 一、期望结果：最终要达到什么目的

### 1. 作者按完整故事组织内容

同一段故事可以在等待玩家到达地点、进入羁绊、切换场景后继续；不再为了这些停顿被迫拆成多个 StoryEntry、提前标记完成，再用 FollowUp、尾段推送或持久 flags 把内容接回来。

Entry 划分依据是真正的投放、完成、奖励和目录边界。正文仍可分成多份 StoryDef，通过已有 goto / insert 组织；不要求所有正文写进一个文件。

必须支持三个代表流程：

```text
好感对话 A（同一 StoryDef）
  前文 → kizunaCard〔原游标暂停〕→ 后文 / requiresFlag → A 完成
                  ↓                      ↑
             独立羁绊 Entry B → 完成并回传本次局部结果
                  玩家回到原空间后，A 才越过卡片继续

同一段天台邀约
  聊天前文 → 地点续播点〔原游标暂停〕→ 天台相遇正文 → 真正完成
                  玩家自行前往，到达后手动接着播
                  此处没有子 Entry，也不占子槽

前往 Area 接续独立子故事
  父对话 A → 赴约提示〔原游标暂停，投递父绑定邀请〕→ A 原有后文
                  玩家自行前往指定 Area                 ↑
                  手动接取当地 ActiveStoryEntry B → 子故事完成并回传
                  玩家回到 A 来源空间后，才继续 A
```

用户已否定 afterStoryId / 固定前后两份 StoryDef 的包装；续播点应是当前节点的自然后继，不让作者填写返回地址。

本轮新增明确需求：关联子故事不必从原空间直接启动，也可以先成为指定 Area 的新主动故事入口，玩家到场接取才开始。可使用专门的赴约提示 / 卡片，不强求继续命名为 kizunaCard。此方式仍是一次父子调用，不是同游标地点续播，也不是旧故事完成后独立启动下一章。

### 2. 分清空间、进度与最终画面

| 对象 | 责任 | 应保持的边界 |
| --- | --- | --- |
| 会话空间 | 保留历史，主要是 Chara 聊天历史，并提供场景与原有聊天风格 | 当前在这里显示，不代表所有演出都属于其历史 |
| 游标 | 记录一次 StoryEntry–StoryDef 运行的位置、局部 flags、等待与父子返回关系 | 不与屏幕、当前 Area、历史条目数量绑定 |
| 屏幕对话渲染 | 组合当前场景与剧情呈现，决定最终可见内容 | 不通过查询、刷新或重建界面推进故事 |

故事跨 Area / Chara 场景时保持自己的运行身份。羁绊或现场演出的临时主题、排版和正文不污染 Chara 的实际聊天风格与普通历史；原聊天后文返回原空间呈现。演出输出仍须随运行进度保存恢复。

### 3. 多游标只承担实际需要的关系

Init / Chara 保存自有运行记录，正式播放最多一个活跃子故事。多个空间可以各自保留卡片或待返回结果，但不因此创建多个活跃子运行。

等待是已有游标的状态，不额外建独立等待游标、通用事件等待图、无限调用栈或第三种中央核心游标。子故事返回结果交给父记录后即可释放子槽，不必等玩家读完父后文。

“所属空间有运行”“全局子槽占用”“前台播放权”分别判断；浏览历史、离开空间和世界 Tick 不因父游标等待而一概停止。

### 4. 玩家看到故事组织，而不是调用结构

目录继续展示主线、活动、角色好感及关联羁绊。游标、父子绑定、flags 表不成为玩家概念，也不为卡片前后几句对话建立额外目录条目。

完整回放自然串起前文、羁绊和后文；地点续播在回放中使用虚拟场景，不要求真实旅行。单独重读羁绊不需要真实父故事，不唤醒正式聊天，不改变正式奖励、进度或 Chara 历史。

## 二、现有背景：已有能力与限制

### 1. 播放链已具备可复用的基础

StoryService 按 owner 管理普通运行会话；StoryNodePlayer 解释有序 nodes、逻辑等待点、局部表和文档返回栈；StoryPlaybackCoordinator 管理有限表现步骤、计时与稳定输出；UI 查询并提交明确意图。表现进度、逻辑进度和历史输出已有独立保存边界。

当前存在 Init 上下文中的全局流与各角色流，重读另按 replayId 隔离。新设计应在这些边界上改造，而不是为每个 Area 或渲染窗格再造播放器。旧 stages / stageId 不参与当前顺序控制，不恢复为新调度机制。

### 2. 当前机制分别解决不同问题

| 当前机制 / 事实 | 现有作用与限制 |
| --- | --- |
| AreaStoryDelivery | 保存主动 Entry 的待领取 / 完成记录；投递不等于启动，当前主要按 Entry 去重，不含父调用关系 |
| PassivePool 与好感就绪 | 过滤并选出候选；好感增长、就绪与实际开始是不同阶段，进入角色空间通常才推就绪段 |
| FollowUp | 来源故事完成后等下一次进入 Area；Active 目标只投递，Passive 目标保留直接启动行为；fulfilled 对 Active 表示已交付入口 |
| pushAfterStory | 根据已完成 StoryDef 扫描并优先推送另一个尾段 Entry；不携带上一运行的局部 flags |
| block / studentBlocks | Passive 完成后给角色设置持久投放门槛，条件满足后复检解除；不同于活跃游标停在节点 |
| reactions | 来源完成后安装事件反应，既可用于叙事接线，也可用于真正的世界后续 |
| goto / insert | 同一 Player run 内转移 StoryDef；insert 维护文档后继，不是另一 Entry 的调用 |
| 显式移动节点 | 正常播放可真实移动并迁移当前 owner 槽；目标已占用会拒绝，尚未实现来源归属与演出场景完全解耦 |
| entryCard / startCardStory | 现有同 owner 路径会替换来源运行，含强制启动策略，不能直接作为保留父游标的 kizunaCard |
| 完成与恢复 | storyCompleted 广播只有 storyId；保存恢复换发 runId / token；当前完成身份会用 terminalStoryId，不能直接代表未来父子返回 |
| replay | 跳过一般 Operation，Click 结果仍可能产生世界效果；尚不满足组合回放全部隔离要求 |

以上依据来自 0349 的源码与测试阅读，不把已阅读的测试写成已执行验证。

### 3. flags 的三种含义必须保持分开

- 本次 Entry 的 localFlags：独立键值表，可存 JSON 值；requiresFlag 只判断键存在，false / 0 / null 也算存在。goto / insert 沿用同一表，新 Entry 默认不继承。
- PlayerState.flags：持久状态表，普通 Condition 的 flag 查询读取它，不读取 Entry 局部表。
- session.flags：本次执行过哪些持久 setFlag 的名称记录，不是局部键值表或可直接回传的结果。

子调用要返回的是本次局部结果；地点续播属于同一次运行，本来就保留原局部表，不需要回调复制。

### 4. 已核实的合并样本与差异

基础内容中发现一个 FollowUp 声明（星野天台）与一个 pushAfterStory 尾段声明。天台链目前包含前段完成、FollowUp 消费、主动入口投递，另有角色条件阻断，适合评估同游标地点续播。

尾段关联 bond_hoshino_1，但已有邀请卡指向 bond_hoshino_evening；它们不是已经核实的一条完整调用链，迁移前必须选定真实父好感 Entry。

现有测试还覆盖多 Active 同时投递、Passive 直接开播、尾段优先级和跨 Init 恢复。不能因为基础样本少，就把独立投递、多目标解锁和长期世界响应一起删除。

## 三、如何修改：收敛后的方案与实施路径

### 1. 先定义有限运行关系

建议保留空间自有记录与一个正式子槽。运行记录表达：自身稳定身份、来源 Init / 空间、当前 Entry / StoryDef / 节点等待点、局部 flags，以及可选的子调用绑定和结果消费状态；优先复用现有快照，不先确定另一套重复结构。

根运行可以顺序播放、地点等待或发起唯一受限羁绊调用。子运行只有一个具体父亲，不能再发起子调用。切换场景或进入另一个 StoryDef 不改变运行角色。普通独立主动故事是根运行，不能因启动按钮在角色页面就自动成为孩子。

| 等待类型 | 保留的内容 | 恢复条件 |
| --- | --- | --- |
| 地点续播 | 原等待点、局部表与来源空间 | 目标地点符合，玩家手动接受 |
| 羁绊卡片未点击 | 原卡片及自然后继 | 玩家点击且子启动准入成功 |
| Area 子故事待接取 | 原等待点、父绑定邀请、目标 Entry / Area | 玩家到指定 Area 接取且子启动准入成功 |
| 子故事进行中 | 父卡片、具体子运行绑定 | 本次子运行正常完成且 finishing 结束 |
| 子结果已返回 | 父等待点、结果及未消费标记 | 正确空间重新激活且可取得前台 |

等待记录仍占所属逻辑槽，不能被新闲聊或好感段覆盖；它不等于全程禁旅行。长期占 Init 根槽会影响其他故事启动，确需独立并行任务时仍用资格 / 投递记录，不为此增加等待游标列表。

### 2. 给数据包作者提供有限交互

以下仅是拟议字段片段，省略现有必填项，不能直接作为当前合法数据包使用：

```text
好感 StoryEntry：
  storyId: 完整好感正文
  kizuna:
    entryId: 独立羁绊 Entry
    returnFlags: [允许返回的局部键]

同一 StoryDef 的 nodes：
  前文
  Click / kizunaCard          ← 目标只从 Entry 的关联取得
  后文 / requiresFlag        ← 不填写 afterStoryId 或返回地址

地点续播的 nodes：
  邀约前文
  Click / areaContinue:
    areaId: 目标 Area
  到场后文
```

作者只声明故事关联与明确地点；不开放目标游标 ID、任意 event、回调脚本、通用等待表达式、合并策略或手写调用权限。

**kizunaCard** 出现即停住原故事。点击前不占子槽；子启动失败保持卡片可用，不消费旧等待点。子在独立槽运行，场景即使与父 Chara 相同也不替换父记录。成功返回只使父待续播；回到来源空间后，从原卡片后继继续。

**areaContinue** 建议仅按目标 Area 当前匹配，已在目标地点即可接受；到达只使续播可用，手动接受才推进。该入口从游标派生，不创建另一 Entry 或另一份 AreaStoryDelivery。接受时复核 Init、位置、运行、阶段和 token，现场正文按地点演出呈现。

**前往 Area 接取子故事** 是本轮确认需要支持的第三种入口。父 Entry 的受限关联需表达目标 ActiveStoryEntry、接取 Area 与允许返回的键；字段及卡片名称待定，不让作者手填调用身份或任意事件。原故事到达该节点后登记一次关联邀请并暂停；原空间显示“前往某处继续故事”，不直接开 B，也不强制旅行。到达 Area 后在主动故事入口中手动接取 B，才创建子运行。关联目标引用作者定义的 Entry，运行时生成的是这次邀请和运行记录，不动态复制一份作者定义。

| 三种入口 | 到场 / 接纳后的行为 | 是否创建子运行 |
| --- | --- | --- |
| areaContinue | 继续当前 Entry 的后继节点 | 否 |
| 直接羁绊入口 | 在原卡片接纳后开始关联 Entry | 是 |
| Area 赴约入口 | 在指定 Area 接纳父绑定的 ActiveStory | 是 |

Area 赴约必须满足：

- **邀请不占子槽**：行走和未接取期间只保留父等待与邀请；真正接取成功才占唯一子槽。到达、打开 Area 或查看入口都不自动开始。
- **绑定一次具体邀请**：入口保存来源 Init、父运行 / 等待点、目标 Entry 和 Area 的关联；不能只用 Entry ID 去重，也不能把普通独立投递或历史完成当作本次赴约已完成。
- **接取仍是子调用**：入口出现在 Area 不等于改成 Init 根故事；B 仍进入子槽，不覆盖父 Chara / Init 自有记录或其他根运行。
- **开始前统一准入**：复核地点、Init、邀请有效性、父仍在等待、目标资格和子槽。忙或拒绝不消费邀请；重复接取不创建多个 B，子运行仍不能再发起此类赴约。
- **成功后回传同一父亲**：沿用本次 flags 回传与回到来源空间续播规则。B 取消 / 可重试失败时恢复 Area 接取路径，不悄悄改成原空间直接开 B；父取消使邀请和迟到返回失效，已结算异常仍按回执恢复。

这可以复用 Area 主动故事卡片的显示，但现有 AreaStoryDelivery 仅按 Entry 管理的身份不足以直接承载它；实施时需增加受限的父绑定来源或等价关联记录。普通独立投递与关联邀请不能被混为一条无来源入口。此能力不引入第二层调用或跨 Init 子故事。

现有 moveToArea / moveToCharaspace 继续用于故事主动移动或切场景；它们不能代替玩家自行前往。来源归属、真实位置、当前演出场景与历史归属需要分别维护，不能再靠改 owner 同时表达全部含义。

### 3. 回传局部结果，而不是建立共享表

建议 A、B 各持有独立表；本阶段不自动把 A 整表传入 B。成功返回仅复制 returnFlags 声明的键；先清除 A 中这些键，再复制 B 最终存在的项，A 的其他键保持，避免旧分支残留。省略列表表示不回传键，但正常返回仍会解除等待。

成功与否由运行回执判断，不要求作者另写“完成 flag”。B 的最终局部结果要在 Player 清空 run 前取得，并随 finishing / 快照保留。返回绑定跨读档稳定的具体身份，不能用换发的 token、当前 owner 或历史完成日志替代。

此键名单与覆盖规则仍是推荐提案，尚未作为生产合同确认；requiresFlag 的存在判断语义不扩展成值比较。

### 4. 在所有启动入口严格禁止嵌套

- 静态检查子根文档沿 goto / insert 可达的内容，包括 Click 结果、Operation、卡片及已知 Entry 启动行为；不能只检查根文档有没有 kizunaCard。
- 在 StoryService 的实际启动准入统一复核普通请求、卡片、Effect / Trigger、旅行监听、完成反应及延后请求。子身份由 Runtime 保留，换 owner、system 或延后一轮不能升权。
- 子可以改变世界、解锁和投递未来根故事；未返回时不递归开新播放。多个入口可投递，不等于多个子调用。
- 仅一次子运行的正常完成可回给它的父记录。全局 storyCompleted、其他 Entry 共用正文的完成、重读都不能伪造返回。
- 首版建议父运行只有一个关联目标、一次成功调用；正式播放只走父绑定的直接入口或 Area 赴约邀请，不能从无关普通入口绕过。单独阅读走回放。连续两次非嵌套调用并不增加深度，但目前没有必要开放。
- 子忙、父待返回和前台占用分别判断；准入区分实际启动 / 恢复、只投递、忙和拒绝，不把“请求已提出”当作已成功运行。

### 5. 逐用途替代旧结构

| 原用途 | 改写方式 | 退场条件 |
| --- | --- | --- |
| 羁绊后几句尾巴 | 放回父 kizunaCard 后的节点 | 明确真实父入口后，移除此用途的尾段 Entry、pushAfterStory 扫描 |
| 同一故事等到某 Area 再接后文 | areaContinue 保留原游标 | 重审结算 / 目录后，移除此用途的 FollowUp、假完成与专用目标 Entry |
| 为切场景而交接运行 | 同 run 场景投影与显式移动 | 不再用场景切换隐式迁移父归属 |
| 为表达未完故事而先完成再 block | 活跃游标等待状态 | 仅移除这种用途；真正持久投放门槛保留 |
| reaction 只为接回原故事后文 | 线性节点或一层返回 | 不再通过持久监听拼接同一次运行 |
| 真正完成后解锁其他章节 / 活动 / 多支线 | 独立条件与投递 | 功能保留；旧 followUps 字段是否整体删除另据剩余用途决定 |

FollowUp 的严格 next-enter 与新地点当前匹配不是完全同义；Active 手动接取与 Passive 自动启动也不同。现有可用性投递仅服务指定 Entry 列表，不能仅加一个完成条件就宣称完整替代目标地点、一次性消费与多目标投递。

合并必须一起审查完成身份、奖励、冷却、统计、外部 hasReadStory 前置、角色阻断持续时间和 reactions 激活时机。正文可复用旧文档，但当前 terminalStoryId 的完成语义不能无意把合并根故事记成旧后段。

### 6. 保存、异常与回放一起闭环

父等待、活跃子、最终结果和消费状态一同保存；整组预检后恢复，拒绝孤儿、双父、错 Init 和重复活跃子。子返回后父尚未回空间时，即使子槽已释放，父结果仍须存在。旧 token 和迟到结果不能影响同空间的新故事。

Area 赴约还要保存未接取邀请及其消费 / 子运行绑定。读档、重复进出 Area 不重复投递或接取；其他入口完成同一正文不能错误消费邀请。邀请尚未接取时不恢复出一个活跃子运行。

子取消 / 未结算失败可恢复邀请；已结算但 finishing 失败不能直接当成未完成重开。保留实际回执，不承诺回滚世界效果。父已取消则返回失效。内容或节点失配时，父子须成对处理，不能只重启一端，让旧孩子回到新父节点。

Init 切换按现有快照边界冻结所属关系，不开放跨 Init 子调用。地点等待应允许正常旅行，不能沿用 leaveArea:false 等全程锁而形成“要求去天台却不能移动”的死锁。

组合回放使用临时关系；保留局部 flags 的分支计算，隔离世界写入、奖励和正式历史。地点等待与 Area 赴约在回放中按虚拟场景接续，不写正式投递或要求真实旅行；重读单独子故事不回传真实父。需要专项调整现有 replay 的 Operation / Click 动作语义。
