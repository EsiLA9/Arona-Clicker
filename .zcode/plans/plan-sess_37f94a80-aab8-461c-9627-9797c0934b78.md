## 二、改造内容

### 1. 尾巴挂靠 PassiveStoryEntry 推送服务（§3 新载体）
- `PassiveStoryEntry` 新增 `pushAfterStory?: string`（引用演出本体 StoryDef id，与 `hasCompletedStory` 同语义）：声明后退出随机抽取，关联剧情完结后**强制优先推送**
- `pickAffectionStep` 就绪队列扩展：尾巴条目（pushAfterStory 达成 ∧ 本条未播过）**绝对优先**于好感台阶（需求值升序次之）；推送点复用现有两处（进入对话空间 / clickSend idle 必中）
- UI 订阅 `storyCompleted`：匹配尾巴条目（pushAfterStory = 完结 storyId ∧ owner 一致 ∧ 未播过）且玩家正在该角色对话空间 → 立即经队列推送（延续"完成后自动追加"体验）；不在该空间 → 留在队列顶等打开时推送；owner 不匹配不触发
- base 数据：`base:bond:hoshino_1` 配尾巴条目（owner Hoshino）；台阶示范改 `affectionRequired(1)/(3)`，无消息后回环仍可玩

### 2. 未读迁移到对话空间
- 未读定义 = 就绪队列条数：`StoryService.readyStepCount(owner)` 只读查询（未拥有 → 0）
- `controller.getUnread` 改接 `readyStepCount`（预留接口链不动）；对话空间头部"N 条未读"同源
- **输入中省略号**：打开对话空间且队列非空、无进行中演出 → 先渲染动态省略号气泡（新增 `.chat-typing` CSS 动画），约 900ms 后自动推送队列顶；期间点发送/返回则取消定时立即推送或清除

### 3. 保持不变
§1 全部（bondDict 阶梯、addAffectionExp、星级锁、affectionLevel 条件、affectionChanged 事件）、轴 B 队列本体、升级提示 reward 行、剧情侧 kizuna 卡片全套原始设计
