# addResource 语义统一 + 新增显式持续流机制

## 目标
- `addResource` 在 Affector 上下文中与其它场景统一：**Latent→Active 翻转时立即一次性发放**（边沿触发），不再被 reinterpret 成每 tick 流。
- 每 tick 持续产出改用新增的**显式 `flows` 字段**表达，沿用现有 GameNum 懒求值路径。
- 迁移存量数据：`energy_drink` / `pyroxene_flow` / `unified_logistics_flow` 三个包 + Spot 功能的 linearYield 转译。

## 改动清单（按依赖顺序）

### 1. 类型层 — `src/engine/types/trigger.ts`
```ts
/** 持续流：Affector 激活期间每 tick 懒求值入账的资源产出。 */
export interface AffectorFlow {
  resource: string;
  value: number | ValueExpression;  // 每 tick 数量
}
```
`AffectorEffect` 新增 `flows?: AffectorFlow[]`；`effects` 注释更新为"即时效果（addResource = 激活时一次性发放）"。AffectorFlow 经 `entities.ts → index.ts` re-export 链路自动暴露，无需额外导出。

### 2. Builder — `src/engine/def-factory/affector-pack.ts`
- `entry()` 初始化 `flows: []`
- 新增 `.flow(resource, value)` 附着到当前 entry
- `build()` 空 flows 时 strip（与 zoneModifiers 一致）

### 3. 引擎执行 — `src/engine/effect/affector-engine.ts`
- `recheck()`：计算新状态后，若 `oldState !== 'Active' && newState === 'Active'`，收集 active entries 里的 addResource 效果，经 `effectEngine.applyEffects`（无则 mutations）**一次性执行**；随后照常 emit `affectorStateChanged`。
- `applyActiveEffects()`：过滤条件不变（仍排除 addResource / setSpotMaxLevel / removeSpotMaxLevel），仅更新注释——addResource 改由 recheck 翻转时发放。
- `buildSpotFunctionalityPack()`：linearYield 转译从 `effects: [addResource(spotLevel × amount)]` 改为 `flows: [{ resource, value: Expr.mul(spotLevel, amount) }]`。

### 4. GameNum 求值 — `src/engine/expression/game-num-eval.ts`
- `evaluateResourceAffectorFlows` / `evaluateSpotAffectorFlows`：改读 `entry.flows`（按 flow.resource 过滤），不再读 `entry.effects` 的 addResource。value 求值复用 `resolveEffectValue` 的 number/ValueExpression 逻辑（提取小助手或放宽签名）。
- 树结构（primitiveGain + affectorFlows 叶子）不变。

### 5. 文本描述 — `src/engine/effect/affector-text.ts`
- `describeEffect` 的 addResource 文案：`每 Tick X +v` → `获得 X +v`（一次性语义，与其它上下文一致）。
- `describeAffectorEntry` 参数扩展 `flows?`，把每条 flow 渲染为 `每 Tick X +v`，与 effects 以「；」拼接。

### 6. base 数据迁移 — `src/data/base/datapack.ts`
- `energy_drink`：`.effect(addResource +1)` → `.flow(CREDIT, 1)`
- `pyroxene_flow`：→ `.flow(PYROXENE, 2500)`
- `unified_logistics_flow`：→ `.flow(CREDIT, 1)`
（extra 元数据保留；行为不变，仍每 tick 入账）

### 7. Schema / 编辑器同步
- `AffectorEffect` 是 HAND 类型：`npm run gen:schema` 重新生成无 diff（预期），仍按协议跑一遍确认。
- `tools/datapack-editor/schema/editor-extras.ts` 的 `affectorEntryObject()`（490-502 行）新增 `flows` 字段（`alist` + 对象：resource 字符串 + value 参照 effectObject 的 value 类型），保证数据包编辑器可编辑。
