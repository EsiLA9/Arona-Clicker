# Color / ColorGroup 合并实施计划

## 目标形态

删除 `ColorDef`，`ColorGroupDef` 成为唯一色彩实体 = **重点色彩组（slots 内联 hex）+ 头像渲染方案（compositionType）+ theme-tree 预设（theme 覆盖表，primary 缺省取主色位 hex）+ 解锁条件（unlock）**。

## 默认决策（可否决）

1. **命名**：保留 `ColorGroupDef` / `colorGroups` 表名，改动面最小；`state.activeColor→activeGroupId`、`colorsOwned→groupsOwned`。
2. **所有权**：统一走闸门——玩家只能激活已解锁的组为主题；删除 `state.customTheme`（它存在的唯一理由是绕过闸门）；装备解锁级联从「解锁组内每个 Color」改为「解锁该组」；未拥有的组在 header 色板置灰展示。
3. **深浅判定双标**：不强行统一模型——引擎 HSL 明度 0.38 判「主题浅底/深底」是有意设计（见 color-system.ts:102 注释列举的色板），UI WCAG 亮度 0.30 判「背景上文字白/黑」也是有意设计；本次只修正「必须共用此值」的误导性注释，把两层契约写清楚。

## Phase 1 — 类型层（src/engine/types/）

- `character.ts`：删 `ColorDef`/`ColorId`；`ColorGroupSlot` 改为 `{ role, color: string /* hex */ }`；`ColorGroupDef` 增加 `unlock?: Condition|ConditionGroup`；`ThemeDef.colorId → colorGroupId`（@ref colorGroups）；`ColorEquipmentDef` 删 `themeColorId`（组自带主题）。
- `state.ts`：`activeColor→activeGroupId`、`colorsOwned→groupsOwned`、删 `customTheme`（规则 7：不做存档迁移，清档重来）。
- `world.ts`：`SpotDef.colorGroupId` 注释更新；`expression.ts`：`ThemeEffectValue.colorId → colorGroupId`；`events.ts`：`colorUnlocked → groupUnlocked`、`themeChanged.colorId → groupId`。

## Phase 2 — 引擎核心

- `color-system.ts`：`resolveTheme(group)` 收敛为唯一解析路径（主色位 hex 派生 + `group.theme` 覆盖 + CT-04 对比度防呆保留）；删 `themeContributionFromColor`/`themeContributionFromGroup`（并入 resolveTheme）；`themeContributionFromThemeDef` 改查组表；`ColorSystem` 门面改名（`ownedGroups`/`tryUnlock`/`activeThemeTokens`/`describeGroup`——图鉴 defined/derived 拆解按 `group.theme` 显式键判定，`autoConstructed` = theme 缺省或仅 primary）。
- `theme-runtime.ts`：`ThemeLayer.colorId → groupId`、`ResolvedTheme.colorId → groupId`；resolver 回调改查 colorGroups。
- `registry.ts`：删 `_colors` Map；外键校验改为 equipment.colorGroupId / theme.colorGroupId / themeDesign.theme.colorGroupId → colorGroups；slot 外键校验删除（内联 hex 无引用）。
- `state-mutation-service.ts`：`unlockColor→unlockGroup`、`activateTheme(groupId)` 闸门读 `groupsOwned`、删 `setCustomTheme`；`CharacterCatalog` 删 `getColor`。
- `color-equipment-system.ts`：`avatarColorsForGroup` 直接 `slots.map(s => s.color)`；:109 级联改 `unlockGroup(def.colorGroupId)`。
- `game-instance.ts`：catalog 注入与 ColorSystem 构造适配。
- def-factory：删 `color.ts`；`color-group.ts` 扩展 `.slot(role, hex)`、`.primary(hex)` 快捷、`.unlock(...)`；`color-equipment.ts` 删 `.themeColor()`；`area.ts`/`variant.ts` 的 `.theme()` 参数改名。

## Phase 3 — UI

- `theme-tree.ts`：删 `themeTreeFromColor`；`themeTreeFromGroup` 成为唯一快速映射（不再需要 getColor 注入）。
- `controller-theme.ts`：`syncRuntimeTheme` 删 customTheme 分支；学生层组解析改读内联 hex。
- `controller-actions-theme.ts`：`data-activate-custom-theme → data-activate-group`，走 `activateTheme` 闸门；删 setCustomTheme。
- `header.ts`：色板两列表合一（已拥有可点、未拥有置灰）。
- `collection.ts` + `collection-modal.ts`：色彩 tab 改渲染合并组（describeGroup + 头像小样）。
- `contacts.ts`/`story.ts`/`production.ts`：头像 hex 数组消费形状不变，仅适配解析入口。

## Phase 4 — 默认数据（src/data/base/）

- `areas.ts` 7 处 `.theme('base:color:…')`、`stories-play.ts:194` setTheme、`datapack/AronaClickerCore/13-areas-millennium.json` 引用同步重定向。

## Phase 6 — 测试与验证

- 审查/重写 16 个受影响测试（~193 用例）：theme-runtime、theme-tree×2、color-system、color-derive、color-ingame、color-equipment-system、entity-theme、def-factory/color（删，新增 color-group builder 用例）、avatar-renderer、character-freeze、contacts、chat-image、def-factory/area、variant-gacha-chat。

## 风险

- 决策 2 是玩家可见行为变化（未拥有组不能再当主题）；若否决则保留 customTheme 旁路，Phase 1/3 对应回退。
- 数据合成时 `base:color:coral` 这类全量自定义主题要完整搬进组的 theme 字段，逐条核对不丢 token。
