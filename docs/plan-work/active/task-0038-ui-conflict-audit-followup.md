# Task-0038：UI 表现层潜在冲突收敛

状态：✅ 已完成（2026-09-09）

## 背景

task-0037 已将三栏 Panel 的 Tabs 从负边距横切组件重构为独立的 `panel-tabs-region`，解决了主 Panel 的方形背景、双层线和滚动边界问题。后续只读审计发现 UI 系统中仍存在相似的结构分叉和层级假设。

## 目标

1. 将通讯录对话空间纳入统一的 Panel 结构契约；
2. 明确对话空间的顶部标题、正文滚动和底部回复区职责；
3. 约束表现宿主的背景节点、装饰节点必须处于直接子层级，避免主题刷新与 CSS 几何规则失配；
4. 保留 collection、gacha、主题编辑器等非 Panel `switch-tabs` 的独立间距和边框；
5. 增加结构测试，防止再次引入双层边框、负边距或错误宿主层级。

## 设计决策

- `conversation-panel` 不复用 `panel-tabs-region`，因为对话标题不是 TabGroup；它使用同等边界职责的 `conversation-header` 顶部结构区块。
- `panel-body` 作为对话内容的语义容器，但对话内部的 `chat-stream` 继续承担实际滚动，避免标题和回复区随正文滚动。
- 不为通讯录对话强行新增表现宿主 ID；当前对话使用 `ctx.background` 的全局背景语义，避免改变主题数据契约。

## 完成标准

- 对话空间与三栏 Panel 具有一致的外框、裁剪和内容层级语义；
- 对话标题、聊天流、回复区之间不存在重复边框或滚动容器竞争；
- 表现宿主的主题刷新路径不依赖隐藏的 wrapper；
- 全部验证命令通过。
