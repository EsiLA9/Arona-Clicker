# Task：数据包编辑入口收敛与启用集 Apply 门禁

状态：done — 2026-09-19 实现、自动化核验与浏览器交互验收完成，待归档

## 来源与问题

当前数据包管理页同时显示 Pane 内“打开编辑器”、详情区“打开编辑器”和“运行时数据包编辑”卡片，多个入口重复表达同一个编辑目标；创建编辑态后还会自动打开编辑器，用户无法通过 Pane 状态按钮明确完成“先选择、再进入”的动作。

## 目标

1. 移除数据包管理页中的“当前编辑目标”和所有“打开编辑器”按钮。
2. 移除整个“运行时数据包编辑”卡片，保留顶栏 Runtime Editor 入口。
3. 已有编辑态时，第一次点击“编辑态”只选择该 Pane 的编辑态；再次点击同一“编辑态”才选中该 Mod 并进入编辑模式。
4. 创建编辑态后不自动进入编辑器，用户通过上述两次点击进入。
5. 启用集草案存在未应用变更时，不允许进入编辑模式；必须先“应用启用集草案”。

## 交互契约

```text
普通态 / 编辑态按钮
  └─ 首次点击编辑态：保存 Pane Selection，停留在数据包管理页
  └─ 再次点击已选编辑态：校验启用集草案已 Apply → 打开该 packRecordId 的编辑工作区
```

- 普通态点击仍只切换 Selection，不进入可写编辑器。
- 编辑态第二次点击若启用集草案有未应用变更，阻止进入并提示先 Apply。
- Runtime Selection 的“待 Apply”语义继续保留；本 Task 的编辑器门禁只检查启用集配置草案是否已落地。
- 编辑器只能通过顶栏入口或编辑态二次点击进入，不由数据包卡片提供额外入口。
