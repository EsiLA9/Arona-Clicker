# Task 0232：Gameplay B 人物行动卡与 AC 中心记录流

## 目标

在现有三地点游乐园样例中，尽可能移植原始 Demo 的人物卡片式阅读与操作风格：玩家先看人物身份及其行动卡，直接在卡内调整，然后一次提交整轮或整批；中心 AC 流主要阅读已发生的结果，同时承载全队共同决策和独立玩家手牌。

本 Task 交付卡片交互与信息呈现，不重建原始 Demo 的全部规则或 13 地点内容。独立完成定义为：正式样例的战斗、Individual、Global、玩家牌、路线、结局和奖励均可通过卡片与紧凑控件操作，中心保有连续结果阅读空间，已有原子命令、局部刷新与续局语义继续成立。

## 已冻结的玩法与信息归属

| 对象 | 主要宿主与操作 | 提交语义 |
| --- | --- | --- |
| 战斗学生 | 左侧学生身份卡附一张当前行动卡，显示行动、目标、理由和自动/修订状态；先展示当前行动，点击“更改”才展开该人物合法替代行动。 | 继续最多修订一名学生；既有 revise/clear 命令与一次整轮 Commit。 |
| Individual 场景 | 每名存活学生的身份卡附本批行动卡，卡内选行为；合法目标确需选择时在该卡内用人物标签/按钮选择。中心只显示批次与费用摘要。 | 每名存活学生各一项；卡内选择为未提交 UI 草稿，暂存后才进入 Run，再一次确认整批。 |
| Global 场景 | 中心当前操作区一张全队行动卡；替代行为按需展开，执行者用紧凑人物按钮，目标按当前投影合同选择。 | 全批恰好一项共同 SceneAction；不生成三份个人 Global 选择。 |
| 玩家 SceneCard | 中心独立手牌区，每个物理实例是一张可选牌；牌内显示费用、选中态与 OperationView 投影的合法执行者/目标。 | 可不出牌，也可选择多张；与场景行为同批付费，成功后进入 discard。 |
| 对手与设施 | 右侧对应身份卡附 Intent；设施独立分组。 | 只读，不能借风格移植增加玩家控制能力。 |
| 共享 PlayerCost | 底部 Action Dock 余额与本批预览；行动卡显示自身费用。 | 不以 UI 计算代替 Runtime 校验，不在每条消息重复当前余额。 |
| 路线 | 地点完成后中心呈现出口行动卡/按钮；完成前只在当前摘要显示真实门禁/进度提示。 | 可用性取自 View；一个出口自动转场与多出口选择沿用 Runtime。 |
| 已发生结果 | 中心按 resolutionSequence 展示有界结算消息，路线履历另设紧凑可展开摘要，终局一条结案消息。 | 只读派生，不生成新的 ChatEntry/EventRun 日志。 |

行动卡不等于把所有合法 Action 同时铺成大量按钮：默认一人一张当前行动，替代项按需局部展开；目标选择也仅在该行动确有多个合法候选时展开。选项再多仍使用卡内局部区域，不引入另一份中央人物行动清单。按钮使用原生可聚焦元素、可读标签与 `aria-pressed` / `aria-expanded` 表达状态。

### 一次操作的可观察结果

1. 战斗：看左右人物卡 → 在一名学生卡内更改行动/目标 → Dock 提交本回合 → 中心出现一次结果 → 侧栏更新下一轮计划。
2. Individual：三名存活学生各有当前场景行动卡 → 可逐卡修改 → 独立选择玩家手牌 → 暂存整批 → 展示总费与已暂存标记 → 确认或返回修改。
3. Global：选择一张全队行动卡及合法执行者/目标 → 可附带玩家手牌 → 以相同暂存/确认流程结算。
4. 地点完成：显示真实开放出口 → 选择或自动转场 → 当前摘要切换到新地点，路线履历更新；不把 UI 点击尝试写成已发生事件。

### 草稿与记录边界

- 未暂存的场景/玩家牌输入属于当前 Operation UI，按 `runId + planVersion + locationId` 隔离；选择、展开、hover、scroll 不触发 Runtime 写命令或新的 View 查询。
- 同版本的局部展开/选择应保留其他人物、手牌与目标输入。版本或地点变化时清理或以当前 View 重建；暂存成功显示 Run 的 pendingSceneActionBatch。返回修改根据清除前的 detached pending 输入重建本地选中态，再按新 View 校验；不能回到随机默认项而丢失整批选择。
- 不能为了按钮化而缩小合法输入、随意默认所有目标、隐藏费用不足或缺少选择的阻塞。当前样例没有足够目标/资格投影支持的牌只保留已验证的样例输入，不承诺任意 Datapack 自动 UI。
- 结算消息可展示实际数值 before→after、事实/持有物增减、场景所用卡与实付 Cost、已提交干预/技能成功状态；无变化项可省略。规则文本、roll 数字和 UI 猜测不作为发生结果。
- `knownFactIds` 是当前状态，不能据此宣称“我”执行了某行动或现在仍持有已消费员工证；发生来源取 Resolution，持有现状取 `heldItemIds`。
- 路线履历只按自身数组顺序展示已确认转场，Cost 变化只用对应记录的已暴露值。不将路线、地点入场和结算拼成统一历史，也不推算抽牌时间/牌序。
- 结算只保留现有最近 32 条；裁剪后提示“显示最近结算”，不补造失去的细节。返回、重新进入和 Save/Resume 可从 View 重建这些记录；未暂存输入不承诺跨存档恢复。
- 中心顺序：一次性开场 → 紧凑当前情境及路线履历摘要 → 结算记录 → 终局消息或当前操作块；Dock 固定可见。场景说明与目标不在每轮重复追加。

## DOM budget 与连续性

- 新装饰 wrapper：0。学生当前行动卡优先复用现有 plan 节点；每名学生至多新增 1 个有交互职责的场景行动宿主，全队行动至多 1 个，路线摘要至多 1 个。
- 替代项与目标节点数按实际展开的合法候选计；折叠后不常驻多份完整候选列表，玩家牌按当前 hand 实例计。
- 稳定节点：workspace frame、三栏宿主、学生/对手/设施身份卡、主滚动流、结算 sequence 节点、Action Dock。
- behavior：卡内选中态、折叠、目标与预估输入；region：成功命令后的单个 `workspace.operation` 收敛。允许 structure 的条件仅为 Operation route/owner 变化。
- 同 Run 命令保留日志滚动：原本在底部才跟随新结果，阅读旧记录时保持位置；结算裁剪时保留可用锚点。
- 同语义输入仍存在时保留焦点；暂存/确认后聚焦可用下一步，失败聚焦可读 notice。popover 遵守统一 mutation 生命周期，不保留断开的锚点。
