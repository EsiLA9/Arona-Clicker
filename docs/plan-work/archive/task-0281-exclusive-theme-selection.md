# Task：主题改为单选内容，不在游戏界面堆叠

状态：completed — 主题单选路径已实施并完成代码级验收；2026-10-13

## 目标

让普通游戏界面由一个当前主题完整决定。当前场景可以声明自己的主题选项并指定默认主题；玩家可以选择当前场景可用的主题，或自己收集到的独立主题。主题选中后，其颜色、背景和 Presentation 作为当前界面的整体内容生效，不再把玩家、场景、学生、用户自定义等来源按层级合并。

本 Task 覆盖主题运行时选择与投影的简化，不改变主题资源本身的表达能力。通用堆叠、优先级和背景图层算法保留为未来能力，但退出普通游戏界面的当前选主题路径。

## 设计边界

- 本 Task 包含：
  - 将当前界面主题收敛为单一的已选主题定义；颜色、palette、节点覆盖、背景与 Presentation 均由该定义提供。
  - 场景可提供一个或多个主题选项，并明确其中的默认主题；没有有效玩家选择时使用当前场景默认主题。
  - 玩家收集的独立主题可作为主题选项，选中后完整替换当前场景主题。
  - 用户自定义主题暂时只有一个实例，但以可枚举的主题来源 / ID 接入选项解析，为将来多实例留出扩展位置；本 Task 不实现多实例存储或管理 UI。
  - 普通游戏页不再把学生主题、玩家 ColorGroup、场景主题、用户主题、预览层或剧情临时层当作多个同时有效的主题来源进行堆叠或优先级判定。
  - Init 主题仍只用于外部 Init 选择页。
  - 保留通用主题堆叠、优先级和背景图层排序算法及其独立覆盖；不删除这些未来能力，也不让普通游戏页的选中主题依赖它们。
- 明确非目标：
  - 不删除 ThemeDef、ColorGroup、ThemeDesign、背景图层或 Presentation 的定义能力。
  - 不实现用户自定义主题多实例、主题交易 / 收集玩法或新的主题编辑器。
  - 不改变 Init 选择页的独立主题预览。
  - 不把主题切换改造成跨多个主题来源的字段级继承。
- 已裁定来源：用户在 2026-10-13 提出的单主题选择方向；本 Task 将其作为待施工需求，不作为已实现机制事实。

## 施工切片

### P0：建立单一主题选项与运行时选择

- 定义稳定的主题选项身份与来源信息，使场景主题、玩家收集主题和单例用户自定义主题可统一列为候选项。
- 明确当前主题的选择状态、可用性校验和失效回退：场景默认主题作为回退；玩家选择必须来自当前场景主题或玩家拥有的主题。
- 将普通游戏页的主题投影改为读取一个已选主题定义；其完整 token、palette、节点、背景及 Presentation 一次性提供给界面。
- 移除普通游戏页对 player/area/student 多层顺序与 user / preview / ephemeral 叠加的依赖。若剧情 `setTheme` 仍需临时换肤，改为单主题整体替换并在结束时恢复原选择，不引入并行主题层。
- 用户自定义主题保留单例，但通过可扩展的来源集合接口呈现为普通候选项，不享有高优先级。

### P1：收敛用户操作与旧配置

- 将玩家可见的主题选择限定为当前场景主题与已收集主题；不存在“主题层级优先级”设置。
- 保留通用 RuntimeThemeManager 堆叠 / 优先级算法及其测试入口，标明其不是普通游戏界面的当前选择策略。
- 按 schema-sync 约定处理 `themeLayerOrder` 等旧玩家设置：普通游戏页不读取其来决定外观；兼容字段是否保留或迁移须由实际读写与存档兼容核验决定。
- 检查主题预览与保存路径：编辑预览只替换当前候选主题的预览结果，不叠加为另一来源；保存后仍由单一主题 ID 选择。
