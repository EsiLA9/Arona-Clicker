# Task 0202 — 玩法 B 重叠卡牌拖拽命中区

状态：done — 扇形卡间距修正，普通行动卡的标题与拖拽起点清晰可见

## 目标

修正玩法 B 战斗中普通行动卡与特殊技能卡扇形重叠过多、普通行动卡可见/可拖区域过窄的问题。玩家能清楚识别并抓取普通行动卡，同时保留特殊技能卡在其右侧且层级更高的表现。

## 当前事实与复现

- `prototypes/gameplay-b/src/view.ts` 的战斗卡组以 112px 卡宽、19px fan step 叠放；后出现的特殊技能卡 z-index 更高。
- 当普通行动卡与已触发的特殊技能卡同属一名 Chara 时，普通行动卡大部分面积被覆盖，只有约 19px 的左侧边缘露出。可见卡面标题与拖拽起点不一致；若从覆盖区域开始拖动，实际命中的是只读特殊技能卡，目标编辑不会启动。
- 首场战斗第 2 轮的芽衣“鼓舞”普通卡存在两个合法 `prepared-attack` 目标，Runtime 与 `pointerup` 落点提交均正常；从其左侧露出窄边起拖可将目标从由理改为纺希，事件预览同步更新。这确认目标规则与提交 API 有效，故障集中在手牌可识别和可命中的面积。
- 单一合法目标、全组固定、技能绑定行动等不可编辑约束不在本 Task 中放宽。

## 范围

- 只改 `prototypes/gameplay-b/src/view.ts` 与必要的 `prototypes/gameplay-b/src/style.css`，以及本 Task 记录。
- 为战斗行动/技能卡扇形选取足够的可见偏移量，并同步计算 `--prepared-card-space`，避免遮挡角色数据。
- 普通行动卡与特殊技能卡都必须能从其明确可见的卡面区域命中；特殊技能仍在右侧并保持更高图层。保持现有 hover / focus 拉至高层行为。
- 不改变候选目标、卡组、技能绑定规则、Runtime、Click 结算、卡片关系或 AC 主工程。

## 验收

- 在存在可编辑目标且同一 Chara 同时有普通行动卡与触发技能卡的战斗回合中，普通行动卡标题和可抓区域清晰可见；从该区域拖动可启动 ghost、高亮合法目标并提交目标转移。
- 特殊技能卡仍显示在右侧高层；拖动它不伪装为编辑普通卡。普通卡 hover/focus 时该卡及对应影响线按既有规则提升。
- 提交后战斗预览、目标线、高亮和卡牌关系更新；取消/非法落点清理状态；主 Click 仍是唯一结算入口。
- 在独立玩法 B 页面完成浏览器复现核验；原型类型检查、全量测试与独立构建通过；`npm run check:docs`、`git diff --check` 通过。
