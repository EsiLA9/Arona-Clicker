## 最终玩家与作者体验

- 玩家最终能：在数值变化、行为触发、解锁、剧情响应和持续生产之间得到一致、可解释的结果；一次性事实、可逆状态与派生缓存各自保持正确生命周期。
- 数据包作者最终能：使用清楚且边界稳定的声明定义数值生产、触发行为和领域解锁；无需理解重复的运行时接线细节，也不会把不具备可靠事件覆盖的条件误认为实时响应。
- 运行时权威事实：PlayerState、StatsSnapshot 及各领域拥有的事实字段；Registry、GameNum 缓存、Affector 实例、Trigger Registration、Condition 依赖索引、Reveal/Milestone Watch、可见性快照及 UI ReadModel 属于定义驱动或状态驱动的派生投影。具体字段仍以源码和当前机制文档为准。

## 长期边界

- 明确暂缓：把 EB-T 变成通用响应式条件框架；把所有 EventBus 订阅、缓存失效、UI 更新或每 Tick 工作都改写成 Trigger。
- 尚未裁定：是否要新增内部 `ConditionWakeSource` / Watch 层；学生阻断是否要事件化；颜色解锁是否存在值得优化的全量扫描成本；条件依赖宽事件覆盖是否需独立修复。
- Trigger/EB-T 只负责运行期唤醒、事件匹配和已准入的行为路由；领域仍负责 Admission、当前完整条件复验、权威事实提交、重建与撤出。
- Goal Set 是可删除的讨论地图，不是 Task、当前计划或机制事实源。决定进入正式讨论时新建全局编号 Draft；达到准入后另立 Task。
