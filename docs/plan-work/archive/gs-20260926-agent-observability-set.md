# Goal Set：面向 Agent 的界面与逻辑结果观测工程

Set ID：gs-20260926-agent-observability

## 最终玩家与作者体验

- 开发 Agent 最终能：从一次操作或一个问题出发，快速取得操作后的状态结果、局部构成、前后差异、相关日志和证据位置；在浏览器验收可稳定运行后，再取得操作后的最终 theme/内容渲染切片，检查切换是否及时及内容是否丢失或残留。
- 数据包作者最终能：解释某项产出、条件、支付或联动为什么得到该结果；区分定义错误、状态不满足、监听未准入、提交失败与界面未刷新。
- 玩家最终受益于：界面切换、交互连续性和玩法联动有可重复的回归证据；观测功能关闭时正常游玩不承担持续全量录制成本。
- 运行时权威事实：沿用 Registry 定义、PlayerState / Stats 及领域事实的现有归属。观测结果是带来源与采集边界的派生证据，不成为第二套游戏状态，不进入玩家存档。

## 三类核心产物

| 产物 | 回答的问题 | 最小边界 |
| --- | --- | --- |
| Result | 现在或该次操作最终得到什么？ | 原始值、单位/作用域、状态、证据来源、采集身份 |
| Slice | 与这个问题相关的局部由什么组成、哪里发生变化？ | 明确目标与深度/数量预算；父子或来源关系；前后差异；未覆盖与截断说明 |
| Log / Trace | 当时实际执行了什么，在哪一步被拒绝或中断？ | 执行序列及相位、操作/因果关联、实际记录的判断与提交结果；不可把事后重算伪装成历史 |

切片默认给摘要与可继续查询的句柄，详细数据按需展开。UI 语义结构、实际 DOM/CSS、截图和静态调用图分别标注证据类型。

## 长期边界

- 保持 StateMutationService、只读 UI、数据服务单向依赖、现有事件顺序及 UI 局部刷新护栏。观测模块采用各层的窄接口，不让 engine/data-services 依赖 UI。
- 实时观察默认不执行游戏命令、不替换真实玩家包库/存档；场景重置、单步和模拟位于明确标识的隔离执行环境。查询不能隐式暂停游戏来制造一致快照。
- 只读诊断不得改变业务状态、随机序列、事件顺序、监听生命周期或缓存失效事实。现有求值会更新缓存的路径必须在接入前裁定，不能直接标为无副作用。
- 首期明确暂缓：任意脚本远程执行、开放网络控制服务、全函数/全状态连续录制、通用时间旅行回放、自动修复、自动更新视觉基线、独立数据包编辑器改造、为观测重构全部机制。
- 不修改 AOCI 的索引规模、协议或认知建立方式；本工程解决运行结果证据的可用性，不建立第二份仓库认知索引。
- 尚未裁定：统一查询契约的宿主位置、浏览器验证工具选型、生产构建是否保留最小诊断、性能开销门槛与更多条件/随机源准入范围。G01/G03/G04/G05 的非浏览器证据先行；G02 需要真实浏览器连接以核验最终 DOM/theme 内容，恢复时再决定浏览器适配，MCP 封装后置按需。
- 终点不因首期收窄而自动改写；未来未覆盖能力以 unsupported / not-captured 表达，不以空值或“通过”掩盖。

## 成功判据

1. Agent 在受支持场景中用“摘要 → 定位切片 → 需要时展开轨迹”最多三步拿到足以定位问题的证据；无法定位时能明确说明缺了哪一层。
2. 同一隔离场景重复执行，规范化逻辑结果与断言一致；每份结果能回溯到代码/内容身份、输入、步骤和验证命令。
3. 界面构成、DOM行为、视觉与性能分别验收；刷新次数下降不自动等于视觉正确或性能改善。
4. 与关闭观测的对照相比，开启/读取观测不改变业务结果、随机调用次数、事件顺序和应保留的 UI 节点/交互状态。
5. 输出、保留条数和执行时间有预算；截断、采样、超时、环境不可用和未知结论始终可见。
