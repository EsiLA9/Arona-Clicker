# Patch Unit 0190-U2：Route Runtime 核心

## Goal

新增通用 `GameplayBRouteRuntime`，从调用方独立提供的 `initialParty` 与有序 `nodes` 初始化并推进路线。集中处理入场、招募、纯活动结算、战斗 HP 回写、线性自动转场、只读 `getView()` 与终态。此 Unit 不实现 camp sCost modifier；camp 生命周期由 U3 负责。

## Confirmed Facts

- `initialParty` 必须独立于 `nodes` 输入；正式十二节点路线可从非战斗活动开始，不能从后续战斗反推初始名册。
- 转场按数组索引；路线 node ID、活动 `locationId`、战斗 `encounterId` 各自保留，互不推导。
- 活动固定效果后判定个人检定资格；骰值及 actor ID 按路线名册顺序。活动结算后全队 HP=0 时立即失败，不转场。
- 每次 Route Click 只结算输入开始时显示的活动或战斗轮；可自动进入/准备下一节点，不自动结算其行为。
- 战斗结算的净 HP/终态由 `resolveBattleRound` 提供；Route Runtime 回写 HP，不重实现战斗结算。活动随机使用路线 seed，战斗使用运行 seed、node ID 和场序派生的稳定 seed。

## Constraints

- `onEnter` 以稳定 node/character key 幂等；角色先入队，再参与同节点活动。重复读视图不改状态或消费 RNG。
- HP 在路线名册中持续保留；每场战斗根据路线名册重建 party，敌人取当前节点模板。Battle node 模板仅含 `encounterId`/`enemies`；party 与 round 由 Route Runtime 重建，camp modifier 只能来自 activity node 并由 U3 消费。
- Route Runtime 只接受调用方的通用节点数组；不导入或硬编码 `short-route.ts` 的节点 ID、数量或转场表。
- battle node 输入类型只暴露 `encounterId` 与 `enemies`，并以编译测试保证 U1 `shortRouteNodes` 可直接赋值。
- 本 Unit 不应用 `initialSCostBonus` 或 `rechargeBonus`。`model.ts` 可声明 U3 所需输入/只读视图类型，但 camp modifier 的准备、登记、消费和测试归 U3。
- R06、R09、R10 的暂定规则不升级为用户确认规则；不修改 AC 或 `docs/docs-829/`。

## Completion Criteria

- `GameplayBRouteRuntime` 从显式 `initialParty` 与节点数组构造；支持活动起始路线。
- 通用入场/索引转场、招募幂等、固定恢复后复活者参与检定、HP 跨场景、战斗 HP 回写及全队活动倒地立即终止均有测试。
- Route view 暴露当前节点、活动度、名册 HP/row/sCost、当前冻结战斗 view、有序事件与终态；`getView()` 纯读。
- Route activity RNG 可重放；不同战斗节点获得稳定且不同的派生 seed。
- 新节点只自动进入/准备，不在旧节点最后一次 Click 内执行新行为。
- `R06/R09/R10` 暂定状态及用户确认的全队活动倒地边界不变。
