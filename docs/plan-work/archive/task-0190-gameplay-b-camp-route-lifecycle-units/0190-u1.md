# Patch Unit 0190-U1（P0）：场所活动与全队失能边界

## Goal

定义独立于页面的场所活动配置与纯结算函数，按场所内容输出固定全队效果、逐人检定/伤害和有序事件；并提供 U2/U3 消费的五节点有序短路线内容（首战→节点6入队/补给→节点7危险活动→第二战→出口）及中途角色数据。活动函数提供全队 HP 归零的确定结果供 U2 Route Runtime 立即终止；U1 不实现路线状态机。

## Constraints

- 活动规则按固定输入与已提供骰值返回结果；此 Unit 不写 Runtime 状态，统一写入留给 U2 Route Runtime。
- `short-route.ts` 提供五个有序节点的内容表和节点活动/入队/战斗/出口数据，使 U2 可将其作为调用方传入的路线节点表；U2 Route Runtime 仍必须通用，不能硬编码这五个节点。节点6的千世在其活动前加入；节点10的玲奈仅通过专用 camp fixture 覆盖，不插入0190五节点短路线。
- 当前没有节点9遭遇的正式实现输入；为满足0190的第二战 Click 流程，可在 `short-route.ts` 复用已有首战战斗夹具并使用不同的临时 encounter ID，明确标注这是短路线施工样例、后续由0191正式遭遇内容替换。不要把此临时敌方配置写成导演最终内容或用户裁定。
- 当一项活动同时包含固定全队效果与逐人随机检定时，原型默认先结算固定效果，再按该阶段更新后的 HP 判定个人检定资格；固定恢复把倒地 Chara 救起后，该角色可参与本活动后续个人检定。此时序属于 R10 原型暂定默认，须与 0182 营地文本对照，并留待 2026-10-04 用户验收；U1 测试应覆盖 HP0 固定恢复后参与/未触发的分支。
- 活动度每个有效场所 Click 只减少一次由 U2 Route Runtime 保证；U1 输出供其消费的事件/HP delta，不把下一节点结果并入同一批结果。
- R06 与 R10 保持原型暂定默认；R09 仅非配方攻击标记/范围处理及未明确的配方优先级/匹配顺序保持暂定。三种基础配方输出为用户已确认内容，本 Unit 不改变这些输出，也不重定其他 R06/R09 规则。
- 线索只追加到事件日志，不能形成运行状态、资源、旗标或路线分支。
- 全队归零时 U1 的结算结果显式带出失败判定；U2 Route Runtime 必须在自动转场前消费该判定并设终态。

## Completion Criteria

- [x] 固定全队效果先结算，再以活动阶段当前 HP 判定个人随机/属性检定资格；仅当前 HP>0 的在队角色参与，明确的固定恢复可按暂定 R10 顺序先救起倒地者，再参与该活动的个人检定；逐人顺序符合 0186、0182 和 0184，并在 Receipt 标明此默认待明日验收。
- [x] 纯函数接收当前成员状态、固定场所规则与预先抽取骰值，返回逐人结果/HP delta/有序日志，不改输入状态或消费 RNG。
- [x] `short-route.ts` 暴露首战、节点6（含千世入队和开场 +1）、节点7、第二战、出口五节点有序内容；第二战如复用首战模板须标为临时样例，路线 ID/顺序清晰、不会被 Runtime 硬编码。另提供节点10玲奈加入/恢复/recharge 的 U3 测试夹具。
- [x] 纯结算结果显式提供 `partyDefeated`；Route Runtime 可据此先于转场立即结束，不进入下一节点或营地救援。
- [x] R10 线索只出现在事件日志，不形成旗标、资源、持久线索状态或分支；相同输入与预先骰值可复现逐人结果和事件顺序。
- [x] U1 只提供纯结算；状态写入、活动度消费与终态控制由 U2 的 Route Runtime 统一负责。
