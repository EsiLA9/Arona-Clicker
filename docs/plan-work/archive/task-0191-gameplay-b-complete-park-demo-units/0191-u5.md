## Constraints

- 校验函数纯读输入，不修改 Route、Runtime、内容或事件状态。
- 对节点唯一 ID、引用存在性、固定顺序、节点 5/9/11 战斗位置、九个非战斗 activityCount 合计 11、节点 6/10 recruit 顺序提供明确失败说明。
- 不要求把每个 content string 的叙事写作质量变成算法规则；文本与意图语义由 U4/U3 的人工对照与测试负责。
- 使用 U4 实际 schema 和真实 ID；校验器不发明内容 type 或跨域映射。
- 暂定规则标记状态仅作 Task/Receipt 文档要求，不增加游戏存储字段。

## Stop Conditions

遵守 PROJECT-CONSTITUTION 六条停止条件。另有专项停止项：U4 Route schema 未定或未完成；0190 交接缺失；校验需要额外文件/全仓库扫描；需裁定 R10 或其他临时规则；净改动低于 160 行或超过 500 行、总文件超过 5；内容测试/typecheck 失败。停止并交回最小事实，不顺手修 U4 内容。

## Completion Criteria

- [ ] 校验拒绝重复/空节点 ID、悬空遭遇/活动/角色引用和非预期节点顺序。
- [ ] 校验三场战斗只能在 5/9/11，非战斗 activityCount 总和为 11，招募仅在 6/10 且活动前。
- [ ] 每种失败提供节点/引用定位信息；合法十二节点通过。
- [ ] Validator 纯读、可重放、无持久状态写入。
- [ ] 新增边界测试覆盖缺引用、重复 ID、错误顺序、活动度不匹配；content test 和类型检查通过。
