# Draft：玩法 B 孤立样本引擎

状态：draft — 概念规则；不实现为 TS，不接入 AC 当前实现

> R06、R09、R10 的以下口径是原型暂定基线，待用户明日验收；本标注不代表用户已逐项确认。

## 目标与边界

为玩法 B 初次原型提供一套容易阅读、容易手算的数值与事件规则，供导演角色草案和界面草案共同引用。本文描述的是一套孤立的样本引擎，不是 AC 现有引擎的扩展计划，也不授权修改或接入 Story、战斗、地图、状态、Datapack 或 UI 代码。

运行时只有一种玩家输入：**Click**。非战斗时它完成一次场所活动；战斗时它结算屏幕上已经准备好的一整轮。角色如何行动、敌人打出什么意图牌、随机技能是否触发，均由配置和随机序列自动决定。没有实时计时、点击速度比较、其他玩家输入、构筑界面或临场选牌。

本文给出小整数候选值和通用接口。具体角色、普通牌组、技能、敌方模板、场所效果和文本由对应内容草案提供；引擎不另造一套独立牌库。

## 最小运行状态

一局只需保存以下状态。角色卡牌与场所规则作为只读配置引用，不在运行中改写配置。

| 状态 | 最小字段 | 用途 |
| --- | --- | --- |
| 行动进度 | 当前场所序号、场所剩余活动度、运行结束标记 | 线性路线推进；活动度归零后自动前往下一场所 |
| 随机进度 | 本局 seed、随机数序列当前位置 | 重复同一局时复现随机结果 |
| 我方名册 | Chara ID、前/后排、HP、战斗内 sCost、临时护盾、待用攻击 +1 标记（每人最多 1 个）、是否在队伍中 | 初始 2 名前排 + 2 名后排；节点 6 与 10 各加入一名前排，最终 4 前排 + 2 后排 |
| 当前战斗 | 敌方参战者、回合序号、双方本轮已准备的行动牌、行动牌来源顺序、有效营地加成 | 显示敌方意图与我方自动形成的行动，供 Click 结算；sCost 只在当前战斗中有效 |
| 事件日志 | 连续序号、场所/回合、事件类型、来源、目标、结果与随机点 | 展示聊天内容并复核结算 |

### Chara 与行动牌配置接口

Chara 配置至少提供 HP 上限、ATK、DEF、前/后排、自己的普通技能牌组及其选择倾向、一个随机技能。新加入角色以满 HP 入队，并从加入场所的活动 Click 起参与全队行为；sCost 在每场战斗开始时统一初始化。敌人配置提供基础数值和回合意图牌序列。导演草案定义具体数据；此引擎只读取它们。

普通牌不从全队公共牌库抽取：每名 Chara 只从自己配置的普通牌组中选一张。触发型技能可生成免费额外行动；用户已确认纺希“校准镜”作为免费修正只给本轮普通狙击 +1，不生成第二张狙击牌或第二次攻击。敌人使用其模板配置的意图牌。各行动使用同一张**行动牌记录**，以便交给同一套匹配与效果流程：

| 字段 | 含义 |
| --- | --- |
| 来源与顺序 | 我方/敌方、Chara ID、该 Chara 本轮牌序号 |
| cardTag | 一个或多个匹配标签，由角色/敌人内容配置提供 |
| sCost | 普通牌费用；随机技能牌为 0；敌方意图牌不走我方 sCost |
| 目标规则 | 前排优先、指定排、任意存活目标或多个目标；未特别声明时按前排优先 |
| 效果 | 伤害、掩护、恢复、Buff 等简单效果；牌本身或配方声明效果。修正型技能附着于原牌，不复制攻击或 Tag 牌 |

配方只引用这些牌的 cardTag 与来源，不复制或发明牌组。若角色草案命名/字段尚未定，引擎合稿时统一名称即可。

## 唯一推进输入与流程

路线起点和每个新场所都自动进入；进入场所、战斗结束和路线结束不另要 Click。玩家下一次 Click 永远处理当前屏幕所展示的待推进单位。

### 非战斗场所

**R10 原型暂定、待用户明日验收：**线索发现仅写入事件日志，不保存任何线索状态，不改变资源、固定线性路线或解锁条件。无人发现时使用内容定义的兜底文本，路线继续按节点顺序前进。

1. 新场所进入时载入唯一的首版活动及其活动度。场所入场事件（例如固定加入一名新角色）立即执行并记日志，不额外消耗 Click。
2. 每次 Click 执行全队共同的这一种活动。每名 HP 大于 0 的在队 Chara 按相同活动规则分别掷骰并得到个人结果；活动度减 1。HP 为 0 的角色不参加检定，但营地等明确的恢复事件仍可作用于他们。
3. 活动度大于 0 时，显示事件结果并留在本场所。活动度归零时，自动进入路线中的下一场所；下一次 Click 才结算新场所。
4. 最后场所活动结束时直接记录 Demo 完成。

场所活动只引用已有属性和 Tag，不新增探索属性。活动可以是固定全队效果，也可以附加逐人随机结果；需要考验学生差异时，再配置引用 ATK 或 DEF 的难度检定、可加成的 Tag 及成功/失败效果。HP 不参与活动检定，负责耐久；活动效果可恢复或消耗 HP。

建议检定公式：

```text
检定值 = 1d6 + 指定属性 + (拥有指定 Tag ? 1 : 0)
成功：检定值 >= 活动难度
```

普通检定难度候选为 6，较难检定为 8。只有定义了逐人随机结果的活动才掷骰，每名 Chara 各掷一次；同一活动的结果可以不同。不做属性检定的个人机会可以使用 `1d2` 表示 1/2 成功，例如营地固定恢复之外个人额外找到敷料；不要求每个场所都使用属性检定。内容配置决定成功和失败分别发出什么事件，例如恢复 1 HP 或记录线索。失败可以是无收益，不强制附加伤害。每次非战斗活动结算后若我方全员 HP=0，立即结束本次行动；不再继续路线等待营地救援。

### 战斗场所与准备中的回合

每场战斗开始时，每名我方 Chara 都将当前 sCost 重设为基础 2/5，再应用尚未消耗的一次性营地加成；上场战斗剩余的 sCost 值不保留。营地加成是独立的战间效果，可令下一场战斗开局值提高，或提高该场战斗内的回合回复速度。战斗结束后清除当前 sCost。进入战斗场所时敌方参战者按模板生成，并消耗已配置为“下场战斗”的营地加成。引擎自动准备第 1 轮，并把双方牌列展示在当前界面。之后每次 Click 结算所展示的一轮；只要战斗未结束，引擎就立即准备并展示下一轮。

每一轮的准备顺序固定如下：

1. 从第 2 轮开始，我方仍可战斗的 Chara 各回复 1 sCost，上限 5；溢出舍弃。第 1 轮不做这次回复。
2. 敌方按各自模板的意图顺序放入本轮意图牌。一个敌人可按模板打出一张或多张牌；敌方意图不消耗我方资源。简单样本优先用固定循环序列，避免额外随机点。
3. 每名存活我方 Chara 按自身牌组、当前状态和牌组内的倾向顺序选择最多一张可用普通牌。按选择时支付其 sCost；选出的牌保留在本轮牌列中。
4. 若没有满足倾向和保留资源条件的可用普通牌，该 Chara 选择零费用“观察/待机”，不形成普通攻击牌。Click 结算后，仍存活的待机 Chara 回复 1 sCost，上限 5。
5. 对每名 Chara 的随机技能先检查内容定义的条件；条件成立时掷一次 `1d4`，掷出 1 即以 1/4 概率触发。成功就加入该技能的免费额外行动或效果，不花 sCost，也不占普通牌次数；每名 Chara 每轮最多触发一次。若内容以后为同一 Chara 配置多个技能，再由角色草案约定检定顺序与次数。
6. 所有本轮牌就绪后等待 Click。牌列已生成，玩家无需也不能再输入其他指令。

普通牌选择的通用接口是角色自带的优先列表：逐条检查其情境条件、sCost 能否支付及支付后是否满足该角色的保留值；选择首个符合的普通牌。若均不符合则待机。角色草案可用不同优先级、条件与保留值表现“偏向掩护/狙击/攒费”，引擎不用另设一份 AI 牌库。

**R06 原型暂定、待用户明日验收：**只有明确指定的应急优先牌可越过支付后保留线。芽衣的医疗、千世的现场包扎仅在队友受伤且 HP 不高于上限一半时豁免；玲奈的掩护仅在本轮存在敌方冲锋意图时豁免。豁免只跳过保留值检查，仍须付清牌费；情境条件、合法目标和完整费用照常检查。不满足条件或付不起费用时继续查优先表下一项。牌一经准备，不因后续 Tag 配对结果重选。

### Click 结算一轮

1. 冻结已准备的我方普通牌、随机技能行动与敌方意图牌；不在结算过程中重新选牌或重掷触发骰。
2. 按下节规则对本轮牌做一对一 Tag 匹配。
3. 匹配成功的牌按其配方产生一个替代结果；未匹配牌各自应用自己的效果。被配方消费的原牌不再重复结算。
4. 先生成护盾与攻击加成，再按同一公式计算各次攻击。指定 Chara 持有的攻击 +1 标记可用于本轮已准备、尚待结算的攻击；每人最多一个，不叠加，可跨轮保留，下一张造成伤害的行动牌结算时消耗，战斗结束清除。范围牌对每个有效目标各加 1，但整张牌只消耗一个标记。角色本轮开始时存活则其已准备行动仍会结算，即使它在本轮同时受到致命伤害。
5. 每名角色本轮护盾不叠加，取各来源中的较高值；把其受到的本轮总伤害合计后，护盾先吸收伤害，剩余伤害再与恢复量一起结算：`新 HP = clamp(轮初 HP + 本轮恢复总量 - max(0,本轮总伤害 - 本轮护盾), 0, HP上限)`。护盾在轮末清除。仍存活的待机 Chara 此时额外回复 1 sCost，上限 5；HP 为 0 的角色不获待机回复。
6. HP=0 代表失去战斗能力，不再准备后续战斗行动。若本轮恢复令结果高于 0，该角色仍存活；普通恢复不得超过 HP 上限。
7. 检查胜负。敌方所有参战者 HP=0 为胜利；我方所有参战者 HP=0 为失败；双方在本次 Click 后同时全灭则平局。结果发生后不准备下一轮。
8. 胜利自动进入下一场所；失败或平局记录终局并结束 Demo。没有额外移动 Click、撤退、复活重试或复活次数系统。

## 数值与效果候选

导演角色草案已给出小整数示例：我方 Chara HP 上限为 8–13、ATK 1–3、DEF 0–1；杂鱼 HP 6–9，强敌 12，Boss 18。样本引擎按内容表读取这些数值，不再另定一套范围；这些仍是待体验候选。

普通攻击沿用导演草案的公式：

```text
基础伤害 = max(1, 攻击者 ATK - 目标 DEF)
结算伤害 = max(0, 基础伤害 + 本次攻击加成 - 配方削弱值)
```

鼓舞或免费技能可给指定 Chara 一个待用 `+1` 攻击标记；标记不叠加，可跨轮保留，下一张造成伤害的行动牌结算后消耗，战斗结束清除。同轮产生的标记可用于同一 Click 中尚待结算的攻击。范围牌逐个有效目标计算伤害时，每个目标都加 `+1`，但标记在整张牌结算后只消耗一次。内容明示为固定伤害的范围牌仍按牌面值对每个指定目标结算；普通范围攻击对每个目标各用上述公式。掩护提供目标本轮 2 点护盾，先吸收该目标所受伤害；同一目标有多种护盾时只保留数值最高的，不叠加，轮末清除。恢复量直接按牌面固定值且不超过 HP 上限。伤害没有命中、闪避或暴击随机。以上 R09 口径为**原型暂定、待用户明日验收**，不表示用户逐项确认。

### 一轮手算示例

攻击者 ATK=3 攻击 DEF=1 的目标，基础伤害为 `max(1,3-1)=2`。“敌方冲锋 + 对同目标的我方掩护”将该冲锋伤害削弱 1，掩护仍给目标 2 点护盾；先将基础伤害降为 1，再由护盾吸收，HP 不变、护盾剩 1 点。配对的两张原牌都不再重复结算。

该示例只解释公式与配方能如何串接。具体威力、角色数值、掩护是否形成匹配和输出效果由导演内容草案裁定。

## cardTag 一对一匹配

配方表属于引擎配置格式，不是新增的牌组。每条配方声明：所需两侧（我方/敌方/同侧）、左右 Tag、结算类别、目标关联、不同 Chara 限制、替代输出效果和优先级。用户已确认三种首版配方；引擎采用优先级从高到低、同级按牌列顺序的确定性匹配：

| 类别 | 统一含义 | 示例意图 |
| --- | --- | --- |
| 抵消 | 取消配方指定的原牌效果 | 狙击针对掩护，抵消该掩护效果 |
| 削弱 | 用调整后的效果替代原效果 | 掩护应对冲锋，将冲锋威力减 1 后结算 |
| 合成 | 两张原牌被一个新结果替代 | 我方冲锋 + 我方掩护生成“掩护推进”效果 |

| 优先级 | 配方 | 限制 | 替代输出 |
| ---: | --- | --- | --- |
| 1 | 敌方掩护 + 我方狙击 | 狙击目标与被掩护目标相同 | 移除目标 2 点本轮护盾，再由狙击按通常公式攻击一次 |
| 2 | 敌方冲锋 + 我方掩护 | 掩护目标与冲锋目标相同 | 冲锋伤害 −1（最低 0），目标获得掩护原本的 2 点本轮护盾 |
| 3 | 我方冲锋 + 我方掩护 | 两张牌来自不同 Chara | 冲锋伤害 +1，冲锋者获得 1 点本轮护盾；原 2 点掩护不另行结算 |

匹配顺序固定：配方按显式优先级从高到低；同级按配置文件顺序。对每条配方，从对应两侧的牌列顺序中各取第一张尚未匹配且满足目标、角色条件的牌，组成一对并标记已用；继续寻找下一对，直到不能再配。匹配一对后不能再参加其他配方。若一张牌带多个 Tag，优先级最高且牌序最早的可用配方生效。未匹配牌按自身效果结算；已匹配牌只结算表中明确列出的替代输出，不列出的原效果不再发生。该规则保证同一牌列和配方表始终给出相同的结果。

## 目标规则与后排保护

每张攻击牌在内容配置中声明目标排规则：

- 普通敌方攻击默认为前排优先；只要有存活前排就不能选后排。
- 若前排已无存活 Chara，普通攻击可选任一存活我方角色，避免只剩后排时战斗软锁。
- 只有明确标记为“任意排”或“后排”的攻击牌，才可在有前排时攻击后排。该牌形成意图时在日志中明确显示“锁定后排”。
- 我方攻击由角色牌的目标规则选择敌方。无特别目标偏好的默认取敌方当前 HP 最低者；同值按队列顺序。目标在准备阶段确定，本轮内不因别的攻击而重选；目标在同轮被击倒后，之后指向它的伤害记为溢出，不转移给其他角色。

这让后排能正常行动和攻击，通常受前排保护；例外攻击来自可被识别的牌，而不是隐藏随机目标。

## 营地、加入角色与事件

营地沿用普通场所的 Click 与活动度规则，不增加交互输入。当前 sCost 值不会跨战斗保存；营地可给紧接的下一场战斗配置一次性开局值或回复速度加成。沿用导演草案的首版试验参数：节点 6 令下一场战斗每人开局 +1 sCost；节点 10 令 Boss 战从第二轮起每轮额外回复 1 sCost，均受 5 点上限限制。具体 +1 数值待试玩，不代表生命周期规则待定。营地活动还可令全队各恢复 2 HP、个人额外获得 1 HP。此类活动 Click 在自动加入事件之后执行。

角色加入作为**场所进入事件**：地图配置在节点 6 急救补给站自动加入前排千世，在节点 10 后台休息室自动加入前排玲奈。事件发生时立即把角色追加到队伍并记录，不消耗活动度或 Click；千世加入后为 3 前排 + 2 后排，玲奈加入后全队为 4 前排 + 2 后排，六人都从此参与战斗和场所活动。入队事件以唯一事件 ID 去重，自动切换或重复读档不会重复加入；不提供编队、替补或接受加入输入。

通用事件种类只保留这些：

| 事件 | 效果 |
| --- | --- |
| 场所活动成功/失败 | 按活动定义检定/随机，恢复 HP、扣 HP、写入下场战斗一次性 sCost 加成、发 Buff 或只写线索日志；可在固定全队效果之外给个人加独立概率结果 |
| 战斗行动结果 | 计算伤害、防护、恢复或简单属性 Buff |
| 角色加入 | 将一个预定义 Chara 加入名册一次 |
| 场所完成 | 活动度归零后移动到下一场所 |
| 战斗终局 | 写胜利、失败或平局，并按规则推进/结束 |
| Demo 结算 | 记录终局结果并停止推进 |

### ReadOnlyView 投影（R06、R09、R10 原型暂定）

UI 只读取已准备行动、队伍状态和追加的事件日志：

- AI 预览展示实际选出的牌与目标；应急牌越过保留线时，日志说明牌费已支付及越过的保留值，不提供玩家选牌输入。
- 角色状态投影显示待用攻击 +1 标记归属的 Chara；攻击结算日志按目标列出加成后的伤害，并在整张范围牌完成后清除标记。
- 线索只作为事件日志条目展示。界面不投影线索旗标、计数、资源、路线分支或解锁状态；节点推进始终遵循固定线性路线。

本节的 R06/R09/R10 均为**原型暂定、待用户明日验收**，不表示用户逐项确认。

事件采用固定顺序运行。所有随机结果先记录在事件日志，再应用明确的效果。首版不设事件脚本语言、嵌套触发器、计时器或条件链编辑器。

## 随机与日志约定

全局使用一条可播种的伪随机序列；一局开始时载入固定 seed。随机调用顺序固定为：场所活动按队伍名册顺序逐人检查；之后每轮技能按我方名册顺序逐人检查。普通技能检定按角色条件掷 `1d4`（1 为触发），场所 1/2 机会可掷 `1d2`；需要考验属性的活动则用 `1d6 + 指定 ATK/DEF + Tag加成 >= 难度`。没有配置随机项的场所只执行固定效果。敌方意图序列和目标挑选首版保持确定性。

每次随机调用把骰值写进日志。相同配置、seed 和 Click 序列应产生相同结果。渲染界面、滚动日志和重新查看已结算内容不得消耗随机数；只有产生新的活动或战斗准备事件时才推进序列。seed 可供调试/复盘固定，但不新增为游戏中的玩家操作。

一条战斗日志尽量按“敌方意图 → 我方行动 → 匹配结果 → 伤害/恢复 → HP 与 sCost 变化 → 胜负/前进”顺序简短呈现。非战斗日志按“场所行为 → 各 Chara 检定骰值与结果 → 效果 → 剩余活动度/自动前进”呈现。
