# Task：全数据包浏览、普通态与编辑态数据包工作流

状态：proposed — 🟡 玩法与易用性规划，待裁定与拆分施工

归档原因：已合并至 `task-0110-datapack-editing-state-and-targeted-authoring`，不再单独推进。

## 目标

让玩家可以从包库中浏览任意已登记数据包，并把普通态数据包复制为独立的编辑态数据包。数据包的逻辑身份由 `ModId + VersionId` 构成；数据包记录另有 `normal` / `editing` 状态。原先的“启用编辑态”不再创建全局临时编辑槽，而是创建一个专门用于编辑的数据包记录；同一时间只允许一个编辑态数据包作为 Runtime Editor Overlay 活动运行。

本 Task 只规划数据包 Catalog、普通态 / 编辑态生命周期、Runtime Session / Overlay、页面信息架构、切换保护和易用性；不实现压缩包写出服务，也不重新设计 Datapack 文件格式。它是 `task-0108-runtime-editor-export-import-modid-handoff` 的前置任务。

## 核心认知

### 普通态与编辑态是两种不同的数据包记录

- **逻辑身份**：普通态与编辑态共享 `ModId + VersionId` 这一逻辑身份，但在本地 Catalog 中是两个不同的记录；不能用逻辑身份直接覆盖其中一条。
- **普通态**：从 ZIP / 文件夹读入后产生的标准数据包记录，是只读来源和编辑基线；可被浏览、启用或复制为编辑态。
- **编辑态**：普通态的完整副本，专门用于内容编辑、预览、保存和导出；编辑态中的所有内容字段都必须可编辑，不能以“暂不支持字段”作为最终交付语义。
- **内部记录身份**：每条 Catalog 记录必须有独立的 `recordId` / `packRecordId`，用于区分同一 `ModId + VersionId` 的普通态、编辑态和未来其他副本。
- **状态归属**：`normal` / `editing` 是本地 Catalog 的生命周期状态，不擅自写入标准 Datapack 文件格式。导入任何包文件一律先登记为普通态；导出编辑态内容产生的仍是普通数据包文件，重新导入时按普通态包处理。

这样既能保留导入文件作为稳定基线，又能让编辑器对编辑态数据包承担完整内容编辑责任。

### 三个对象必须在界面上分开

| 对象 | 用户看到的名称 | 语义 |
| --- | --- | --- |
| 普通态数据包 | 数据包 | `PackManager` 中登记的不可变来源；可浏览、启用、复制为编辑态 |
| 编辑态数据包 | 编辑中：数据包名 | 普通态的独立副本；所有内容字段均可编辑，保存、预览和导出都作用于它 |
| Runtime Overlay | 运行中：数据包名 | 某份编辑态数据包已 Apply 后在当前 Runtime 中的物化结果；同一时间最多一份 |
| 压缩包文件 | 已保存的数据包文件 | 外部文件服务产生的普通数据包；不自动替换原包或加入启用集 |

“关闭编辑器”只隐藏工作区；“结束 Runtime Session”解除 Overlay 但默认保留编辑态数据包；“删除编辑态数据包”才是删除编辑态记录的明确动作。三者不能共用一个含糊的关闭按钮。

## 设计裁定

### 1. 包库是入口，维护普通态 / 编辑态数据包 Catalog

包库页面展示全部数据包，并同时提供两种动作：

- **查看**：只改变当前浏览对象，不影响任何编辑态数据包；允许用户在查看其他包时继续保留当前编辑器状态。
- **切换为编辑态**：以目标普通态数据包为基线，复制出新的编辑态数据包，生成独立的 `packRecordId`，并打开它。
- **打开编辑态数据包**：从 Catalog 选择已有的 `packRecordId`，恢复它的内容和编辑上下文；不会重新复制来源包。

编辑器顶部固定显示：

```text
编辑中：<数据包显示名>  ·  ModId <modId>  ·  VersionId <versionId>
来源：<普通态数据包 recordId>  ·  编辑态 recordId <packRecordId>
状态：未修改 / 有未保存修改 / 已恢复 / 存在阻断问题
```

包库列表可以显示多个“已有编辑态”标记，但只能有一个“Runtime Overlay 活动”标记。浏览选中态、当前编辑态数据包和活动 Overlay 必须分开，避免用户查看其他包时误以为已经切换了 Runtime 来源。

### 2. 从普通态立即创建编辑态数据包

从普通态数据包点击“切换为编辑态”后，用户感知到的流程必须是原子完成的：

```text
包库原包
  → 复制当前内容与元信息
  → 建立编辑态数据包记录(packRecordId)，绑定 sourceRecordId / sourceDigest
  → 进入编辑工作区
```

创建编辑态数据包的规则：

- 初始内容以目标包当前快照为基线；不要求目标包已启用，也不因编辑而自动启用。
- 原包继续留在包库中，名称、版本、启用状态和来源不被编辑操作改写。
- 编辑态数据包记录来源普通态的 `recordId`、逻辑身份和基线摘要；用户必须能看出“正在编辑的是副本”。
- 编辑态数据包创建后即使用户还没有改任何字段，也视为“已进入编辑中”；不能在用户点击切换后再等待 Apply 才建立编辑态。
- 重新点击已有来源的编辑入口，应优先打开现有编辑态 `packRecordId`；只有用户明确要求“新建编辑副本”时才创建新的记录。
- 编辑态的所有内容字段都必须进入可编辑表面；不能把字段留成只读、未接入或通过空值静默覆盖。暂未完成的字段属于施工未完成，不属于最终编辑态契约。

### 3. 多份编辑态数据包，切换当前目标必须保护用户工作

当已有编辑态数据包时，用户可以浏览其他包并保留多个 Catalog 记录；点击“切换为编辑态”或切换当前编辑目标时，必须先判断当前表单是否有尚未写回 Catalog 的输入：

| 当前编辑态数据包 / 表单状态 | 点击另一个“切换为编辑态”或切换目标 | 结果 |
| --- | --- | --- |
| 无修改、无阻断问题 | 立即切换 | 保存当前上下文后选择目标 `packRecordId`，不删除原编辑态数据包 |
| 有未保存修改 | 阻断切换并给出选择 | 保存当前草稿 / 保存为压缩包后切换 / 放弃当前输入并切换 |
| 只有阻断问题、没有用户修改 | 明确提示 | 继续处理当前问题，或确认放弃后切换 |
| 已从快照恢复但尚未确认 | 视为有工作 | 不允许无提示覆盖恢复的编辑态数据包 |

“保存为压缩包后切换”只定义为未来归档服务的 UI 接点：服务成功后才允许切换，失败则继续停留在当前编辑态数据包；本 Task 不规定压缩算法、文件布局或服务内部实现。

### 4. 编辑态数据包不自动成为 Runtime Overlay

编辑态数据包的几个动作必须明确区分：

- **保存编辑态**：保存指定 `packRecordId` 的全部内容，供关闭面板、刷新或重启后恢复；不改变 Registry、启用集或玩家状态。
- **应用预览**：沿用现有 Runtime Editor 的受控 Apply 语义，把当前编辑态数据包用于当前会话的 Runtime Overlay；按钮文案和确认区必须说明这不是覆盖普通态原包。
- **保存为压缩包**：交给外部归档服务生成普通数据包文件；成功后保留编辑态数据包，允许继续修改。
- **结束 Runtime Session**：解除当前 Overlay 关系，但默认保留编辑态数据包；有未保存输入时必须先保存或明确放弃。
- **删除编辑态数据包**：明确删除编辑态 Catalog 记录；若它有活动 Overlay，必须先结束 Session 或确认影响。

编辑一个未启用包不得隐式启用它；编辑一个内置包不得隐式替换内置包。若未来需要把编辑结果安装、替换或加入启用集，应在包库层另设明确动作和影响预览。

### 5. 编辑态数据包与 Runtime Session 的生命周期

| 阶段 | 进入方式 | 用户可见反馈 | 允许的离开方式 |
| --- | --- | --- | --- |
| 浏览原包 | 打开包库 / 查看包 | 只读来源、启用状态、版本、依赖提示 | 查看其他包、开始编辑 |
| 创建编辑态 | 普通态切换为编辑态 / 新建编辑态 | “已创建编辑态数据包，尚未应用到游戏” | 编辑、关闭工作区、切换当前目标 |
| 编辑中 | 输入字段或集合操作 | 当前 `ModId + VersionId`、修改计数、诊断和保存状态 | 保存编辑态、应用预览、保存压缩包、切换目标 |
| Runtime Overlay 活动 | 明确执行 Apply | “当前编辑态数据包已应用为 Runtime 预览” | 继续编辑、结束 Session、切换目标前先处理 Overlay |
| 已恢复 | 浏览器重启或页面刷新 | “已恢复上次编辑态数据包，尚未应用” | 继续、保存、切换、结束 Session |
| 来源失联 | 普通态来源被删除或摘要不再匹配 | “来源已不可用；当前编辑态数据包仍保留” | 继续编辑 / 保存为压缩包，或删除 |

关闭工作区不改变阶段；结束 Session 只解除 Overlay，删除操作才会让编辑态数据包离开 Catalog。

### 6. 状态模型与可复用接口

普通态 / 编辑态数据包的逻辑身份不能单独承担 Catalog 记录身份。建议固定以下纯数据边界：

```ts
type PackRecordId = string;

interface DatapackRecord {
  readonly packRecordId: PackRecordId;
  readonly modId: string;
  readonly versionId: string;
  readonly state: 'normal' | 'editing';
  readonly sourceRecordId?: PackRecordId;
  readonly sourceDigest?: string;
  readonly content: DatapackContent;
  readonly updatedAt: number;
}

interface RuntimeEditorSession {
  readonly sessionId: string;
  readonly editingPackRecordId: PackRecordId;
  readonly hasRuntimeOverlay: boolean;
  readonly overlayRevision: number;
  readonly appliedDigest?: string;
}

interface DatapackWorkspaceView {
  readonly records: readonly DatapackRecordSummary[];
  readonly activeEditingPackRecordId?: PackRecordId;
  readonly session?: RuntimeEditorSession;
}
```

命令门面至少需要覆盖：

```text
importNormalPack → createEditingPack → selectEditingPack → saveEditingPack
                                               ├→ applyEditingPack
                                               ├→ endRuntimeSession
                                               └→ deleteEditingPack
```

普通态记录是导入服务的结果，也是编辑态的只读基线；创建编辑态时复制其完整内容并记录来源关系。Catalog 层可以保存同一 `ModId + VersionId` 的普通态与编辑态记录，甚至保留多个编辑副本，但每条记录必须通过 `packRecordId` 区分。Apply 时必须由 Runtime facade 重新校验，Runtime 层同一时间只允许一个 Overlay。UI 只消费 `DatapackWorkspaceView`，不能直接持有 Catalog 的可变对象，也不能自行拼装“清理 Overlay → reload”。

### 7. 包来源与版本的易用性

- 列表同时显示 `name`、`modName`、`version`、来源类型、启用状态和依赖状态；同名包不能只靠显示名区分。
- 同 `modName` 的多个包可以并存于包库，编辑时以唯一的包库身份和版本作为来源；不因为名称相同就覆盖彼此。
- 内置包显示“内置 / 不可删除”，但仍可“创建编辑副本”。编辑结果默认作为新数据包文件处理，不回写内置包。
- 未启用包显示“未启用”，仍可编辑；编辑工作区明确提示“编辑不会自动启用”。
- 被禁用或缺依赖的包仍可浏览其原始内容；预览 / 应用时才显示运行条件问题，不把查看和启用混成一个动作。

### 8. 对玩法状态的安全边界

数据包编辑属于内容创作，不属于玩家当前世界线的普通操作：

- 开始编辑、修改字段、保存草稿、切换编辑包都不改变资源、角色、剧情进度、背包、好感或其他 PlayerState。
- 预览应用如果会影响当前运行内容，必须显示影响摘要，并保留现有失败回滚和当前编辑上下文。
- 编辑器不得把“当前运行内容”反写成编辑副本基线；基线来自用户明确选择的包库原包。
- 当前游戏正在运行时切换包库浏览对象，不应暂停或重启游戏；只有明确的预览 / 启用动作才进入运行时应用边界。

## 页面与交互规划

### 包库页

包库页是所有数据包的统一入口，建议分为三个区域：

1. **包列表**：搜索、来源筛选、启用状态筛选、版本和依赖状态。
2. **选中包详情**：内容概览、`ModId + VersionId`、普通态 / 编辑态、来源、启用状态和依赖。
3. **操作区**：查看内容、切换为编辑态、打开编辑态数据包、结束 Runtime Session、删除编辑态数据包；危险动作需要影响说明。

列表中的状态组合至少包括：

| 标记 | 含义 |
| --- | --- |
| 有编辑态 | 该逻辑包存在一个或多个编辑态记录 |
| 当前编辑态 | 当前工作区选中的 `packRecordId` |
| Runtime Overlay 活动 | 该编辑态数据包已 Apply 到当前 Runtime |
| 有未保存修改 | 当前编辑态数据包相对其基线发生变化 |
| 普通态 | 导入得到的只读数据包记录 |
| 未启用 | 包库存在但不参与当前运行启用集 |
| 来源已变更 | 编辑态记录的 `sourceDigest` 与普通态当前摘要不一致 |

### 编辑工作区

沿用现有 Runtime Editor Workspace，不另造第二套编辑器：

- 顶部显示当前编辑态数据包、`ModId + VersionId`、来源普通态和保存 / 诊断状态；
- 内容浏览器负责查看普通态和编辑态包内各内容类型，编辑页负责当前编辑态数据包；
- 关闭工作区保留编辑态，重新打开直接回到上次编辑页面和选中条目；
- “导出 / 保存为压缩包”是编辑态数据包级动作，不放在普通态包库行内；
- 编辑态数据包在包库中明确标记为副本，不伪装成第二个已安装普通包，避免用户误以为已经完成导入或替换。

### 首次编辑与切换文案

首次进入：

> 已从「<数据包名>」创建编辑态数据包。普通态原包不会被修改；当前编辑态也不会自动启用。

切换保护：

> 「<当前包名>」的编辑态数据包还有未保存输入。请选择：保存编辑态 / 保存为压缩包并切换 / 放弃当前输入并切换。已保存的编辑态数据包不会因切换而被删除。

恢复提示：

> 已恢复「<数据包名>」的编辑态数据包。它尚未应用到当前游戏，也没有覆盖普通态原包。

## 用户主流程

```text
打开包库
  → 查看任意数据包
  → 点击“编辑此包”
  → 将普通态复制为编辑态数据包
  → 编辑全部内容 / 保存编辑态 / 应用预览
  → 可保存为普通压缩包
  → 继续编辑，或结束 Runtime Session 回到包库
```

切换流程：

```text
浏览其他包
  → 点击“编辑此包”
  → 当前编辑态数据包是否有未保存输入？
      ├─ 否：保存当前上下文并选择 / 创建目标 packRecordId
      └─ 是：保存草稿 / 保存后切换 / 放弃当前输入后切换
```

| --- | --- | --- |
| US-1 | 选择内置包切换为编辑态 | 立即创建独立编辑态数据包；普通态内置包仍不可被覆盖。 |
| US-2 | 选择未启用普通态包编辑 | 可以复制为编辑态；普通态仍未启用，页面明确说明编辑不等于启用。 |
| US-3 | 编辑一个已启用包 | 原包和当前运行内容保持不变，除非用户明确执行预览 / 应用。 |
| US-4 | 先查看 A，再编辑 B | 查看 A 不清除 B 的编辑态数据包；Catalog 可保留多份，Runtime Overlay 活动标记始终只有一个。 |
| US-5 | 有未保存修改时编辑另一个包 | 阻断切换，提供继续、保存后切换、放弃后切换；不会静默丢稿。 |
| US-6 | 刷新或重启后重新打开编辑器 | 恢复 Catalog、当前 `packRecordId`、页面和条目，并提示尚未应用。 |
| US-7 | 编辑态来源普通态包被删除 | 编辑态数据包不被静默删除；显示来源失联，允许继续处理或明确删除。 |
| US-8 | 编辑态数据包包含任意内容字段 | 所有内容字段都可编辑、保存和导出，不存在隐含只读字段。 |
| US-9 | 保存为压缩包成功 | 生成普通态数据包文件；当前编辑态数据包保留，不自动替换、启用或删除普通态原包。 |

## 明确不做

- 不实现或重写外部“编辑态数据包 → 一般压缩包”服务；只定义调用位置、切换前置条件和反馈语义。
- 不实现多个 Runtime Overlay 同时运行；可以保存多份编辑态数据包，但不做多标签、多窗口的并行 Runtime 会话。
- 不直接修改 `PackManager` 中的普通态原包，不自动替换同 `ModId + VersionId` 包，不自动加入启用集。
- 不把所有数据包可进入编辑误写成所有表、所有字段都已支持编辑。
- 不在本 Task 恢复 `tools/datapack-editor/` 为游戏内入口。
- 不把编辑态写入玩家存档，不新增存档迁移或版本兼容层。
- 不设计压缩包文件格式、原始分片无损回写、图片资产或通用归档 writer。
- 不把内容编辑与玩家当前资源、剧情、角色、好感和世界线进度绑定。

## 当前事实与代码落点

- 包库和启用集由 `src/data-services/datapack/pack-manager.ts` 编排，`StoredPack` 同时承载内置、导入、版本和图片等来源信息。
- Runtime Editor 当前仍维护一个编辑态槽，主要状态在 `src/ui/runtime-editor/state.ts`，操作与切换在 `src/ui/runtime-editor/actions.ts`，展示在 `src/ui/runtime-editor/view.ts`；本 Task 规划将其改为数据包 Catalog 当前选择与 Runtime Session / Overlay。

- Registry 仍是运行时只读编译态；任何预览应用必须沿现有 Runtime Coordinator / Registry 受控边界进行，不能从 UI 直接改 Registry。
