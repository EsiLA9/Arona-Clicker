# G04：可复现场景与受控推进

## 对最终目标的贡献

让 Agent 能在隔离的非浏览器场景中快速建立必要前置条件、执行一组操作并重复验证状态结果，避免靠真实玩家状态或手工等待来重现逻辑问题。DOM/theme 转场场景暂缓到 G02 恢复后。

## 完成定义

- [ ] 场景指定代码/内容版本或摘要、fixture、初始状态、命令步骤、clock/RNG 控制、预期结果和上限；使用隔离存储与运行实例。
- [ ] 能 reset fixture、执行受支持业务命令、推进指定 tick/时间，取得每步结果与前后切片；命令写入沿既有服务和 StateMutationService。
- [ ] 明确逻辑 tick、事件队列和受控时钟的完成边界；不用一段固定 sleep 代替完成信号，超时必须留证据。
- [ ] 同输入与 seed 重复三次，规范化逻辑结果和断言一致；时间戳/运行 ID 等允许变动字段单列，不能剔除关键业务差异来制造一致。
- [ ] 正向与拒绝路径成对验证；费用不足、过期 revision 等失败不留下业务状态、统计、事件的部分提交。
- [ ] 保留最短已知失败步骤、相关fixture与差异；报告未控制随机源或外部依赖时，标记 nondeterministic 并拒绝“确定性重放”结论。
- [ ] 场景退出释放 timer、订阅和隔离存储，连续运行不会污染下一例或真实玩家环境。

## 依赖与边界

- 前置 Goal：G01；作为 G03 的受控验收基础。首期复用 Node fixture、fake timers 和已有 RNG 注入点，不接入浏览器或 DOM。
- 暂停自动 tick 不等于暂停所有 timer；手动 tick 不等于模拟经过一秒的完整浏览器流程，场景必须明确其测试层级。
- reset/step 是命令能力，不混入只读查询。fixture 构造限定测试装配；运行中不能直接赋值 PlayerState 绕开事件失效链。
- 本阶段暂缓：任意真实存档的一键回放、生产环境暂停/倒带、全系统随机源改造、自动故障最小化搜索器。

## 会改变方案的未知项

- 产品/架构待裁定：场景格式、受支持命令白名单、离线补算与 UI动画的时钟语义。
- 本地源码待核对：SessionService 的 Date.now、剧情/掉落等随机源、IndexedDB/LocalStorage隔离、Runtime重建后订阅清理。
- 初期选择确定性已可控的两个逻辑场景：生产、拒绝交易；UI局部更新和 theme 转场待 G02 恢复后另行验收。抽卡只有在相关随机源全部受控时才进入确定性声明。
