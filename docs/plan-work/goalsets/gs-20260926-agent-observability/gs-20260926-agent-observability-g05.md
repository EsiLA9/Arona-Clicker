# G05：验证证据与 Agent 交接

## 对最终目标的贡献

让一次开发验证产出既能自动判定、又能由另一个 Agent 或人复核的证据包；真实浏览器验收不再只留一句“看起来正常”。

## 完成定义

- [ ] 提供稳定命令入口：发现能力、运行指定场景/测试、读取摘要、按失败点展开证据；不要求 Agent 每轮编写新的浏览器控制脚本。
- [ ] 记录本次实际命令、退出码、测试名、环境、开始/结束时间和 pass/fail/skipped/blocked；未运行不计入通过，历史报告不得被误作本次结果。
- [ ] 失败包包含首个失败步骤、expected/actual、最小相关 state/UI 差异、日志片段及完整产物位置；stdout 保持有界摘要，详情按需读取，并链接 G01/G03/G04 的状态切片。
- [ ] G02 恢复后追加真实浏览器验收：固定视口、theme 与内容，检查字体/图片就绪、console/page errors、最终 DOM/theme 切片；需要视觉结论时附截图和人工复核状态。
- [ ] 视觉差异有容差、动态区域说明和人工复核状态；不得自动重写基线消除失败。逻辑、DOM/assertion、视觉与性能结论分开输出。
- [ ] 首期至少覆盖生产、拒绝提交；G02 恢复后再覆盖 stale surface、焦点/滚动/hover 连续性与主题转场。快测可按目标选择，机制准出仍执行项目规定的全量检查。
- [ ] 两个独立 Luna 接收相同失败摘要与最小 Read Set，均能定位同一失败断言和证据层；不要求重读无关全仓源码，耗时/输出量实测记录。
- [ ] 产物有隔离目录、manifest、保留策略；性能报告注明环境、数据规模、样本数和统计方法，不以静态调用数充当耗时。

## 依赖与边界

- 前置 Goal：G03/G04 对应的逻辑场景用于首期证据包；G02 仅为浏览器/DOM/theme 验收部分的前置，不阻塞非浏览器证据交付。
- 复用 Vitest 机器结果、现有类型/架构/文档检查；浏览器 runner 与 CLI 适配不复制查询或断言语义。
- Luna 的 Patch Unit 仍需 Allowed Files、Read Set、非目标、停止条件和 Receipt；证据包补充证据，不替代施工纪律或源码核实。
- 本阶段暂缓：自动提交/发布、自动修复、全量截图平台、未测量的性能硬门槛、把全部测试装入每次快速反馈。

## 会改变方案的未知项

- 产品/架构待裁定：本地与CI共用的浏览器方案、基线审批方式、产物保留期限及运行成本上限。
- 本地源码待核对：happy-dom依赖安装状态、首批测试是否可重复通过、浏览器资产与字体的离线稳定性。
- 首期性能先建对照基线，后续根据数据裁定阈值；截图本身不自动成为视觉通过结论。
