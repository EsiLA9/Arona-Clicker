## Constraints
- `validateCursors` 不清理、恢复、发事件、应用奖励或修改 PlayerState。
- `restoreCursors` 必须先完成完整集合预检，再清理旧游标并实际还原。
- 保持 save v2 无旧格式解释；本 Unit 明确增加必需的 `lastChoiceStoryId` 新字段；不处理 GameInstance/runtime-save 的调用顺序。
- 按 `docs/ai/PROJECT-CONSTITUTION.md` §施工纪律与停止条件执行。

## Explicit Non-goals
- 不修改 `runtime-game-instance.ts` 或 `runtime-save.ts`；上游负责在写状态前调用公开预检 API。
- 不修改 StoryNodePlayer 或 PresentationHost。
- 不添加旧 save migration 或修改新的 save 字段。
- `lastChoiceStoryId` 是新 cursor schema 的必需字段，不解释缺字段的旧 checkpoint；Choice 元数据必须与 visited 文档和候选索引相符。

## Stop Conditions
使用 `docs/ai/PROJECT-CONSTITUTION.md` §停止条件的六项默认条件。

## Completion Criteria
- [x] `validateCursors(collection)` 预检全局与所有 variant owner、Entry、node checkpoint、session metadata 与 presentation snapshot，且没有副作用。
- [x] `restoreCursors(collection)` 在清理旧 Session 前完整运行预检。
- [x] cursor 保存/恢复保留 `lastChoiceStoryId`，并拒绝来源不属于 visited Story 或索引不匹配的 Choice 元数据。
- [x] 存档集成测试继续验证双 owner 与重复 load；预检测试证明无效集合不移除当前会话，恢复测试覆盖根 Choice → insert 子 Story → 存档恢复 → 返回根完成并保留 choiceIndex。
- [x] 类型与定向恢复测试通过，Receipt 记录结果。
