# Unit 0322-U23：为活动 StoryNode 恢复保存表现快照

## Goal

让 StoryNode 活动运行的保存快照保留只属于该 run 的临时主题、story 生命周期实体表现和 Overlay；恢复时用服务分配的新 `runId` 只重建这些表现，不重放 Operation、奖励或入口请求。

## Constraints

- 快照类型置于 `src/engine/contracts/story-presentation-snapshot.ts`，只含 `ephemeralTheme?`、`entities[]`、`overlays[]` 三类受限表现数据。
- `StoryPresentationPort.save(source)` 纯返回当前 run 的表现快照，不执行事件或写入状态。
- `restore(source,snapshot)` 只设置新 run 的临时主题和 story 实体覆盖，并重新发布该 run 的 Overlay 显示事件；不得重放 StoryAction、状态资源、旅行、EntryRequest、奖励或 openingTitle。
- 保存只保留 `scope=ephemeral` 主题；area/student 主题槽已属于持久玩家状态，不在表现快照重复写入。
- entities 只保存 `lifetime='story'`，以 `target + author owner` 精确识别；manual/area/init 继续使用已有政策。
- Overlay 以来源 run 和 Overlay `id` 跟踪；show 添加或替换，clearId 删除一个，clearAllTexts / clearFlow 清空当前来源已有 Overlay。
- 表现快照不含旧 `runId`；服务恢复活动运行时分配新 `runId` 并将其传给 Host。
- openingTitle 是瞬时横幅，不纳入恢复快照。

## Explicit Non-goals

- 不重放或保存任何 StoryAction、随机值、状态效果、入口请求或奖励。
- 不保存/恢复旧标题横幅、Area/Student持久主题槽或 manual/area/init 实体表现覆盖。
- 不修改 Service 的运行游标合同；该字段由负责Service的Unit按本合同消费。
- 不修改 UI 消费者；它需按 owner、runId 与 Overlay id 识别恢复后重新发布的事件。

## Stop Conditions

若现有 Player 保存结构不能承载独立的 `StoryPresentationSnapshot`，或恢复服务无法为活动运行分配新的 `runId`，按 `docs/ai/PROJECT-CONSTITUTION` §停止条件上报并等待范围调整。

## Completion Criteria

- [ ] 表现快照类型闭合，不包含 `unknown` 或通用动作。
- [ ] 活动 run 的 ephemeral theme、story entity overrides、Overlay 可保存与恢复到新 runId。
- [ ] close 只清原 run；恢复后 run 可继续工作，旧 run 不能继续修改表现。
- [ ] openingTitle、资源动作、旅行与 EntryRequest 不会因恢复而重放。
- [ ] 定向行为测试、类型与架构检查通过。
