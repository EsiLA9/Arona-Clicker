# Unit 0322-U30：正式StoryDef节点契约与编辑Schema

## Goal

把正式 `StoryDef` 收敛到 `StoryNodeDocument` 的 `id/name/extra/nodes/stages` 原语结构；清除作者契约中的旧Talklet执行字段，并同步正式故事表的编辑器Schema与引用路径。

## Read Set / Context Budget

Task 0322 §10/§13/§14、U1 story-node与actions契约、`src/data-services/contracts/story.ts`、Registry引用扫描器、Schema生成器与 `editor-extras.ts`。目标20k token，历史默认不读；额外源码最多2个。

## Allowed Files

- `src/data-services/contracts/story.ts`
- `src/data-services/registry/runtime-content-reference-rules.ts`
- `scripts/gen-engine-schema.mjs`
- `tools/datapack-editor/schema/editor-extras.ts`
- `tools/datapack-editor/schema/engine-schema.sync.test.ts`（需要改测前先告知主Agent）
- 本Unit及对应Receipt

## Constraints / Explicit Non-goals

`StoryDef` 只继承节点文档形状；不得增加 `legacyTalklets`、旧/新联合、启动时转换或宽松回退。旧 `Talklet` 如暂留，只能是UI纯显示DTO；不含效果、条件、跳转、clickWork、入口卡执行等旧作者语义。StoryEntry身份和 `storyId` 引用保持现有ID域。Runtime/UI/save迁移、Base内容转换与旧StoryService由后续Unit/主Agent处理。

## Stop Conditions

仅改白名单文件；不编辑生成Schema、不加入Datapack兼容解析。Schema字段若需复杂通用JSON交互或编辑器UI超出本Unit，保留透明的 `hand/json` 元数据并报告，不扩展编辑器控件。旧内容造成的暂态类型错误等U32–U34完成后联合验证。

## Completion Criteria

正式契约不再接受 `talklets`；Stories Schema字段反映 `nodes/stages`；Registry对新节点与动作/条件/卡片目标采用新字段路径。Schema生成和同步测试通过，工作区最终 `tsc` 在内容切换后通过。

## Verification

`npm run gen:schema`、`npx vitest run tools/datapack-editor/schema/engine-schema.sync.test.ts`；全量tsc由U32–U34与主Agent联合收尾。Receipt如实记录中间依赖及实际检查。
