# Task：RuntimeEditor 条件树与原子条件弹窗

状态：closing — 🟡 条件树主体已落地，待浏览器体验验收

## 目标

将 runtimeEditor 当前的「条件组内直接平铺目标 / 键 / 比较 / 值」编辑方式，改造成可读的条件树编辑器：

1. 原子条件在条件树中只显示转义后的摘要文本与删除操作；点击摘要文本后进入原子条件编辑弹窗。
2. 组合条件通过 `AND / OR` 点击切换；每个组合节点都可以新增原子条件或子组合条件。
3. 使用缩进与树形层级表达条件之间的关系，降低嵌套条件的阅读与编辑成本。
4. 保留现有引擎 `Condition` / `ConditionGroup` 数据结构，优先只改变编辑器交互层。

### 追加需求（2026-09-16）

5. 编辑器最外层采用 OR 语义：若最外层存在多个条件组，则统一包装为一个 OR 组；只有一个最外层条件组时直接使用它，不再额外包装。
6. 新增叶原子条件时直接插入一个默认 `True` 条件，不自动打开原子条件编辑弹窗。
7. 叶原子条件的展示态需要统一对齐目标、摘要文本与删除操作的布局，保证不同文本长度和不同嵌套层级下仍然稳定可读。

## 设计边界

- 本 Task 只处理 runtimeEditor 的条件编辑体验，不修改引擎条件求值语义。
- 不把“揭示-条件”的运行时展示逻辑、条件结果诊断或 Tooltip 展示混入本 Task；它们另行规划。
- 条件树的持久化仍使用现有 `Condition | ConditionGroup` 结构，不新增存档迁移或兼容层。
- 父级条件树只负责层级、摘要与增删；原子条件的详细字段只在原子条件弹窗中编辑。
- 组合节点本身不携带条件值，只携带 `AND / OR` 与子节点列表。
- 编辑器根容器与普通组合节点分离：根容器负责最外层 OR 归一化，普通组合节点才允许在 AND / OR 间切换。
- 继续沿用编辑器有限递归策略，不做无限递归 DSL IDE：单组条数与嵌套深度仍由统一校验层限制。
- UI 继续只改 Draft；条件弹窗保存不直接 Apply 到 Runtime。

## 当前事实与代码落点

### 当前结构

- 条件编辑器位于 `src/ui/runtime-editor/dsl-editors.ts`。
- 功能、等级升级、揭示条目在 `src/ui/runtime-editor/collection-prototypes.ts` 中挂载条件入口。
- 条件交互事件由 `src/ui/runtime-editor/actions.ts` 统一接线。
- 当前条件编辑器直接在条目子弹窗中展开完整条件表单；每条条件同时显示目标、键、比较符和值。
- 当前条件组支持 `AND / OR`、新增原子条件、新增嵌套条件组、删除条件项。
- 当前条件组根节点与嵌套组都使用同一个递归渲染器。

### 当前校验与编码

- 条件结构校验位于 `src/data-services/authoring/content-policy-dsl.ts` 的 `validateConditionGroup`。
- 当前上限为：单组最多 8 个直接子项，最大嵌套深度 4 层。
- 当前支持 17 种 `ConditionTarget`，其中 `alwaysTrue` 用于编辑器新建叶条件的稳定默认值；其余目标仍统一渲染为文本 `key` 与数字 `value`。
- 当前支持的比较符为 `==`、`!=`、`>=`、`<=`、`>`、`<`。
- 功能、等级升级和揭示的条件最终都由既有 DSL 编码逻辑写回 Datapack Def。

### 当前已知缺口

- 原子条件的详细编辑表单与条件树混在同一层，阅读成本高。
- 条件组的 AND/OR 目前是下拉框，不适合快速查看和切换。
- 嵌套关系主要依靠容器结构，缺少稳定的缩进 / 树形视觉表达。
- 原子条件按 `ConditionTarget` 选择专用字段的扩展已拆入并由 [[task-0078-runtime-editor-condition-target-editors]] 承接；本 Task 只保留条件树与弹窗宿主边界。
- 当前“展开后清空已有条件”的读回逻辑存在 fallback 风险，需要在新树读回协议中一并修正：明确区分“未打开编辑”与“已打开并清空”。
- 已增加显式 `alwaysTrue` 条件目标，由引擎稳定求值为 `true`，且不产生运行时状态依赖；编辑器新增叶条件直接使用该结构。

## 目标交互模型

### 条件树

```text
AND
├─ 资源数量 ≥ 100                         [删除]
├─ OR
│  ├─ 拥有强化：某强化                      [删除]
│  └─ 完成过剧情：某剧情                    [删除]
└─ 当前所在区域 = 主厅                     [删除]
```

每个组合节点包含：

- `AND / OR` 点击切换控件；
- 子节点列表；
- 「添加原子条件」；
- 「添加条件组」。

根容器额外遵循 OR 归一化规则：

- 0 个节点：表示无条件；
- 1 个最外层条件组：直接使用该组；
- 2 个及以上最外层条件组：生成一个 `OR` 包装组；
- 根容器不提供普通 AND / OR 切换，避免用户误把最外层语义改成 AND。

每个原子节点包含：

- 由当前结构生成的可读摘要文本；
- 删除按钮；
- 点击摘要文本打开原子条件编辑弹窗。

新增原子条件时，直接插入一个展示为 `True` 的默认叶条件，不自动打开编辑弹窗。用户之后点击该 `True` 文本，才进入原子条件编辑弹窗。

这里的 `True` 由显式 `alwaysTrue` 原子节点表示；它由引擎稳定求值为 `true`，不会依赖资源、标记或区域状态。

### 原子条件弹窗

第一阶段可继续复用现有字段：

- 目标；
- 键；
- 比较符；
- 值。

但弹窗内部应预留按目标类型分派字段的接口：

```text
ConditionEditorRegistry
  target → render / read / summary / validate
```

后续可逐步将 `resource`、`area`、`hasEnh`、`hasTag`、剧情引用等目标改成 Registry 引用选择器或专用输入框，而不再让所有目标共用文本键与数字值。

## 施工切片

### P0：条件树数据投影与读回协议

- 定义编辑器内部的树节点投影，或提供不改变引擎类型的纯函数适配层。
- 支持 `Condition` 与 `ConditionGroup` 双向转换。
- 明确空组、空条件、已打开并清空三种状态的区别。
- 增加根容器的 OR 归一化与反归一化规则：单组不包装，多组包装 OR。
- 默认 `True` 使用 `alwaysTrue` 结构化表示，不依赖运行时状态，也不使用普通条件伪造。
- 保留最大深度与单组条数限制。

### P1：组合节点树形 UI

- 将 `AND / OR` 改为点击切换控件。
- 每个组合节点支持新增原子条件和新增子组合条件。
- 根容器固定采用 OR 语义；普通子组合节点继续支持 AND / OR 点击切换。
- 使用缩进、连接线或等价视觉结构表达父子关系。
- 删除节点时不影响同级其他节点。

### P2：原子条件弹窗

- 条件树内只保留摘要文本与删除操作。
- 点击摘要文本打开原子条件编辑弹窗。
- 新增原子条件直接生成默认 `True` 展示，不自动进入编辑弹窗；点击 `True` 文本后才进入编辑。
- 保存后更新父级摘要；取消不改变 Draft。
- 摘要文本必须经过 HTML 转义，不能把用户输入作为 HTML 注入。

### P2.1：叶条件展示布局

- 叶条件行固定为「目标 / 摘要文本 / 删除」的稳定三段布局。
- 目标或类型标记使用固定宽度或可控最小宽度，摘要文本占据可伸缩区域，删除操作保持在行末。
- 摘要过长时允许截断或换行，但不能推动删除按钮脱离叶条件行。
- 嵌套缩进只作用于整行容器，不分别作用于行内字段，避免同一层的元素出现错位。

### P3：目标类型输入扩展点

- 已拆分至 [[task-0078-runtime-editor-condition-target-editors]]，本 Task 不再重复承载目标编辑器注册表施工。

## 测试与验收

### 结构与读回

- `AND` / `OR` 根组和嵌套组可以稳定 round-trip。
- 根层一个条件组不额外包 OR，多个条件组自动包成 OR，读回后语义保持一致。
- 原子条件可以新增、编辑、删除。
- 新增叶条件立即显示 `True`，不会自动打开编辑弹窗；点击 `True` 后才打开。
- 默认 `True` 条件的持久化表示不会受资源、标记、区域等运行时状态影响。
- 已有条件全部删除后，保存结果确实为无条件，而不是恢复旧值。
- 空组不会被错误编码为带空条件项的条件组。
- 4 层嵌套和单组 8 项边界与现有校验一致；超限时不能继续新增。

### UI 行为

- 条件树外层不显示原子条件的完整输入表格。
- 点击原子条件摘要才打开编辑弹窗。
- AND/OR 点击切换后立即反映在界面与读回结果中。
- 新增原子条件和新增条件组都发生在被点击的组合节点下。
- 不同嵌套层级具有可辨识的缩进关系。
- 叶条件的目标标记、摘要文本与删除按钮在不同长度和嵌套层级下保持对齐。
- 用户输入的键和值在摘要中被安全转义。

### 回归范围

- 功能条件回归。
- 等级升级条件回归。
- 揭示条件回归。
- 现有 `validateConditionGroup` 与 Datapack 编码测试回归。
- 不修改引擎条件求值测试的语义断言。
