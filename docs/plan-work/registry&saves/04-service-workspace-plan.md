# 数据包与存档服务工作区计划

> 本文规划顶部栏、数据包管理、存档管理与游戏主界面之间的交互关系。
> Registry、PackManager、存档 DTO 与残留数据的机制定义仍分别以 ADR-0004、`01-registry-plan`、`02-save-plan` 为准；本文只规定 UI 信息架构、服务边界和操作流程。
> [[docs/plan-work/active/roadmap-0018-ui-host-registry]] 的 H0–H2 已完成首版；服务面板施工时应直接声明 Host，不再新增专用主题转接服务。
> 完整的存档、数据包、图鉴与统计目标交互见 [[docs/plan-work/active/roadmap-0020-service-workspaces]]。
> 包库必须把 `base@1.0.0` 作为内置数据包展示：始终启用、不可删除，但与外部包一样参与启用集、Registry 环境和来源统计。

## 1. 目标

将顶部栏从“立即执行操作的按钮组”改为“服务工作区导航”。

用户点击顶部入口后，左、中、右三栏切换为对应的服务面板；导入、启用、应用、读取、新游戏、删除和清除残留等高影响操作，都在服务面板中完成，并展示影响范围后再确认。

目标如下：

1. 降低误触导入 Mod、读取存档和开始新游戏的风险。
2. 让数据包启用集和存档状态变成可检查、可解释的对象。
3. 让数据包变更采用“编辑草案 → 校验 → 应用”的事务流程。
4. 在不违反只读 UI 与单一写入口纪律的前提下，复用现有 Runtime 命令接口。
5. 为未来的残留存档检查、来源管理和包版本选择预留统一容器。

## 2. 顶部栏定位

顶部栏只负责工作区导航和轻量状态展示，不直接执行高影响动作。

建议入口：

```text
游戏   数据包   存档   外观/设置   帮助
```

原有的“导入 Mod、数据包库、新游戏、保存、读取”改为服务工作区内的子功能。

顶部栏可以显示摘要状态，例如：

```text
数据包 3 个启用     存档 已保存
```

但点击摘要只进入工作区，不触发导入、保存、读取、重载或清档。

## 3. 统一三栏工作区

所有服务工作区采用相同的三栏语义：

```text
左栏：导航与对象列表
中栏：当前服务的主要内容
右栏：详情、影响、错误、日志与确认操作
```

### 3.1 左栏

用于选择子功能或对象，不承担最终提交操作。

### 3.2 中栏

用于浏览和编辑当前对象。编辑优先修改 UI 草案，不立即改变正式运行时状态。

### 3.3 右栏

用于解释当前选择的后果，尤其展示依赖、冲突、存档风险和待提交变更。

### 3.4 工作区切换规则

- 切换工作区不结束当前游戏会话。
- 未应用的服务草案必须提示“保留、放弃或返回编辑”。
- 数据包应用成功后按运行时要求刷新 Registry、图片索引和 UI。
- 存档读取成功后回到游戏工作区。
- 服务工作区不得直接持有 PlayerState 写引用；写入仍通过 Runtime / StateMutationService 等既有入口完成。

## 4. 数据包工作区

数据包工作区是包库、启用集和导入流程的统一入口。

### 4.1 左栏：数据包库导航

建议分组：

```text
全部数据包
├─ 已启用
├─ 未启用
├─ 有问题
└─ 同 modName 的其他版本
```

列表项显示名称、版本、`modName`、启用状态和问题徽标。

### 4.2 中栏：启用集编辑器

提供：

- 启用或停用数据包；
- 拖拽或按钮调整加载顺序；
- 在同一 `modName` 的多个包版本中选择一个；
- 查看当前启用集与待应用启用集；
- 放弃草案；
- 校验并应用草案。

启用集变更采用以下流程：

```text
当前正式配置
      ↓ 编辑
待应用配置
      ↓ Registry dry-run
校验成功 → 提交并 reload
校验失败 → 保持旧配置和旧运行时
```

不能在用户仅切换一个开关或移动一项时直接重载游戏。

### 4.3 右栏：数据包详情与影响预览

选中数据包时显示：

- manifest 信息；
- 来源类型、导入时间和内容哈希；
- 依赖及其状态；
- 同 `modName` 的其他版本；
- 包内实体统计；
- 解析警告和错误。

编辑启用集时显示：

- `modName` 冲突；
- 悬空引用；
- Tag parent 或 TagRef 问题；
- 图片资源变化；
- 可能变成存档残留的实体；
- 是否需要重新开始当前会话。

### 4.4 导入子页面

“导入 Mod”不再点击即弹出文件选择器，而是在数据包工作区中提供导入页面。

第一阶段支持 ZIP；后续扩展文件夹和单文件 Source。流程为：

```text
选择来源 → 解析预览 → 查看报告 → 确认加入包库 → 决定是否启用
```

导入预览必须显示：

- manifest；
- JSON 数量；
- 图片数量；
- 被忽略文件；
- 解析错误及路径；
- `modName`、版本和内容哈希；
- 与现有包的同名或同版本关系。

导入不自动替换当前运行内容，不自动启用冲突包，也不自动删除旧存档。

### 4.5 包库操作

需要提供：

- 导入；
- 查看详情；
- 启用 / 停用；
- 调整顺序；
- 删除包；
- 查看应用历史或最近一次失败原因。

删除包前必须检查：

- 是否正在启用；
- 是否被其他包依赖；
- 当前存档是否含有该包产生的残留数据。

删除动作必须明确确认；停用不等于删除。

## 5. 存档工作区

存档工作区统一承载保存、读取、新游戏、导入导出和残留检查。

### 5.1 左栏：存档列表

每个存档显示：

- 名称；
- 创建时间；
- 最近保存时间；
- 存档所在数据包环境；
- 是否存在残留数据；
- 是否可以在当前启用集下读取。

### 5.2 中栏：存档操作

提供：

- 保存当前进度；
- 读取选中存档；
- 新建世界线；
- 复制存档；
- 删除存档；
- 导入 / 导出存档。

保存应显示当前进度摘要与目标位置；读取应先展示存档和当前启用集的差异；新游戏应先展示将被重置的内容。

### 5.3 右栏：兼容性与风险

读取或改变数据包启用集时显示：

- 缺失的 `modName`；
- 未启用包产生的残留实体；
- 当前 Registry 找不到的 ID；
- 可通过重新启用数据包恢复的内容；
- 清除残留后不可恢复的内容。

存档系统遵守“惰性保留”：Registry 查不到的实体暂不加载进运行时，但原始数据保留在存档中。只有用户在存档检查界面明确确认后，才允许按 mod 清除残留。

## 6. 危险操作与确认策略

以下操作必须在服务面板中二次确认：

- 应用数据包启用集；
- 读取并替换当前进度；
- 开始新游戏；
- 删除数据包；
- 删除存档；
- 清除存档残留。

确认面板必须说明“会改变什么、是否可恢复、失败时如何处理”。

建议按钮层级：

```text
普通：查看、筛选、返回
主要：校验、保存、应用
危险：删除、清除、开始新游戏
```

## 7. 服务层边界

```text
UI 工作区
  ↓ 只读快照 + 命令
Runtime / PackCatalogService / SaveService
  ↓
PackManager、Registry、SaveLoader、StateMutationService
```

职责划分：

| 层 | 负责内容 |
| --- | --- |
| 服务工作区 UI | 导航、草案、影响预览、确认和错误展示 |
| 数据包服务 | 导入、包库目录、启用集、排序、持久化和应用协调 |
| Registry | 对候选启用集做合并、索引和引用校验 |
| 存档服务 | DTO 读写、活跃视图、残留报告和按 mod 清除 |
| 游戏运行时 | 接收通过校验的启用集，重建运行环境 |

UI 不直接组装 Registry，不直接修改 PlayerState，也不把数据包内容写入玩家存档。

## 8. 实施切片

### W0：工作区壳

- 顶部栏改为工作区导航；
- 实现游戏 / 数据包 / 存档三种布局模式；
- 建立统一左中右服务容器；
- 增加未提交变更拦截。

### W1：数据包工作区

- 将现有数据包库弹窗迁移为三栏页面；
- 包库详情、依赖、启停和排序；
- 导入预览页面；
- 启用集草案和统一应用按钮。

### W2：安全应用

- 接入 Registry dry-run；
- 应用失败保持旧 Registry 和旧启用集；
- 展示 Tag、引用、图片和 modName 冲突；
- 修复启动恢复包库后默认包覆盖的问题。

### W3：存档工作区

- 存档列表和详情；
- 保存、读取和新游戏确认流程；
- 数据包环境差异展示；
- 残留检查与按 mod 清除。

### W4：收束与验收

- 删除包和存档的依赖检查；
- 文件夹 / 单文件导入；
- 统一错误与操作日志；
- 补齐 UI、运行时和失败路径测试。

## 9. 验收标准

- 点击顶部数据包入口不会直接导入、重载或改变启用集。
- 点击顶部存档入口不会直接读取、覆盖或清除进度。
- 数据包启用集可以先编辑、再校验、最后应用。
- 候选启用集校验失败时，旧运行时完全保持不变。
- 导入数据包不会删除现有存档。
- 停用数据包不会自动删除其存档数据。
- 删除包和清除残留均有明确的影响说明和确认步骤。
- UI 只消费只读视图和命令接口，不持有引擎或 PlayerState 写引用。
- `npm test`、`npx tsc --noEmit` 与 `npm run check:architecture` 通过。
