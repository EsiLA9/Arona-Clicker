## 独立性与实施建议

- 建议未来新增独立目录 `prototypes/gameplay-b/`（拟新增），自带 package、配置、HTML 入口、源码、样本内容、测试和运行说明。采用普通 TypeScript + DOM/CSS，避免首版引入额外 UI 框架。
- 原型不得 import AC 的 Engine、StateMutationService、PlayerState、Registry、Datapack、Story、UI、CSS、内容或资源；不访问 AC 存档、浏览器存储键、服务或启动入口。三栏只是视觉参考。
- 原型内自行定义集中状态写入口与只读视图；同名概念不借用 AC 类型。内容使用本地静态配置，避免为样本先造数据包协议、编辑器或通用事件语言。
- 可以使用通用第三方开发工具，但应声明自身依赖，不能靠父目录 AC 的配置或安装目录才能工作。独立复制后安装、测试、构建、启动是最终硬验收。
- 建议独立包统一提供 `dev`、`test`、`typecheck`、`build` 四个命令；这些是未来要求，当前尚不存在。后文运行命令均指该独立包内。
- 不做存档/迁移、AC 集成、实时循环、自动战斗、编队、路线分支、手动选牌、经济或成长系统。seed、场景选择和重置只供测试/开发入口使用；玩家画面仍只有 Click 推进，刷新页面可重新开始一局。

## T03 — 可手算的确定性单场战斗

**前置**：T02 通过。Read Set 增加 Draft 0182 初始角色与首战、T01 的 AI/目标/HP 裁定。

**施工边界 / 交付**：四人对节点 5 的两名敌人；实现个人牌组、确定性优先 AI、前后排选目标、sCost、待机、伤害/护盾/恢复、同时结算和胜负平局。此技术样本暂不启用随机技能及配方，明确标记简化范围；开发样例可直接进入战斗。

**验收门槛**：进入即准备首轮，准备时支付一次；每 Click 只结算所见一轮，继续时自动准备下一轮。首轮无额外回复，后续与待机回复遵循裁定且不超过上限；每人最多一张普通牌。前排保护、无前排兜底、狙击例外、护盾取最大及轮末清除、同轮致命行动、胜/负/平局均有定向测试与手算对照。日志分开本轮结算和下轮准备，资源变化能逐笔对账。

**剩余**：这是基础战斗验证，不作为完整玩法平衡结论。
