# SolChat 讨论提示词

> 用于从简单需求获得完整终点和可实施的阶段图。发送前填写需求、相关 Draft 与已核实事实；SolChat 的输出仍是建议，由本项目裁定。

```text
请讨论以下玩法与数据结构需求。先定义完整的最终玩家/数据包作者体验，再规划到达它的阶段目标；不要只给最近一个版本。

需求：<需求>
本项目已裁定边界：<Draft / ADR 摘要或链接>
已核实的当前事实：<附源码依据；未知写“未知”>

请输出：
1. 最终目标：玩家能做什么、数据包作者能声明什么、运行时哪些事实必须持久化或可重建。
2. 阶段全图：列出到达最终目标的全部主要阶段、依赖与各自独立完成定义。只展开最近一个可施工阶段的细节；远期阶段保留终点，不因首期收窄而消失。
3. 对最近阶段，把问题分成“产品/架构待裁定”“本地源码待核对”“可直接施工”。仅当事实会改变方案或验收边界时安排核对。
4. 每次建议新增 Goal、Draft 或 Task 时，说明其独立验收结果；无法独立验收的内容留在原阶段。不要把事实核对自动变成新产品 Goal。
5. 给出本轮应写回同一 Draft 的建议、明确暂缓项，以及进入施工 Task 尚缺的证据。

请区分你的建议、本项目已有裁定和当前实现事实。不要假设尚未核对的代码能力已经存在。
```

收到结果后，本地 AI 先对照 Draft 的裁定记录，逐项标注采纳、修改或暂缓；不直接复制 SolChat 方案为当前系统事实。
