# 调查 / 施工 Task 模板

> 复制到 `docs/plan-work/task-<全局编号>-<主题>.md` 并登记 `00-index.md`。Task 可以是独立可验收的只读审计或实施；两者均须有完成定义。

```markdown
# Task：<独立可验收的结果>

状态：proposed — <当前进度>

## 目标

<本 Task 要交付什么，以及它覆盖最终方向的哪一部分；不依赖 Goal Set。>

## 设计边界

- 本 Task 包含：...
- 明确非目标：...
- 已裁定来源：<相关 Draft / ADR；建议本身不作权威>

## 当前事实与代码落点

| 已核实事实 | 源码/测试依据 | 对本 Task 的影响 |
| --- | --- | --- |
| ... | ... | ... |

## 施工切片

### P0：<独立步骤>

- ...

## 测试与验收

- [ ] <可执行、可观察的完成定义>

## 当前核验（YYYY-MM-DD）

- <实际执行结果；未执行写“未执行”及原因>

## GALHCG 影响闭环

- 发现路径：<关键查询词与命中 / 未命中；未知项如何继续定位>
- 变更审查：<review_changes 路径与分页结果>
- 地图维护：<Evidence / maps_to 更新及写后验证；未更新时说明无直接语义影响或缺少裁定>

## 剩余工作

- <本 Task 内未完成事项与最终方向仍缺的阶段，分开写>

## 相关路由

- <Draft、机制、Read Set>
```

只有完成定义独立成立时才拆新的 Task。施工 Task 再按 [[docs/ai/PROJECT-CONSTITUTION]] 拆 Patch Unit 并记录 Receipt。
