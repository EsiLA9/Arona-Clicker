# Execution Receipt 模板

> 用法：由 Luna 在每个 Unit 结束（完成或中断）后填写，供下一 Unit 或高层 AI Review 使用。
> Receipt 不是完成声明，也不能替代真实测试结果；与所属 Unit 同名。
> 存放位置：默认内联在所属 Task 文档中对应 Unit 之后；拆出 Unit 文件时放同目录 `receipts/`。

## 骨架

```markdown
# Receipt <task-id>-U<n>

| 项 | 内容 |
| --- | --- |
| 状态 | 完成 / 中断（中途停止时必填停止条件编号） |
| 实际修改 | <文件列表，标出新增 / 删除> |
| 未完成内容 | <本 Unit 内未做完的部分，写明原因> |
| 范围外变更 | 无（默认）；有则列出并说明授权来源 |

## 测试与验证结果

| 项 | 命令 / 方式 | 结果 | 备注 |
| --- | --- | --- | --- |
| 定向测试 | ... | 通过 / 失败 / 未执行 | ... |
| 类型检查 | ... | ... | ... |
| 人工验收 | ... | ... | ... |

## 遇到问题

- <阻塞、歧义、文档与源码不一致等；没有写“无”>

## 需上游确认项

- <需要高层 AI 补足事实、拆分 Unit 或建立 ADR 的问题；没有写“无”>

## 事实更新建议

- <本 Unit 核实到、但尚未写入权威文档的事实；没有写“无”>
```

## 填写要求

- 只记录事实：改了哪些文件、跑了什么命令、结果如何。
- 中断必须写明触发了哪条停止条件，以及已确认事实与缺失信息。
- 未执行的验证写“未执行”并说明原因，不得留空或写“应该通过”。
- 不把推测写成结论；需上游判断的内容放入“需上游确认项”。
