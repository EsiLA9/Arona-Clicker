# 05-conventions/doc-maintenance — 项目文档维护规则

> 本文回答：项目文档如何区分当前事实、协作协议和历史材料，并组织稳定路由与归档。

## 内容归属

| 分区 | 责任 |
| --- | --- |
| `00-INDEX.md` | 唯一总入口和高频任务路由 |
| `01-architecture/` | 跨模块职责、依赖、生命周期和数据流 |
| `02-modules/` | 与代码大模块对应的短卡片：职责、源码、测试、Wiki 路由 |
| `03-data-structures/` | 字段组织、生命周期归属和引用语义 |
| `04-mechanisms/` | 行为算法与运行流程，按 Engine、Data Services、AronaClicker 分组 |
| `05-conventions/` | 项目稳定开发与文档维护约定 |
| `06-wiki/` | 按 AC Outline 分层的功能关系页和跨模块协作地图 |
| `docs/ai/` | AI 协作协议、GALHCG 操作说明、Read Set、上下文包、提示词和模板；内部权威与路由见 [[docs/ai/00-index]] |

Wiki 页面解释文件和子系统如何协作；字段含义和机制细节由 03/04 的专门页面承担。`docs/ai/` 只约束协作和查阅流程，不另建机制事实源。相同内容只保留一个正文权威点，其余使用 WikiLink。

## 页面格式

- 文件标题采用 `# 分区/文件名 — 标题`，紧随一句“本文回答什么”。
- Wiki 页需标明主题职责、主要协作关系、源码入口、适用测试与深入阅读链接。
- 关系图需区分静态 import、运行时调用、数据流和事件协作。
- 用中文解释，保留代码/API 英文名；代码事实直接引用路径和符号。
- 新增功能页按稳定职责切分，不按源文件或临时任务逐篇建页。

## 链接和历史处理

- 新系统内使用全路径 WikiLink：`[[docs/docs-829/...]]`。
- 只有当整篇内容被源码核实的新页面完整替代时，才将旧文标记为“已被取代”；局部事实变化记录更正，不推断整页过时。
- `docs/docs-829/` 是唯一持续维护的系统。`docs/archive/docs-828-snapshot/` 只读保存旧版来源；`docs/docs-828/` 仅放兼容重定向，分别指向当前承接页和对应历史原文。不得在重定向路径恢复第二份机制正文。
- `docs/plan-work/archive/` 专用于计划历史；不要把当前机制正文移入计划归档。

## 静态核验

运行 `npm run check:docs` 检查新链接与文档结构。此命令不判断语义过期，因此事实更新仍要核对当前源码和测试。
