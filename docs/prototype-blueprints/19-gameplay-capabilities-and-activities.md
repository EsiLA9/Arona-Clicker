# 从现有实体设计探索、收藏和回访活动

[P4](05-gameplay-prototypes.md) 的五项试验继续用于核对机制。本页从玩家的一次选择、获得的知识和下一次行动出发，设计能持续进行的活动。下述活动和新增字段为候选。R8 可先用 Base、addition-test、area-achievement-demo 各自的实物验证，再在一个单独的试验世界线组合。所有实验可用 JSON。

## 实体已有的能力和缺口

| 实体 | 玩家做什么，如何触发 | 结果可以接到哪里 | 当前依据及待补能力 |
| --- | --- | --- | --- |
| Area | 读位置提示、尝试前往、重访。地图节点、剧情或交通可引导 | 实际到访、新地点行为、地区 Story | `InitService.travelToArea` 与到访事件已有。多项可调查对象和长期线索回看需要明确定义交互 |
| AreaMap | 打开、收录、切图。可由剧情奖励取得 | 空间知识、地图入口、条件允许时直达 | `AreaMapCommandService` 和 `acquireAreaMap` 已有，收藏与访问各自记录。历史图来源和不同阶段的标注需设计 |
| Spot | 到场选择设施功能、经营、购物或进入地图/行动 | 资源、地点服务、故事或路线入口 | `SpotFunctionalityDef` / `SpotFunctionalitySystem` 有现有功能种类。常驻资料检索或反复调查可能需要专用使用动作 |
| Item | 获取、持有、回收、消耗或支付。来自 Story、商店、掉落 | 交换、累计收藏、材料、可阅读线索 | `ItemService`、`ShopService.checkout` 和累计事实可用。现有 Item 三类可组合多玩法。通用持量门禁和带出处的资料回顾需补或验证 |
| Character | 会面和认识。由公开 Story 或资料引入 | 资料、关系前置、后续邀请 | Story 可写已读/flag，`CharaProfileService` 有现行资料。没有通用 Character 知识 Reveal。需要资料分级与主动回访时补 |
| Variant | 招募、持有、培养。由卡池或奖励发放 | 角色功能、羁绊和表现 | `RosterSystem` 和真实差分入口。未持有对内容的影响按现有规则，人物认识与差分持有独立 |
| StoryEntry | 发现、接取、赴约。由事件、地区或资格产生 | 启动剧情、说明下次去哪里 | 有 active/passive、资格、后续与父子入口。有条件变化无唤醒的真实案例才扩监听或持久预约 |
| Story | 阅读、选择、回顾。经 Entry 或正文续接 | 局部选择、世界信息、玩家状态效果 | 已有 Story、Flag、Effect 及真实重读机制，回顾结构可显示关联线索 |
| Enhancement | 购买或作为调查奖励取得并使用能力 | 新设施、区域、路线或操作资格 | 现有 `hasEnh` 与授予。需体验上有去处和活用方式，避免只显示数字 |
| Milestone | 进度达成与后续开放。由收集、访问或剧情检查 | 任务完成事实、解锁或奖励 | `MilestoneAdapter` 先写完成再跑监听。必达能力优先直接由完成事实得出，确需独立奖励再设计可靠领取 |
| Achievement | 查看当前线索、完成反馈与回顾 | 指向下一项调查、显示曾完成 | area-achievement-demo 有进度与关联监听。单纯达成反馈可沿现状，引用具体知识来源需要另证 |
| PassivePool | 在合适地区、时间和状态遇到日常 | 自然补充人物与世界线索 | 有加权、冷却和预置候选。必要通关线索另有可靠入口，随机只调丰富度 |
| Affector / AffectorPack | 玩家获得强化或改变状态后体验数值或通路变化 | 生产、条件、交通网络 | AffectorEngine 挂载和自带领域行为已有。把网络解锁和“知道网络在哪”分别呈现 |

以下玩法是使用方式和内容配置。作品可以按地区特产、文献、凭证、礼物、纪念物、线索、材料和系列收藏安排体验，沿用 Item 现有类型。

| 物品用途 | 玩家怎样遇到、为什么继续 | 已有办法与待验证差距 |
| --- | --- | --- |
| 地区特产 | 玩家根据资料去三个地点，各自找到不同物品，有不同发现方式 | Item、到访、掉落、限定商店、累计获得。哪一份来自哪处用来源回顾 |
| 文献 | 取得后读其中一段，点同主题条目发现另一段和关联 Story | Item、Story、资料入口。需要取得后永久回查位置和正文时，补资料呈现 |
| 通行凭证 | 玩家学会出示和消耗的区别，拿到以后实际开通另一条路 | 已有 Enhancement 适合长期通行。对暂时持有的凭证做显式检查，支付使用正常物品消耗 |
| 礼物 | 玩家先接触人物，再根据会面了解送什么。赠送进入一段关系内容 | 复用对话、持有与好感相关效果。实际消耗、关系奖励与再次赠送要核对同次操作和回执 |
| 特殊纪念物 | 完成一次活动后能看到哪次、在哪里得到，可在以后阅读 | 已读/里程碑和背包显示可当起点。一次性取得或来源需服务实际提供 |
| 线索 | 拿到信号芯片，读出它指向的下一个站点，有可行动提示 | 使用现有 Item、地点 Reveal 和一条后续。消耗后仍要能获得提示 |
| 材料 | 选择留作交换或解锁设施，有机会重新收集 | 商店 price、材料消耗与设施效果。验证多种合法获得途径及失败不扣料 |
| 系列收藏 | 分散得到的物件拼出完整信息，最终打开新入口 | Item 组合、现有累计或完成事实，Achievement 显示缺哪项。重复同物不能补齐不同缺项 |

## 活动一 · 旧图上的第二条路线

开场。玩家初次到夏莱主厅，在一段可稳定进入的场景里得到“过去有另一条到天台的路线”的提示。提示有“问值班同学”和“查观测站旧记录”两个去处。两条各交付一项线索，任一先做都能回到活动说明。用肖像和路线条目表现新信息，玩家能看见自己在找什么。

在测试包中，资料先揭示地图节点的存在。与人物会面后再揭示名称或用途。旧图由正文动作授予并可在已收录地图中打开。发现旧门还需要实际通行，先用一个真实 `hasEnh` 条件和正常旅行行为。房间里的初次调查给一次可回顾资料。路线随后给玩家日常通行收益，例如到达距离更短或可从地图直达。当前机制不能表示的“走捷径”须先验证既有交通网络或 mapDirect 规则，而后明确一个新增动作。

失败与回访。地图已收录但未获通行时，点击显示当前合法的提示，不改变到访。玩家暂时离开可从活动提示再查知识。读档后图仍在本 Init、一次性资料不再重复发放。错误线索在同一路回查，未揭示区域不得由拒绝文案泄露。首个可验收结果是玩家决定一条顺序，自行找到另一项线索，最终用实际旅行抵达，回访能说出地图提供的行动能力。已有步骤在 P4 A 验证，额外资料回顾见下文缺口。

## 活动二 · 学生访谈与信号芯片

用 addition-test 实物先核对信号芯片的 Story 奖励和使用收益。组合活动安排在单一试验 Init。玩家可通过一个稳定邀约与白子初次会面，或从设施得到一条访谈提示。会面只开放一条人物资料与地点线索，不发 Variant。第二次可在地区商店或日常获取芯片。紧要信息还可通过固定的 Entry 接取，避开一直抽不到日常而卡住。使用芯片可播放短资料并指向第三处。以后获得另一枚仍可用于已有经济收益。如同时要“用芯片会永久打开某项活动”，先试既有条件和 Story 事实，再决定持量查看或消费操作。

玩家回到人物页，能按“在哪里认识、发现了什么、还可以问什么”选择一条独立回忆。未持有时培养仍不可用。招募后，角色页保留访谈线索，并开放正常差分操作。旧玩家持有时也能完成会面，不以持有量猜测已经认识的侧面。失败对照是零库存使用、重复使用、错过日常、未持有、读档与跨 Init。首个可验收结果是消耗最后一枚后，玩家仍能找出曾读线索并发起一个实际后续。

## 活动三 · 跨地区档案与调查设备

以 area-achievement-demo 的现有累计和 Reward 为技术基线。真实活动的三项不同档案各有一处线索与一种取得方式，一项首次调查、一项交易或交换、一项重访的剧情选择。进度页面告诉玩家缺哪一份及可去的地区。重复进同一个房间可获得通用材料，但不能补齐尚未取得的另一份档案。三项到齐打开一项可使用的调查设备，例如在原档案馆选择查阅，再从新 Entry 获得能找到旧路线的记录。一次性信用点和可访问能力分别验证。功能用不等于能领奖，玩家调用一次实际的设备或 Entry 才算完成路线。

失败与回访。买不起时可去另外两处，不丢已读内容。集齐后模拟奖励监听失败，必须能厘清“目标已完成”“奖已发/可重领”“能力可用”三样。先用已有可靠事实决定公开 Entry，确需领取时再补领取回执并阻止重复。换另一个 Init 时按数据实际归属显示。若产品选择跨线收藏，仍需验证旧 Init 获得的权限不越线打开新地点。读档和重载各跑一次。

## 哪些缺口值得扩建

| 想做的行为 | 首次实现和判断 | 缺口成立时的构造草案 |
| --- | --- | --- |
| 知道同一人物的多个侧面，并长期可查 | 用独立 Story 完成事实和角色资料页的只读显示。验证访谈互不覆盖、已读可追、查阅入口真实存在 | 为 Character 声明知识条目，用稳定条目键、可读内容引用与揭示条件。保存为已知条目键集合，当前决定前先用同 Init 样本测。投影只公开已知内容，对旧档无记录给安全缺省。D08 决定是否从已读补入及跨线范围 |
| 物品/文献曾获得后仍能说明来历和实际可用线索 | 用不同 ID 的累计获得、Story 已读和资料页关联验证。累计数字能支持进度但不用来猜具体出处 | 仅记取得时需展示的来源，候选字段为 Item 或资料键、来源种类和可回查 ID、取得 Init、首次/最近标识。写在成功取得或查阅提交后，独立于库存数量。查历史入口失败仍显示可用标题和未知来源 |
| 反复调查同地不同方向、由已知条目开下一项行动 | 用实际 Spot/Entry 对照。若要在同屏列独立目标且可重访，试现有条件、投放和局部交互的组合能否提供顺畅操作 | 地点可挂一个有 ID 的调查条目列表。各项有可见/可执行条件、提示、实际动作与首次/可重做策略。执行进入领域命令验证地点、版本和前置，成功才写该项完成并返回具体下一步。可用稳健失败回执或独立领取，存档持久层按 D08 |
| 出示、消耗和部分支付选择 | 优先使用真正的 Shop 交易或 Item 使用，并对照候选门禁。验证无库存、无资格、并发点击及不会双发 | 若无法表达，增加准确的持量条件，再给显式出示/消耗命令。需要消耗和发放同成败时用现有交易写入或领域内一次提交。显示持有、已知和已消耗三种不同玩家状态 |
| 必要内容在登录、条件改变或失败后仍可拿到 | 优先地区稳定入口与现有完成事实。故意清空随机池，模拟重载和授予错过 | 有永久失联时再加可恢复的一次性待投或待领取记录。键由任务和实际 scope 决定，记录 pending/claimed 或可从完成事实恢复。触发、重查、用掉、撤销和重复用例各有断言，D09 核对既有奖励兼容 |

R8 先独立验五个现有路径，保留实际配置和结果。后续活动验证记录玩家曾看见什么、选择缘由、失败后去哪、取得的资料是否持久、有没有使用新能力。若活动价值高而现有框架阻塞，可将知识、地点调查或可靠投放作为独立框架改造提案。要写清状态存放、兼容、入口、写入顺序和负例，之后另行授权。
