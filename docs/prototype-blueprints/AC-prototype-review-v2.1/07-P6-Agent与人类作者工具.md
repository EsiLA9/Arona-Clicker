# P6 Agent 与人类共同使用的作者工具

## 1. 不熟悉源码的使用者如何完成任务

A17 已定位现有 ai/guide、Context Packs、Schema 生成、Base export、测试和 Task 工具。它们是工程施工入口，不是作者项目操作入口。GALHCG 用于源码定位，不能充当游戏内容索引。我们真正希望一个只拿到玩家文本和项目目录的 Agent，不用理解全部引擎源码，也能查角色和引用、生成 DSL、得到具体错误、修正、构建和试播。

使用场景优先于协议设计。首轮推荐普通 Node CLI 加项目内可调用的 TS 函数；工作台调用同样的作者服务。暂不需要独立 Agent 服务端、常驻进程、细粒度权限平台或所有文本编辑先生成永久计划 ID。对于批量改名和删除等操作，提供预览与显式写入是合理需求；对于作者直接编辑文件，工具应当可以重新读取并检查，而不是禁止直接写文件。

## 2. 一次可执行的作者操作样例

以下命令形态都是候选，需由本地确定实际入口；其中 .story 仅是示意路径，不是已经裁定的扩展名。CLI 不应绑定某一版语法，解析、格式化、转换和帮助由当前语言实现提供。

```
ac project inspect ./my-pack
ac schema show Story
ac entity find --kind Character --query 白子
ac entity refs --kind Area --id <实际区域ID> --direction incoming
ac story check ./stories/invite.story
ac story to-json ./stories/invite.story --out ./tmp/invite.json
ac project check ./my-pack --json
ac project build ./my-pack --out ./dist/my-pack.zip
ac preview --entry <实际EntryID> --init <实际InitID> --fixture ./cases/invite.json
```

Agent 第一步获取项目格式、有效实体类型、语法版本和参考例子。第二步查真实角色、地点、已有 Story 和 Entry，避免凭空构造 ID。第三步在项目规定范围生成或修改文本，调用检查器。第四步处理错误：若角色别名歧义，返回真实候选或要求明确 ID；若转移目标不存在，指出对应文件和行；若输入语法不合法，显示具体错误及允许写法。第五步构建到指定临时输出目录；第六步调用隔离预览，根据操作脚本执行真实选择并查看结果。人类可走同样命令，也可从工作台点击相同诊断。

## 3. 最小命令能力及输出要求

项目查询显示当前根、识别文件、依赖、实际内容类型；Schema 查询返回字段、允许结构、引用目标及示例，不要求 Agent 阅读生成器；实体查询显示真实 ID、来源和完整定义或指定字段；引用查询支持正向和反向、精确与可能引用；文本检查输出语法/引用/领域诊断；格式转换和格式化默认显示结果或写明确指定的输出，不偷偷覆盖；项目构建返回是否产生可运行产物；预览返回实际状态变化和拒绝原因。拆分、合一、层级化调用 P1 统一转换器。

机器可读输出可以采用简单一致的 JSON。示意：

```json
{
  "ok": false,
  "phase": "reference",
  "diagnostics": [{
    "code": "REF_MISSING",
    "file": "stories/invite.story",
    "line": 8,
    "column": 3,
    "message": "指定地点不存在",
    "targetKind": "Area",
    "targetId": "example:area:missing",
    "hint": "查询项目中实际 Area ID 后替换"
  }]
}
```

字段名及退出码由共同协议确认。要区分用户数据不合法、文件冲突、无法读取和工具内部失败。JSON 模式标准输出只包含合法 JSON，进度放标准错误。信息可按实体/路径/字段缩小范围；只有真实大数据需求时加分页。所有命令说明包含输入、是否写文件、成功结果、失败结果、至少一个真实可复制示例。

## 4. 修改与写入的两条路径

普通文本创作：作者或 Agent 直接编辑授权项目文件，然后运行 check/build。工具发现外部变化后更新来源索引，旧诊断标注过期。工作台未保存草稿遇到外部修改时显示冲突，不覆盖。

结构化批量修改：例如改名一个 Area 并更新地图、Story 中的引用。工具先给出具体写入文件、旧值/新值、不能修改的只读引用和无法确定的动态引用。确认后再写；核对参与文件的当前内容，发生冲突则不继续。第一次原型可使用临时文件、备份和明确的失败报告；真正需要多文件恢复和重复提交时再实验持久计划/回执。不能因此建立所有普通创作必须经过的繁琐工具手续。

路径范围、显式输出和只读依赖是基本安全边界。作者工具不能任意修改正式游戏存档。Preview 只使用选定内容和隔离初始状态。是否需要权限细分、审计日志、长期会话、SDK 或常驻宿主，应由真实第二客户端或多人操作需求证明。

## 5. 文档本身也是工具的一部分

提供简短入口：项目格式、当前语言接入及检查工具的用法、与语言版本相符的合法例子、常见错误和修复、命令参数、Schema/实体查询、如何试播。正式语法尚未设计时，只提供临时前端测试说明；不得把它当成正式 DSL 快速开始。未来语言改版时应能单独更新说明、语言实现及测试，而不重写 CLI 与共同领域校验。更复杂的编译和事务设计放技术附录。Agent 任务文档应指向当前可运行命令，不把全部规则压成一个黑话 prompt。

验收让一个未参与设计的 Agent 仅凭作者说明和 CLI 完成：查询实际角色 → 新建一小段合法 Story 候选 → 故意制造一个引用错误 → 根据诊断自行修复 → 构建 → 隔离试播 → 人类工作台打开同一源。记录它实际需要额外读取哪些工程文件、失败次数及能否定位问题。工具能返回正确协议并不足够，必须证明真实使用者能够完成任务。
