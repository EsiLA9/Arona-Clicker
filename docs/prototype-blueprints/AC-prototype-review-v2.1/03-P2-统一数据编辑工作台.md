# P2 全量数据作者工作台

## 1. 目标不是新建一个通用表单

作者能够在同一项目内查看所有正式数据结构，修改任意受支持的实体、打开其引用对象、查找它被谁使用、直接进入复杂字段的详细编辑，保存到实际来源文件，检查并试播。全量覆盖是最终目标；首轮选择少量真实实体检验公共框架，不能把首轮的默认 Inspector 当作最终覆盖。

已有三个实际消费者：独立 Datapack Editor 的 EditorModel、Schema、字段编辑和导入导出；游戏内 Runtime Editor 的条件/Effect 编辑、领域写入及诊断；Story Editor 的节点正文、Reference Navi、Flag、试播和草稿。公共 EditorWorkbench、BrowseInstanceManager、EditorExplorerService 及 WorkspaceColumns 已经建设。审计 A04/A06–A10 有相关路径。先核对其实际调用链，不能依据历史 Task 完成状态假定所有交互成立。

## 2. 宿主与业务的关系

推荐目标是共享一个作者核心和一个公共工作台能力集合；独立应用和游戏内工具可有不同启动方式、主题和可用操作。研究是否将独立作者应用作为主要工作场所、游戏内保留运行浏览及试播入口，或让两者使用同一编辑工作台。两种方案必须用实际文件读取、浏览器权限、游戏运行态及现有 Story 写包流程比较。暂不承诺两套宿主都能访问本地任意路径；浏览器环境需明确由文件选择器、授权目录或本地服务提供能力。

公共宿主只负责：工作类型、独立 Explorer、实例条、布局、命令作用域、稳定栏位及刷新。业务 Provider 提供实体查询、内容/属性和专属操作。不得由 Story、World 或新领域分别构造完整工作台。保持既有契约：选择 Explorer 不切换活动实例；激活实例不改变搜索来源、查询、折叠、滚动；显式定位才允许临时显露；业务刷新不得替换另一 Explorer。目录管理是普通实例，不能再次变为必须退出的特殊模式。

## 3. 一次实际编辑过程

1. 作者打开项目，左侧选择“文件”或“实体”，按名称、ID、领域和来源过滤。打开一个 AreaMap，实例条增加地图标签。中间显示地图专用编辑器，右侧显示选中节点属性；左栏继续调查当前目录。
2. 点击节点引用的 Spot，打开 Spot 标签。地图实例保留选择、缩放和滚动。Spot 内容读取同一作者工作副本，不能因打开途径不同另生成一份独立实体数据。若第二个标签也打开同一 Spot，它共享未保存的实体修改，但保留各自视图选择。
3. 修改一项普通字段，立即更新当前控件、草稿标识及依赖这一字段的可见摘要。需要更新的引用索引和诊断与当前草稿版本对应；旧异步结果不得覆盖新内容。不会自动修改运行中的游戏。
4. 点击复杂进入条件摘要，打开详细条件编辑器，修改逻辑组和参数。确认后以一个完整操作替换当前条件；取消不改草稿。返回后保持原字段位置、焦点、滚动，不重建整个工作台。
5. 点击“引用关系”查看该 Spot 被哪些地图、Story、设施或其他实体引用。每一项显示来源、字段路径和关系类型，点击进入精确字段。对于动态选择器标记可能引用；不完整索引不能声称零引用。
6. 保存时展示影响的实际文件及可选 Diff，核对磁盘版本。源文件可以显式保存未完成内容；构建不允许严重错误。只读依赖可浏览与引用，不可原地编辑。冲突保留原草稿并比较基础、磁盘、草稿三个版本。
7. 检查和构建使用 P0；试播使用 P3/P0 的隔离服务；显式应用才进入 Runtime 准入。关闭某个实例不能错误删除另一个实例共用的草稿；关闭项目时再处理未保存修改。

## 4. 公共组件体系必须按实际角色设计

| 字段或任务 | 建议交互 | 必须复用的能力 |
|---|---|---|
| 名称、数值、布尔、简短描述 | 原位输入，非法值就地标记 | 字段读取、类型转换、修改命令、撤销 |
| 枚举与短列表 | 紧凑选择器 | Schema 候选与空值语义 |
| 角色、地点、物品、图片等引用 | 当前目标摘要，点击打开检索选择器；可查看目标 | 统一索引、筛选、跳转、候选有效性 |
| 条件组 | 逻辑摘要及编辑入口；点击进入详细弹窗 | 共享条件结构编辑，不压缩成一团输入框 |
| Effect/Operation 参数 | 类型与摘要，复杂内容独立编辑 | 类型合同、参数控件、验证与原子确认 |
| 有序集合、Story 节点 | 列表/专用编辑器，增删、排序、复制 | 稳定局部身份及修改历史 |
| 地图图形 | 专用地图编辑器、节点详情及关系 | 实体引用、诊断、草稿和保存 |
| 长文本/DSL | 专用沉浸编辑器或文本区域 | 来源映射、错误定位、预览和提交 |

条件编辑必须详细设计。先核对现有 Runtime Editor 条件树、原子条件弹窗、参数来源及现有嵌套上限。推荐弹窗左侧或主体显示 AND/OR/NOT 等实际受支持的组关系，原子项显示自然语言摘要，选择原子项进入其参数编辑；底部明确确认、取消、非法字段提示。删除组、调整顺序、改变条件类型时应保留或明确丢弃原参数。不能通过新组件悄悄减少已有条件表达能力。上限是否扩大、是否提供高级源码模式，作为单独实验，不强迫所有复杂表达用一层小控件承担。

Reference Picker 应统一：按目标类型过滤、搜索名称/ID、显示来源和必要缩略信息、明确空值、不可用/只读目标、点击查看引用。调用方提供期望类型、当前值及合法候选规则，不再各自编写候选搜索逻辑。返回资源身份而非 DOM 文本。引用导航不自动改左栏调查条件；显式定位另有命令。

## 5. 数据编辑模型与 Schema

现有独立 EditorModel 以 table/index/path 保存快照历史。未来实体在文件中移动或数组重排时，不能继续用旧数组下标定位长期编辑对象。可先用真实类型+ID+来源定位，必要时补稳定内部身份。共享作者工作副本持有可读写定义及未提交修改；UI 实例仅持有当前选择、视图状态及与工作副本的引用。修改采用明确的领域操作（设置字段、插入项、删除项、移动节点），一次弹窗确认构成一次可撤销操作。无需为所有细小编辑提前建设通用分布式事务。

Schema 不只是生成表单的字段列表。需要从现有 TS 合同、生成器、editor-extras 和领域验证器识别：字段类型、可选性、默认值、引用目标、复杂联合类型、作者说明及特殊编辑方式。候选路线是保留 TS 为结构来源、领域规则在统一注册入口声明、编辑元数据按领域拆分。另一方案为 Schema-first；比较 AreaMap、Condition、Effect、StoryEntry 的实际表达和新增字段流程。禁止同步维护两份独立结构定义。显示元数据不决定运行合法性。

全量覆盖清单由实际 Datapack 合同生成或核对：每个领域标注能浏览、能创建、能编辑、能删除、能查正反向引用、复杂字段有无专用组件。未知字段暂可源码编辑并明确提示，不能让默认表单静默丢弃。先覆盖 Area/AreaMap/Node/Spot，接着用 Story/Entry 证明专用内容接入，再选择 Character/Variant、Item/Shop、Enhancement、Trigger/Effect/Condition、Reveal/Milestone 等领域进行实际迁移。具体实体表名和全部支持范围由本地 Schema 盘点确认。

## 6. 视觉语言和真实刷新

继承 ui-style 中 authoring 已采用的密度、树行、工具带、Inspector、引用/条件和 Story Flow 规则。不是给所有工具换同一种新主题。保留成熟交互的具体细节；若独立编辑器与游戏内主题不同，先共享语义角色和组件结构。实际 DOM 复用现有 WorkspaceColumns 与区域更新分级。输入时不全页重建，复杂弹窗使用已有浮层和锚点管理，树滚动只属于相应 Explorer。

布局实验至少展示项目文件、实体 Explorer、混合标签、中间地图或正文、Inspector、可折叠诊断区域。不要把所有工具塞进顶部，也不要用满屏卡片替代已有密集工作界面。需要在真实宽屏鼠标环境检查复杂条件弹窗、长 ID、滚动与选择；其他逻辑优先 DOM/状态测试与 DEV Navigation。

## 7. 实际迁移计划和验收

第一批：选择一个真实 Spot 的普通字段、一个引用字段、一个真实复杂条件，分别在独立编辑器、Runtime Editor 和 Story 相关控件定位当前实现。提取共用的字段/引用/结构编辑能力，选择真实消费者接入。第二批：统一草稿和文件保存路径，保留现有实例与宿主，移除同一编辑操作的重复写入。第三批：P0 的正反向索引进入实际关系导航；改名与删除显示影响。第四批：地图专用编辑与 Story 专用编辑接入，不重新实现框架。第五批：逐域扩大覆盖并删除已经迁出的旧表单、校验、保存和引用查询路径。

验收：同一实体两标签共享修改；Explorer 来源与活动实例独立；无效引用能定位到真实字段；复杂条件弹窗确认/取消及撤销正确；文件移动后仍能编辑正确对象；只读依赖不可写；外部修改冲突保留草稿；P2/CLI 对同一输入得到同一诊断；试播不污染玩家存档。每次验收必须使用真实消费者，而非单独新建的 Demo。最终新增一类普通实体只应配置 Schema/领域查询与必要专用操作，不再重造搜索、保存、引用与布局框架。
