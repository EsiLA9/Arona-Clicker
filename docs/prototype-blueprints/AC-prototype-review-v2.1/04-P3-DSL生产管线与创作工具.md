# P3 DSL 生产管线、文本创作工具与高级预览

## 1. 本轮设计范围：建设能持续演进语言的工具，而不是定稿语言

DSL 是作者书写内容的一种方式，而不是本轮原型调查需要完成的产品语言。未来负责人将专门、细致地研究和修改 Story DSL 的语法、记号、书写惯例、表达方式，乃至其他实体的文本表示。此次设计必须为这种持续修改提供可靠工具和接入路径。即使下一轮将全部语法推翻，文件项目、标准数据模型、诊断系统、输入框、预览器、CLI 和 Runtime 接入也不应随之重写。

我们仍然期望正式语言像 Markdown 一样适合普通作者和 AI 写作，而非机械地手写 JSON 对象。但这是未来语言设计的产品目标，不是此刻要求调查 Agent 比较大量语法候选、决定对白关键字、分支缩进或标记格式的指令。当前只需要说明语言最终必须能够表达什么、工具如何接受不同语法，以及改动语法后如何验证与接入。可使用极小的临时测试文本或模拟解析结果验证接口；不得将它们当成推荐的正式语法，也不需要输出成套语法规范。

现状依据为原审计 A08/A09：StoryNodeDocument、StoryDef、StoryEntry、现有节点播放器、续接、奖励、保存与试播。stat-dsl 解析统计表达式，content-policy-dsl 做结构审查，dsl-editors 是结构化控件，均不能直接等同于正文解析器。本轮要核实的是这些实现提供的标准结构、校验、引用及预览能力，确定 DSL 接入和未来更换语法时的边界。原型不另造 Story Engine，也不为了演示 DSL 编造运行规则。

## 2. 实际使用场景与完整数据流

未来作者在项目中打开一份 Story 源文件，输入或粘贴文本。文本编辑器保存原文，调用当前语言解析实现，取得候选 Story 数据、对应源码位置以及错误列表。作者可以在右栏阅读解析结果，检查条件和选项，或者使用真实游戏播放器试播。错误不应让文本消失，也不应使旧预览悄悄冒充当前结果。作者保存未完成文件后仍然可以继续创作；正式构建需要走 P0 的完整检查。Agent 从终端读取同一份文件，也能得到同样的诊断及候选定义，不必启动浏览器。更换语言语法后，这些操作仍应沿用同一工具入口。

```text
源文件 / 输入框片段 / CLI 文本输入
  ↓  明确格式、语言版本、输入上下文
语言前端（可更换：文本识别、语法解析、语义转换）
  ↓  候选标准定义 + 源位置映射 + 诊断
共同作者模型与 P0 检查（结构、身份、引用、领域规则）
  ├─ P2 结构化编辑 / 阅读及高级渲染
  ├─ P6 CLI / Agent 可读诊断与转换输出
  └─ 正式构建 → Registry / Runtime 准入 → 隔离试播或实际应用
```

JSON 输入可走现有结构解析，随后与 DSL 共用同一标准定义、引用检查与运行入口。图中的阶段是职责边界，不强制每层创建一个类或独立数据副本。原型要核实已有 Story 作者合同是否足以直接作为共同模型；若需要中间结构，说明它保存了哪些无法直接在现有定义中表达的信息，而不是仅为“编译器应当有 IR”新造一套 Story 类型。

## 3. 语言前端与公共工具之间的工作界限

| 工作 | 负责方与实际结果 |
| --- | --- |
| 识别输入格式 | 根据显式选择、项目声明或受控检测选择语言实现；歧义时提供候选，不擅自修改文本 |
| 解析语言 | 当前语法实现读取原文，返回语法结构、错误及位置；语法树如有需要由该语言实现拥有 |
| 转成标准定义 | 当前语言实现将语法结构转为实际 Story/Entry 等候选定义；保留可定位映射，报告无法表达或尚不支持的内容 |
| 领域规则检查 | P0 和现有领域规则检查定义与引用，不在各语法实现中重复 |
| 文件读写与组织 | P1 保存原文、格式声明及文件归属；不理解具体语法关键字 |
| 编辑与预览 | P2/P3 的编辑和预览组件消费共同数据、诊断与位置；不直接遍历某一版私有语法树来决定 Story 如何播放 |
| CLI 与 Agent | P6 调用同一作者服务，返回同一诊断和候选定义，帮助文档随实际语言版本更新 |
| 运行 | 使用现有 Story 执行规则；不按文本语言另行解释玩家行动 |

建议研究一个足够小的语言接入合同。以下仅表达边界，不锁定类型名、字段名和实现技术：

```ts
interface AuthorTextFrontend {
  parseAndConvert(input: AuthorTextInput): AuthorTextResult;
  // 仅在语言实现支持时提供以下能力
  detect?(input: AuthorTextInput): DetectionResult;
  format?(input: AuthorTextInput): TextEditResult;
  encode?(definition: AuthorDefinition): TextEditResult;
}
```

输入需要能说明完整文件还是局部片段、文本、来源位置、语言/版本及必要的领域上下文。输出至少区分完全成功、部分可识别和失败，提供候选标准定义或结构化片段、源位置和诊断。原型不要求所有格式具有完整反向转换能力；不能转换时明确告知调用方。现有引用查找由共同作者服务完成；如语言支持别名，前端只提供实际引用请求和源位置，不复制一份私有 Registry。

语法树、词法记号、缩进、关键字和文本组织方式属于语言实现的内部决策。其他模块如需要语法高亮、补全、提示或格式化，应通过当前语言实现提供的能力取得结果，而不是写死语法。是否独立 lexer、AST 和转换阶段，以未来语言复杂程度及原型证据裁定。本轮不能以某种语法已经“推荐”或“试验通过”为理由冻结公共接口中的语法细节。

## 4. 三类输入工具的实际行为

### 4.1 现有编辑器内的片段输入与自动识别

普通 Story 节点正文、支持结构化粘贴的输入区域和专门的 DSL 输入区域需要有明确区别。作者在普通正文写冒号、方括号或换行时，不能被自动转换成动作。作者粘贴一段可能包含多个节点的文本时，可以调用语言前端进行识别，显示候选转换和诊断，确认后按现有草稿命令插入或替换；也应允许用户显式选择格式，直接进入解析。检测本身不修改原文或草稿。

原型需具体规定输入触发时机（粘贴、显式解析、输入停顿等）、识别结果展示、确认与取消、插入位置、撤销，以及 IME 组合输入和过期结果。解析若耗时较长，用户已修改输入时不得将旧结果应用到新文本。不能识别的片段仍可作为普通文本保存。片段解析与全文解析必须使用同一实际语言实现和领域转换，不允许为了快捷输入独立发明一套正则语法。

验收使用当前 Story 合同可表达的多节点结构作为预期输出，而不限定测试文本的表面写法。检查识别、明确解析、拒绝、取消、撤销、插入锚点失效、普通输入不误改和引用歧义等操作。

### 4.2 完整 DSL 文件与 JSON 并行

作者能够在项目中创建、打开、编辑、保存 DSL 源文件和 JSON 定义。P1 应知道哪些文件需要语言前端处理，而不依赖固定扩展名才可工作。需要研究作者源与编译产物的区分，以及同一资源出现两个可写源时如何明确选择或报告冲突。推荐每个实体在一个项目版本中只有一个作者权威；具体文件布局、声明方式和存储策略仍待项目设计确认。

在 DSL 源未完整解析时，作者仍可保存原文。构建应拒绝严重错误，不得用旧成功结果冒充新产物。由 DSL 生成 JSON 时允许查看、复制、导出为明确产物；由 JSON 生成 DSL 的能力可随语言设计推进，但不能承诺任何 JSON 当前都能无损编码。切换作者格式时先给出转换预览和丢失信息，再确认写入。结构化编辑若不能可靠回写 DSL，应提供明确的源码定位或转换入口，不能整文件覆盖注释、原有格式或未知指令。

### 4.3 沉浸式文本创作工作区

建设左文本、右渲染的工作方式。左侧拥有作者原文、光标、选择、输入撤销和错误标记，右侧读取当前解析结果及诊断。左右区域独立滚动；源位置映射支持双向定位，但不强制每次输入都滚动预览。解析失败时标出问题位置，并说明右栏是当前部分结果、上一份成功结果或无可用结果。解析任务与文件修订绑定，旧任务完成不能覆盖新版本。

沉浸模式接入已有 Workbench 实例生命周期，允许切换其他资源后恢复正在编辑的文本和位置，不引入必须退出才能继续工作的全局锁。可暂时收起 Explorer、Inspector 或诊断区；退出沉浸恢复原布局，不隐式覆盖基础偏好。已有 Story 正文编辑器、属性和试播能力应被调查、提取及接入，不因使用 DSL 就建立一套孤立的展示和播放组件。此轮只设计通用文本宿主、诊断定位和预览接线；具体语法着色、补全规则、快捷输入语句等待正式语言设计。

## 5. 右侧渲染与高级判定：消费标准定义，不消费语法记号

右栏至少覆盖三个实际用途，不因语言语法尚未定稿而延后整体设计。

- 作者阅读/结构视图：展示全部可解析正文、发出方、选项、分支、演出与操作摘要及关联 Entry。未满足条件的内容应可展开查看，不能直接丢弃。点击元素通过源映射找到对应文本。此视图不是模拟玩家已经获得的信息。
- 玩家试播：选定真实 Init、Entry 或 Story 以及初始状态，调用现有播放器，按点击和选择观察实际结果；试播不写正式玩家存档，不发放真实奖励。
- 高级判定：显示条件表达、求值结果与失败原因、Flag 的读取/写入、Effect 实际执行记录、跳转与续接目标、缺失引用。允许在隔离状态中修改测试输入和尝试其他分支。静态无法确定的结果明确标为未知，未运行的行为不得显示为已执行。

例如一个标准 Story 有两个选项，其中一个带条件。无论它最初来自 JSON 还是未来任意版本的 DSL，结构视图都应能展示两个选项，玩家视图依据真实状态给出可见选项，高级视图说明条件结果及对应源位置。这才是渲染工具与语言解耦的检验。对于从中途开始的预览，核实必要的剧情逻辑和表现状态能否重建；首轮可选明确检查点，不要求任意文本行立即运行。

## 6. 语义覆盖、来源映射与语言迭代

先调查现有全部 StoryNodeDocument、StoryEntry、条件、效果、Flag、选择、续接、演出、等待、音频、移动等合同和真实样本，形成“标准字段或行为 → 语言需表达的语义 → 当前接入能力 → 测试样例 → 未支持原因”的覆盖表。这不是语法手册。不要逐字段发明关键字；后续正式语言设计可利用默认值、简写、引用、组合结构等方式表达这些语义。

第一批用普通对白、旁白、选项及分支检验端到端接口；第二批用现有白子邀约/天台样本检验 Entry、续接、Area、返回 Flag 和存档；随后覆盖其余实际节点与动作。使用同一标准 JSON 作为行为对照，比较字段、节点顺序、引用、分支及运行结果。对复杂内容暂时无法由试验前端表示的情况应明确报告，不准删除字段或编造等价关系。

源位置映射需要适用于节点、字段和引用，支持诊断跳转、预览对应及以后可能的精确回写。原文和节点身份如何关联、外部编辑后如何识别同一节点，仍需实验；不把行号、显式 ID 或某种标记格式直接规定为唯一方案。若需要稳定身份，说明它如何兼容重新排版和语法迁移。保留旧语法源及其版本信息，格式升级应有显式转换、差异预览和失败保留原文的能力。首轮不要求为尚未设计的语言实现完整迁移器，只需要确定接入点及不破坏作者源的规则。

最重要的架构实验：用一个极小的临时前端贯通文件、编辑器、CLI、构建和预览；再替换为另一个仅改变测试文本表示方式的前端，验证共同标准定义与后续消费者保持相同。第二个前端是测试替身，不是第二套正式 DSL，也不需要另建完整解析器。若更换前端需要修改公共编辑器的业务逻辑、P0 的领域规则或 Runtime 的 Story 执行器，应记录泄漏点并重新设计边界。将来扩展到其他实体时可以复用文本接入、诊断、来源映射和工具宿主，不提前建设万能 DSL。

## 7. CLI、AI 自助检查与语言说明的交付

P6 提供共同命令入口；P3 提供实际语言接入、识别、解析、转换、格式化及帮助能力。建议命令用途包括检查全文或片段、输出标准 JSON、查询语义支持范围、查看诊断、按当前语言格式化、验证试播。具体命令名称及扩展名暂不确定。CLI 可直接读取文件，也可接受明确格式的标准输入，方便其他 AI 将玩家生文本转换为候选 DSL 后快速检查。

诊断需同时适合人类和机器：输入来源、行列或片段范围、具体错误、相关实体及当前语言实现可提供的修正提示。语法错误来自该语言实现，引用和领域错误来自共同检查服务。人类编辑器和 CLI 对同一文件、同一版本及上下文应得到一致的关键结果。工具说明应能从当前语言能力和实际测试样例更新；正式语言尚未设计时只提供试验工具的使用说明，不能把临时文本格式写成官方规范。将来语法改版，修改语言说明、测试和该语言实现即可，不能要求 AI 重新学习整个引擎架构。

## 8. 建设路线与验收

1. 核对标准数据合同及现有创作、校验、运行、试播入口；列出可复用能力、真实缺口和每个消费者所需输入。完成语义覆盖表，而非语法规格。
2. 确认文本接入、候选结构、诊断、来源和版本的最小公共合同；以一个临时前端或模拟解析结果贯通 JSON/DSL 并行输入和 P0/P1。检查错误与未完成源保存。
3. 接入现有输入区域的识别和解析、结构化插入与撤销；建立真实沉浸式左文本右渲染宿主。CLI 同步调用实际共同入口，不先建设独立工具系统。
4. 让作者视图、玩家试播与高级判定真正读取共同模型，使用现有 Story 样本比较语义和运行结果。完成源码与渲染双向定位，检查试播状态隔离。
5. 进行语言替换实验：改变临时文本表示，验证文件组织、编辑器、诊断、构建及预览可沿用。记录尚不支持的反向转换、节点身份和来源映射问题。
6. 形成独立的后续正式语言设计任务输入：已确认的语义需求、工具限制、可用接入点、真实样本、未决问题和必要的实验指标。之后由负责人组织详细语法设计与多轮修改，不能把此次临时表示直接提升为正式语言。

本轮原型通过的标准是：真实文本或测试输入能沿共同管线变成候选数据、得到定位明确的诊断、在编辑器与 CLI 中使用，并由现有 Runtime 验证；语言实现可以被替换，普通工具不会因语法变化而整体返工。最终语法、关键字、缩进、扩展名、语言简写、格式化风格、节点锚点写法及具体书写惯例属于后续专门的语言设计，不是本轮的完成条件。

本页仍是指导本地调查与设计的参考稿，不是源码施工授权。所有实际接口和迁移对象必须以本地当前工作树核实。
