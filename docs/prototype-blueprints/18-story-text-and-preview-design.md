# 文本接入与三种剧情预览怎样构造

此页为 P3 的构造规格。语法本身留给独立语言设计。编辑器如何识别片段、保留输入法与双栏操作见 [P3](04-story-dsl-and-compiler.md)。现有可表达的正文/入口/运行行为见[语义清单](12-story-semantics-and-preview.md)。

## 语言接入做什么，公共工具做什么

| 能力 | 语言接入的输入与输出 | 公共工具怎样采用 |
| --- | --- | --- |
| 识别 | 文件元信息或输入区、原始文字，返回可能的语言/版本和匹配理由。可在不执行完整解析时返回候选 | 显式设置优先。匹配多个显示选择。无匹配保留原输入。构建只能用确定的语言/版本与项目格式声明 |
| 全文 | 文件、文本、语言版本、来源，期望输出表和项目明示的默认信息。解析并转成一或多个标准定义 | P1 扫描器把定义、字段位置和语法诊断交给 P0。项目规则和引用不会在语言实现内重写 |
| 片段 | 文本、字段类型、目标 Story 与局部作用域、草稿版本和插入位置 | 返回标准候选节点/结构、本地位置和诊断。编辑器负责重验插入点、身份与目标草稿版本，走现有草稿动作，整批撤销 |
| 反向生成 | 一个已检查的标准实体或结构、输出版本和可用表达方式 | 返回文本、可表达范围或未支持字段列表。无法无损表示时不给“成功”的覆盖操作 |
| 格式化 | 原文件或选中文本与版本 | 返回待预览文本和受影响范围。保存之前重走解析，对照标准语义、位置和预期源版本。保留丢失信息的原文 |
| 帮助与补全 | 光标位置、语言版本、处于哪种语法与位置范围 | 语言提供语法和语言能力，通用候选从 P0 按领域键解析。没有能力时关闭对应动作并说明，已有原文和读取入口仍可用 |

每语言接入登记语言 ID、明确的版本、输入类别、各项能力与对应函数。语法树可供其格式化和补全，留在语言实现内部。文本处理服务接受以下工作请求并调用接入，生成适用的标准结构、来源和报告。

~~~ts
type TextOrigin = {
  path?: string; packageRef?: string; textDigest: string;
  // 输入框身份和源文件身份分别提供，片段相对框内定位。
  buffer?: string;
};
type TextWork = {
  language: { id: string; version: string }; text: string; origin: TextOrigin;
  requestRevision: string;
  target: { mode: 'document'; expectedTables: readonly string[] }
    | { mode: 'fragment'; owner: Owner; field: string; draftRevision: number; before?: string };
};
type TextOutput = {
  requestRevision: string;
  status: 'parsed' | 'partial' | 'failed' | 'unsupported';
  // 全文用 DefinitionRecord。片段暂由目标域接收未提交内容。
  content?: { kind: 'definitions'; rows: readonly DefinitionRecord[] }
    | { kind: 'fragment'; values: readonly unknown[] };
  fieldRanges: Readonly<Record<string, { start: number; end: number }>>;
  diagnostics: readonly Diagnostic[];
};
~~~

全文标准路径从实体根起，片段从候选根起。公共服务把框内范围映回缓冲区，或在成功插入并取得新来源后生成定位。语法错误与不支持的语义由接入报告。成功转换后，结构、引用和领域诊断沿 P0 共用字段位置返回。全文部分结果可供作者阅读，构建阻断。坏片段禁止提交。缺引用可按原 P3 规定作为待修正的项目问题。文本保存保留真实原文。语义归属由标准 ID 与实际项目源确定。一个已登记的版本若不能写回，结构编辑器只给阅读、查源、复制建议或明确转换。

服务以“语言/版本、来源、原文摘要、目的、请求版本、需要的目标/草稿信息”区分结果。工作台接收时同时核对当前实例、文本和所针对的字段。构建指定固定读入版本，不使用某个编辑器刚完成的旧响应。相同文本走 `projectStoryDefinition` 等现有结构检查，再进入 P0 与 Runtime。CLI 识别与处理调用相同服务。首次接线查 `story-definition-projection.ts` 与 `node-clipboard.ts:pasteStoryNode`，把其中可复用的目标身份、插入和校验留作实际调用。保留旧剪贴板格式和 `stat-dsl` 当前职责。

## 怎样证明两个很小的前端真的解析了文字

A 读取一行里发言者、分隔记号和正文，B 读取括起的发言者行和正文行。试验上下文显式提供同一个 Story ID、节点 ID 与起始 Area 的默认值，发言者用试验表把白子解析成 `shiroko`，正文逐字读取。对比 P3 现有标准 JSON。每个前端支持这一条对白的全文和片段模式，全文包裹共同默认值，片段输出可实际插入的 talklet。帮助、反向生成、复杂语法均可声明未支持。验收以实际消费者独立调用为准。

| 输入或变化 | 必须观察到 |
| --- | --- |
| A 用 `白子：你好。`，B 第一行 `[白子]` 第二行 `你好。` | 相同标准节点、分别准确的发言者与正文位置，编辑器和 CLI 本地调用结果一致 |
| 把两种输入都改成“请到天台来。”，再写一份从未出现在样本中的普通短句 | 文本改变输出也改变。真实 Runtime 显示其中新句子。固定模板只允许提供 Story 的默认壳 |
| A 缺分隔、B 缺右括号。另外测试只填空正文 | 报对应语言的语法错误，位置来自当次输入。保留未完成原文，片段不能改草稿，构建拒绝 |
| 原文有效，把全文默认起始 Area 指向不存在的 ID | 语言识别和语法处理成功，公共引用检查失败。默认生成字段定位到默认值来源，并说明精度 |
| 使用 CRLF、中文和含补充平面字符的正文 | 编辑器和 CLI 同一位置规范。B 的正文仍为第二行，回跳准确，原文不会被标准模型覆盖 |
| 编辑器插入一次、撤销一次，关闭 A 仅保留 B，分别经项目扫描、CLI 和实际构建 | 两种输入均走共同路径。运行使用新构建和标准节点。更换时只改接入注册、样本、语言说明与解析测试，共用检查和播放器无需判断 A/B |

白子赴约 JSON 用于验证复杂运行。现有语义可以经一个测试接入提供同一标准对象做 R6 对照。该对照与上表的真实解析验收各有用途。

## 作者阅读、玩家试播、高级判定的三条输出

| 输出 | 输入与计算 | 作者实际看到的结果 |
| --- | --- | --- |
| 作者阅读 | 规范 Story 和 Entry，顺序遍历所有节点、选项、局部目标和跳转。子剧情可展开一次，循环显示指向关系 | 所有文字和分支，显示声明的条件、Flag、可能效果及跨 Story 跳转，诊断可点回原文。无运行时事实时仅显示声明 |
| 玩家试播 | 固定候选版本、真实 Entry 或临时 Story、测试初态和操作。调用 `createStoryAuthoringPreview` 适配现有 GameInstance 试播。要复现玩家资格时使用实际触发或记录当前作者回放对 replayable 和入口的调整 | 实际所走一条路径、可选条件、等待、位置和结束。选择、行动及广播使用沙盒。作者人工放行另行标记 |
| 高级判定 | 静态全分支目录与当前试播检查点/轨迹一起显示。沿 `StoryPreviewConditions` 读取 entry、choice、transfer 的当前及历史结果。副作用读取实际动作或事件结果 | 显示每项声明来源、当前使用的测试状态、实际求值、人工选择和步骤结果。未到达的环节显示“未执行”，无法安全求值标“未知” |

当前游戏试播会复制当前存档、重置草稿游标，并对直接播放生成隔离 Entry。它尚未给所有工具通用的可注入测试 Init/初态入口。首批用现有测试和实际可启动的初态。需要注入时显式给受支持初态字段和拒绝原因。禁止 CLI 自己计算一套条件结果。

## 高级判定作为单独交付

用一个本项目独立候选 Story，在一个真实 Choice 节点设置六条可区分选项。采用已支持的持久条件、局部标记、Effects 与 transfer，结果由实际测试初态和选择决定。至少覆盖无条件、持久条件成立、持久条件不成立、局部标记存在与缺失、触发目标正文等类别。不强求六项都在同一初态可选。用现有 JSON 先做，沿[语义清单](12-story-semantics-and-preview.md)为每项标记真实字段。作者能展开六项并跳源。实际编写时为每个 option 设置独立的 `marks`，配相同标记控制的 talklet，然后按表验证一条完整路线。

| 选项 | 首次进入选择节点时的状态 | 观察到什么 |
| --- | --- | --- |
| 普通交谈 | 无附加条件 | 播放器提供选项，选中后只进入其正文 |
| 查看已获得的强化 | `showWhen` 用 `target: 'hasEnh'`、`key: 'base:enhancement:pyroxene_rush'`、`comparator: '=='`、`value: 1`。第一份测试初态拥有该强化 | 显示实际通过，另一份初态移除该强化后重跑转为未通过 |
| 查阅特别记录 | `showWhen` 为现有空 OR 的假值 | 高级判定显示实际失败，作者阅读仍能展开。人工放行单独记录 |
| 使用已记路线 | 先由 `localFlag` 的 set 写入 false，`requiresFlag` 检查键存在 | 实际通过，回执说明检查的是存在 |
| 调取另一份记录 | `requiresFlag` 指向尚未写入的键 | 当前选择不可用。另一次运行在前序写入此键后开放 |
| 领取凭证并去查看 | 条件真实满足，后续 operation 加一项资源，再用 `transfer.mode: 'insert'` 进入已知子正文 | 真运行才出现动作和目标记录。资源只加给沙盒，结束后返回原正文 |

先跑实际选择，再改测试状态或在高级模式明确采用人工结果。比较下面的输出。

1. 以 Story ID、nodeId、optionId 或动作位置对接静态条目。运行中附 session、步骤序号与实际 Entry。这样父子互相调用、同节点出现多次时不会覆盖旧结果。当前引擎若没有暴露可关联的身份，先给一项真实检查点补回执。不能靠文案相同推断是同一项。
2. 行可标“声明”“实际通过/未通过”“人工通过/未通过”“未执行”“未知”“动作成功/失败”。人工放行同时保留真实值和采用值。不能用读初态的静态求值冒充剧情途中实际结果。展示玩家持久 Flag、Story 局部 Flag、效果意图与实际已执行各自范围。
3. 独立试播停止时保留一份可读报告，关闭释放状态。现有 `preview-view.ts` 的条件列表、路线和控制适配回执。右栏加可展开的全部正文目录与同一来源跳转，正文数据更新不重置沙盒实例。没有记录的 Effect 只展示其声明用途，从真实消费者逐项补，不声称已执行。
4. 验收包括没走的分支仍可读、人工放行留痕、不同输入可重复实测、非法 target 定位、旧版本试播不会换成新草稿，以及掉线或取消后的正式存档不变。正常工作台顺序为 R5 文本与作者阅读试点、R6 玩家试播和高级判定分别交付。相关现有用例从 `tests/ui/story/story-editor-authoring.test.ts`、`tests/engine/story/story-continuation.test.ts` 开始。
