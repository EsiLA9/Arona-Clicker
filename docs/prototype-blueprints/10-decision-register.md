# 决策登记与负责人确认

保留第一轮 D01–D12 的事实和可比较方案，并改用真实用户操作判断。可逆试验默认项由获准的施工任务记录，例如使用现有包格式、测试副本和临时语言实现。影响长期产品方向、正式数据或存档的选择请负责人根据对照结果确认。语言以后具体写法不阻塞文本接入。先看[共同工作规则](08-cross-system-contracts.md)和[首轮数据合同](13-authoring-service-contract.md)，再查[第一轮技术备选](technical-notes-v1.md)。事实来源见[审计](11-current-implementation-audit.md)。

## D01 编译与运行职责

- **Confirmed。** A01–A06 显示解析、独立验证、Registry、Runtime 写入分别存在。三入口的检查和错误形状不同。
- **Recommended。** P0 从 P1 快照构建，Runtime 做准入与运行保护。可共享规则、定位和构建结果。
- **Alternative。** 以 Registry 为共用工作台宿主并把 Parse、UI 附着其上；集成更快，但 P2/P6 继承运行时依赖。实体库为源另见总架构。
- **Prototype experiment。** 输入重复 scanner、缺引用、复杂 AreaMap 和 Base 有效闭包，比较两个验证实现的诊断数量、直接节点位置、Runtime 依赖和对照效果。
- **Decision gate。** 重复字段必须定位两处，静态错误跨入口一致，旧包合法性差异逐项可解释。负责人确认 runtime-only 检查清单后才能冻结接口。
- **实际使用对照。** 让作者通过工作台和终端分别检查同一个错误并修正。比较从看到诊断到定位进哪一处字段所需的动作，另确认当前游戏仍能明确解释为什么拒绝应用。

## D02 Schema 权威与生成

- **Confirmed。** A06 以 TS 类型生成部分 Schema，工具叠加 extras，语义散在验证器。
- **Recommended。** 版本化领域合同注册结构、引用和语义，沿 TS 路径产出 machine-readable 目录；extras 声明控件/说明。
- **Alternative。** Schema-first 生成 TS 与编辑器目录，规则更新传播明确，复杂表达和特例需要额外语义注册。
- **Prototype experiment。** 选 AreaMap、Effect、Condition、StoryEntry 和一个 tag/legacy ID case，分别表达结构、动态引用和定制错误，做双向变更测试。
- **Decision gate。** 明确哪些字段当前生成漏出，给出两方向变更成本和错误差异。必须证明结构变化只改一个权威层，确定可扩展注册点。
- **实际使用对照。** 给领域作者一项现实改动，例如 AreaMap 节点新增可引用字段。观察编辑器有没有正确的选择器、普通调用方是否只改一处定义、旧生成目录如何更新、字段问题能否原地出现。

## D03 文件所有权、格式、锁和身份

- **Confirmed。** A01/A02/A05 已有作者源、分片、发行包和按序合并。逐文件作者身份尚未覆盖完整链路。
- **试点建议待评审。** 每个实体一个可写源，按实际读取顺序计算表内次序，分片路径可任意组织。以作者侧清单保存次序，以合并 JSON 供旧 Runtime。依赖固定为本次选定记录和摘要。长期稳定 Handle、锁与项目格式另行决定。见[分片构造](15-datapack-fragment-order-design.md)。
- **Alternative。** 单实体允许显式授权的多文件 facet；或者实体数据库权威。合并操作方便，冲突、注释往返和多人版本适配复杂。
- **Prototype experiment。** 拆 Base World 字段、导入旧碎片与一份 Story，进行跨文件引用改名、并发修改和排序置换。第二方案还要测 graph facet 与 metadata facet 冲突。
- **Decision gate。** 语义可重现、文件移动不掉身份、产物根可解析；裁定双 owner、单例重复和依赖覆盖规则后才冻结格式。
- **实际使用对照。** 让新人分别用按表、按实体两种全拆，合回选中的 JSON，再把白子文件移进角色目录。用文件预览、工作台、玩家目录和实际入口分别核查，确保作者能解释多归属如何摆放。

## D04 提交原子性与恢复

- **Confirmed。** 现有包级 save 与 Runtime receipt 已能防某些热写失败，缺多文件工作区事务。
- **首轮默认。** 单文件保存先比较原来读到的内容，冲突保留草稿；在副本做批改并备份。多文件崩溃、同时写入或重试反复发生时，进入第一轮的文件锁、预期摘要、持久日志与发布修订实验，保持 git 可审查。
- **Alternative。** 内容寻址快照和原子指针作为作者源，再显式导出为可编辑树；读一致，外部编辑需要额外同步。
- **Prototype experiment。** 三文件重命名。两个编辑器并发，分别在写入前、部分写入与发布后中止，再重开取相同 planId 回执。
- **Decision gate。** 确认宿主/文件系统支持锁与恢复。若外部直读也要求批次级隔离，比较候选对 Windows 文件操作和复现工作树的影响。
- **实际使用对照。** 用真实场景模拟一个人修改 Spot，另一个人同时改同文件的其它字段。检验冲突界面是否描述清楚、双方改动能否找回；先记录用户付出的额外步骤，再比较事务方案。

## D05 工作台宿主、草稿与预览

- **Confirmed。** A04/A06–A10 有独立工具与游戏内外壳，保存、实例和试播边界分散。
- **试点建议待评审。** R4 首个宿主为现有游戏内 Advanced Workbench，R1/R2 的真实文件入口先用独立 Datapack Editor，Runtime 保留在线查看、热写和沙盒。[宿主与会话构造](16-workbench-session-and-structured-editing.md)明确真实源权限及覆盖边界。长期产品形态未裁定。
- **Alternative。** 先只做独立作者应用，游戏内只保留只读调试和启动器。隔离更强，现有游戏内编辑的常用路径要验收。
- **Prototype experiment。** 用 AreaMap/Node/Spot 和 Story 两域比较打开、按来源编辑、并发窗口、恢复、预览状态，捕获真实宽屏界面与 DOM 行为。
- **Decision gate。** 负责人确认哪些原有在线编辑需保留、何时可退出，同会话共享草稿与跨会话冲突测试通过，可按首个持续使用场景选择宿主。
- **实际使用对照。** 第一次接手的人能否按地图 → Area → Spot 打开条件、取消一次、确认一次并保存正确文件。长列表和弹窗原焦点、滚动和标签的稳定性进入宿主对照。

## D06 Runtime / 旧档准入与回退

- **Confirmed。** A03/A04/A08 有包启用、写回滚和 Story 游标保护，现有工程约定以清档为默认机制。
- **Recommended。** 不兼容新版本时显式拒绝并以独立存档开新版本，保留原档和旧构建作为回退；兼容变更准入前预检。
- **Alternative。** 按有限的身份映射迁移一个目标版本，导出审查结果并可恢复。能保留旧进度，需要先明确受支持数据及失败规则。
- **Prototype experiment。** Base 与依赖包读档、移除当前 Story 节点、旧档含角色/地图/里程碑、模拟两处适配失败；对照继续运行、拒绝或转换。
- **Decision gate。** 负责人决定应保留的实际存档、清档/迁移策略、热切换和停留点。失败前无覆盖，正式切换有已演练回退。
- **实际使用对照。** 以玩家视角记录正在天台等待、尝试切包、看到拒绝、回到原会话的连续操作。避免只验迁移脚本的返回码。正式切换前核对能如何恢复。

## D07 语言实现可替换，具体语言随后设计

- **已核实。** 现有 StoryNodeDocument 与 Entry 承载游戏语义；stat-dsl、作者表单和对象投影已承担各自工作。它们没有提供可替换的全文、片段、双栏和终端语言接入。
- **首轮试验默认。** 每实体一个可写源，项目允许 JSON 和文本共存；只在约定的输入区提示识别，解析后由作者确认插入。共用工具取出标准结构与位置。作者可保存未完成原文。使用两个真实解析发言者和对白的小型试验接入，改字必须改变运行结果，各自产生语法诊断及位置。完整父子行为使用现有 JSON 和共同标准对象对照。
- **保留的长期备选。** 稳定后可考虑 DSL 成为全部 Story 正文的作者入口、不同实体各自选格式、或仅部分字段以文本为主。自然正文加复杂结构、全结构文档及回写取舍都留在后续专门语言研究。第一轮的语法探索不作为本轮施工条件。
- **验收。** 在相同编辑器、构建器和终端更换接入，所得共同定义相同，原文位置各正确；检查输入框不会误改普通正文、失败文本可保存、左栏光标稳定、右栏区分作者阅读/玩家行为/高级结果。观察换接入实际改过哪些文件，公共业务、静态规则和播放器出现语法分支即需修边界。
- **负责人以后裁定。** 正式文本读写风格、扩展名、关键字、复杂行为表达、节点身份书写、无损回写范围与语言迁移。交给该阶段实测写 100 行对白、修改一句话、检查复杂动作、定位错误的成本。以上均不是 R5/R6 完成条件。[P3 实际操作](04-story-dsl-and-compiler.md)。

## D08 玩法知识、归属与捕捉事实

- **Confirmed。** A11–A14 有保存范围 Reveal 与访问/投放/库存的 per-Init 字段，角色持有有专属范围。
- **首轮默认。** 先对照已有 Reveal、库存累计、Story 已读、角色和地图记录。实际达不到回顾或区分范围时，才在相应领域补少量事实及可追溯来源。保留第一轮类型化事实与局部修订方案供存在跨域问题时比较。
- **Alternative。** 全量事件溯源重建知识和到访状态。查询整合容易，存档体积、迁移与冷启动需用多场景证明。
- **Prototype experiment。** 同一玩家跨 Init 获档、认识角色并再次导航。在热更与保存恢复后检查作用域及各域条件，量化事件重放成本。
- **Decision gate。** 项目负责人确认哪些知识跨线、哪些能力禁止跨线、旧档的对应语义。互不冲突的 ledger 和投影再冻结。
- **实际使用对照。** 玩家消耗最后一枚芯片后能否找到已取得的资料，并知道下一步去哪里；换 Init 后分开观察知识、库存、人物持有和访问，明确哪项需要改动。

## D09 必达投放与完成后授予

- **Confirmed。** A14 有投放和随机池；A15 当前奖励失败可以保持完成，且不重试。
- **首轮默认。** 首先以实际 Active Entry、地区投放、已有后续和条件安排必达内容。完成后授予的能力先验证能否从现有完成事实或已有条件直接开放。若玩家确实会永久卡住，再比较第一轮的机会记录、同次提交与待授重试方案。
- **Alternative。** 在随机池设保底以交付必要剧情，完成/授予由单独领取动作触发。UI 解释较简单，必达资格会受玩家参与节奏影响。
- **Prototype experiment。** 跨登录与同一事件重复，随机池为空，条件变化，第三枚档案片及奖励失败；比较待投、待授、实际写入和恢复。
- **Decision gate。** 负责人确认哪些内容必达、何时取消未接取、是否提供人工领取；新目标至少一次可用且禁止重复授权。
- **实际使用对照。** 让玩家一次也没抽中日常时仍能发现并接取必要邀约。让授予失败的玩家看懂下一步，实际试用恢复后开启的功能，观察是否重复领取。

## D10 还原资料与覆盖范围

- **Confirmed。** A16 只有可定位的项目内容与目录，官方公告能核实部分卷章和发布顺序。内部 1.3R、2.3、2.3R 对应未确定。
- **Recommended。** 先确认版本/语言的只读清单、权威来源和可使用范围，以起始故事为第一份实物清单。正式导入从每段来源到目标内容可回查。
- **Alternative。** 先只登记范围和元数据，继续用项目已有文本验证全部工具；覆盖率在来源授权达到后开始。
- **Prototype experiment。** 给 3 单元样本设置单段、跨段与缺失映射，验证每阶段计数和阻断。正式试导需要获准的小样本。
- **Decision gate。** 负责人提交内部标签对应、发行版本与语言、正文及资产来源、篇次优先级和差异许可。正式内容无这些证据不能进入制作批次。
- **实际使用对照。** 让核对者从生成的一条对白返回原片段，再从原片段查所有 Entry、资源与未实现演出。检验来源/顺序和玩家可达性是否分别得到判断。

## D11 诊断、资源地址和构建可重复性

- **Confirmed。** A01/A05/A06 有错误字符串、ZIP data URL、导出路径和部分字段路径。实物比对发现同标签的 Base 分片与 bundle 有 Story 起始和 Entry 可达性差异。addition-test 同标签的 ZIP 与目录也存在字段差异。
- **Recommended。** 编译保留可验证 asset digest，Runtime 做地址适配；源位置与诊断做单独侧车；明确语义等价和字节构建两种对照口径。
- **Alternative。** 编译把完整来源和资产地址带进产物，开发可直查，发行体积及本地路径泄露范围大。
- **Prototype experiment。** 同样本在不同路径构建，移动源、替换资产、测试多语言列号和缺失地址，比较产物和侧车。
- **Decision gate。** 各消费方能用相同 code 定位，发行物不依赖作者绝对路径。确认当前 Runtime bundle、分片及开发 ZIP 的规范化与迁入值，逐条裁定对行为有影响的差异，再验收资产变更和确定性构建。
- **实际使用对照。** 操作员只凭报告能说出哪个包是基线、哪条 Story 的起始地点不同、哪些只是地址重写。跑相关实际行为，拒绝用相同版本字符串定等价。

## D12 Agent 权限、工具和审计

- **Confirmed。** A17 有工程 CLI 与项目地图，尚无统一项目作者 API。
- **Recommended。** Node CLI 首发，SDK/Workbench 共用作者服务，显式计划/应用、根作用域、操作审计和恢复回执。
- **Alternative。** 先开常驻本地协议宿主以支持增量状态和协作；连接生命周期及权限细化需新增验证。
- **Prototype experiment。** 用 CLI 和 UI 对照同一 scanner/Story 变更。注入越范围、旧页、旧计划、丢结果重试、沙箱行为失败。
- **Decision gate。** 两入口语义和返回结果等价。根据第二实际客户端的交互和状态需求决定要不要常驻宿主，先冻结最少可复用协议。
- **实际使用对照。** 让未读项目源码的人跟作者帮助完成查 ID、修改、修复错误、构建并试播。记录是否需要额外求助、在哪些提示卡住和能否自行恢复。
