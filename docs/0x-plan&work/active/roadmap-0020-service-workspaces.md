# roadmap-0020 — 存档、数据包、图鉴与统计服务工作区

> 本文定义游戏管理类功能的目标形态与施工顺序：顶部栏作为服务入口，左中右三栏切换为对应工作区。
> 数据包机制以 [[adr-0004-datapack-management]] 为准，UI 表现宿主以 [[roadmap-0018-ui-host-registry]] 为准，本文只规定交互结构、状态和服务间关系。

## 1. 总目标

将以下高影响或信息密度较高的功能从顶部快捷按钮、弹窗和临时页中收束为正式服务工作区：

- 存档：保存、读取、新游戏、导入导出、残留检查；
- 数据包：包库、导入、启用集、排序、依赖与应用；
- 图鉴：故事、学生、设施、强化、物品和来源记录；
- 统计：资源、设施、学生、故事、世界线、标签和数据包贡献。

顶部栏只负责导航，不直接执行读取、覆盖、删除、重载或清档。

## 2. 统一工作区结构

```text
顶部：服务导航与摘要状态
左栏：分类、对象列表、筛选
中栏：当前服务的主要内容与编辑区
右栏：详情、来源、影响、校验、日志与确认
```

统一操作流：

```text
浏览 → 选择 → 查看影响 → 校验 → 确认 → 执行 → 结果反馈
```

工作区共享以下状态：

```ts
interface ServiceWorkspaceState {
  service: 'game' | 'datapack' | 'saves' | 'records';
  section: string;
  selection: string | null;
  draft?: unknown;
  validation?: ValidationReport;
  impact?: ImpactReport;
  pendingCommand?: string;
}
```

通用服务状态：

```text
浏览中 / 已选择 / 有未提交修改 / 校验中 / 等待确认
执行中 / 成功 / 失败 / 空状态 / 只读 / 不可用
```

## 3. 顶部导航

目标入口：

```text
游戏　数据包　存档　记录　外观　帮助
```

“记录”下包含：

```text
图鉴
统计
```

顶部可显示摘要：

```text
数据包 3 个启用　存档 已保存　图鉴 42%　统计无异常
```

摘要不触发操作，只切换到对应服务。

## 3.1 易用性原则

本工作区面对普通玩家、数据包编辑者和维护者三类用户。普通玩家关心能否安全继续游戏，编辑者关心问题如何定位，维护者关心操作影响了哪些运行时对象。因此所有服务遵循：

1. **先状态，后动作**：固定显示当前世界线、启用集、未应用草案和最近一次操作结果。
2. **动作与对象绑定**：保存、读取、启用、删除等按钮放在当前对象或草案附近，避免失去上下文。
3. **危险程度可预期**：可逆编辑和不可逆操作使用不同层级；危险按钮使用“读取并覆盖当前进度”“清除 3 个 mod 残留”等结果导向文案。
4. **错误可行动**：错误同时给出路径、原因、影响和下一步入口，不能只显示错误码。
5. **渐进披露**：默认显示结论和关键差异，详细 JSON、哈希、引用链和日志通过展开查看。
6. **保留上下文**：切换分类或返回工作区时保留筛选、滚动位置和选择；只有明确放弃草案才清除编辑状态。

## 3.2 统一页面骨架

每个工作区顶部固定提供：

```text
当前位置 / 当前对象　状态徽标　搜索　筛选　帮助
```

右栏固定分为“摘要、影响、问题、操作记录”四个可折叠区。没有内容时显示解释性空状态和下一步按钮，而不是空白面板。长列表必须显示结果数量、当前范围和清空筛选入口。

## 3.3 核心任务流与恢复

### 安全读取存档

```text
选择存档 → 查看差异摘要 → 展开影响 → 读取并覆盖当前进度 → 成功后回到游戏
```

差异摘要先回答是否缺包、是否有残留、当前进度是否会丢失。读取失败时保留原游戏会话、原启用集和当前页面。

### 应用数据包启用集

```text
编辑草案 → 显示变更计数 → 校验 → 修复问题或继续确认 → 应用 → 显示结果与回滚入口
```

草案与正式配置必须有明显标签；离开页面时提示“仍有 N 项未应用变更”。应用中禁用重复提交，失败时明确显示“旧配置仍在使用”。

### 导入、删除与清除

导入分为解析、加入包库、启用三步；解析失败的文件不进入包库，加入包库成功但未启用时允许稍后处理。危险操作的确认面板采用摘要 + 影响对象列表；不可逆或影响超过一个对象时，要求输入对象名称或选择明确的影响项。取消后返回原选择。

## 4. 存档工作区

### 4.1 左栏

```text
存档
├─ 当前进度
├─ 本地存档
├─ 自动保存
├─ 导入 / 导出
└─ 存档检查
```

列表显示名称、时间、世界线、数据包环境、残留状态和可读取状态。

### 4.2 中栏

选中存档后显示世界线、区域、资源、角色、故事进度和数据包环境摘要。

操作：

- 保存当前进度；
- 读取存档；
- 复制存档；
- 导入 / 导出；
- 新建世界线；
- 删除存档。

### 4.3 右栏

读取前展示：

- 当前进度是否被覆盖；
- 存档需要的 `modName`；
- 当前启用集缺失的包；
- 将进入残留状态的实体；
- 重新启用后是否可恢复。

新游戏、删除存档和清除残留必须二次确认。

存档遵守惰性保留：Registry 查不到的实体不进入运行时索引，但原始数据保留，用户明确确认后才能按 mod 清除。

### 4.4 易用性补充

- 默认选中“当前进度”，并列展示最近一次保存与当前未保存变化。
- 存档列表支持按最近保存时间、世界线、兼容性和残留状态筛选；空结果显示当前条件和一键清除。
- 读取结论分为“安全可读”“缺包但可保留残留”“存在阻断错误”，避免警告与阻断混在一起。
- 导入时显示目标名称、覆盖风险和未知字段；导出同时附带数据包环境说明。
- 删除后提供撤销或回收站入口；若暂不支持恢复，确认前明确写出“删除后不可恢复”。
- 保存、读取、新游戏完成后刷新服务摘要、图鉴和统计，避免继续显示旧快照。

## 5. 数据包工作区

### 5.1 左栏

```text
数据包
├─ 全部
├─ 已启用
├─ 未启用
├─ 有问题
├─ 依赖缺失
└─ 同 modName 的其他版本
```

### 5.2 中栏

启用集使用草案模型：

```text
当前运行配置 → 待应用配置 → Registry dry-run → 应用或回滚
```

提供启用、停用、排序、版本选择、放弃修改和校验应用。

导入流程：

```text
选择 ZIP / 文件夹 / 文件
→ 解析预览
→ 查看 manifest、hash、错误和资源统计
→ 加入包库
→ 玩家决定是否启用
```

### 5.3 右栏

显示依赖、冲突、悬空引用、Tag 问题、图片资源影响、存档影响和应用错误。

导入不自动替换当前运行内容，不自动删除存档；停用和删除明确区分。

### 5.4 易用性补充

- 包库默认按“当前启用 / 有问题 / 最近导入 / 其他”分组；版本、`modName`、来源和启用状态使用独立徽标，不能只靠颜色区分。
- 搜索同时匹配显示名、`modName`、版本、文件名和资源 ID；错误路径可直接定位到包和条目。
- 启用集编辑器显示“新增、停用、排序变化、版本替换”四类变更计数；无变更时禁用应用按钮。
- 依赖问题分为缺失包、版本不符、循环依赖和引用不存在，并分别提供导入、切换版本或定位引用入口。
- Tag 问题展示名称、来源包、父 Tag 链和最终展开结果；编辑者可跳转到所有受影响实体。
- 应用完成后显示 Registry 重建、图片索引和存档风险结果，只在实际需要时要求重启或返回游戏。

## 6. 图鉴工作区

### 6.1 左栏

```text
图鉴
├─ 总览
├─ 故事
├─ 学生
├─ 设施
├─ 强化
├─ 物品
└─ 数据包来源
```

### 6.2 中栏

列表显示名称、收集状态、来源包、Pool、解锁时间和是否可重读。

统一状态：

```text
未发现 / 已发现 / 已解锁 / 已完成 / 可重读 / 残留
```

未发现内容只展示允许公开的信息，不能通过图鉴提前泄露剧情。

### 6.3 右栏

显示详情、解锁条件、来源数据包、所属故事或 Pool、完成记录和相关实体链接。

图鉴本身是只读视图；重读故事属于明确的游戏命令，进入对话空间或执行前需要确认。

### 6.4 易用性补充

- 默认以“继续收集”为入口，优先显示最近发现、可解锁和缺少条件的条目。
- “显示已隐藏内容”独立开关默认关闭；锁定条目只显示不泄露剧情的最小信息。
- 详情页固定回答“从哪里获得”“还缺什么”“关联哪些条目”，并支持返回原列表位置。
- 来源包被停用或变为残留时保留历史记录，但标注“当前不可用”，不能静默消失。
- 页面标题或筛选栏固定显示统计口径，例如“当前启用内容 / 本世界线 / 已发现”。

## 7. 统计工作区

### 7.1 左栏

```text
统计
├─ 总览
├─ 资源
├─ 设施
├─ 学生
├─ 故事
├─ 世界线
├─ 标签
└─ 数据包贡献
```

### 7.2 中栏

按类别展示当前值、累计值、本世界线值、全局值、最近变化和趋势。

### 7.3 右栏

显示指标定义、统计范围、数据包来源、时间范围、世界线范围以及是否包含残留数据。

所有统计必须明确区分：

```text
当前值 ≠ 累计值
本世界线 ≠ 全局
当前启用包 ≠ 所有已导入包
```

### 7.4 易用性补充

- 总览只展示少量可解释的关键指标；复杂指标进入分类页，避免首次进入出现信息墙。
- 每个指标提供定义、计算范围、更新时间和数据来源；无数据时区分“尚未产生数据”和“数据不可用”。
- 时间范围、世界线范围和数据包范围使用可见筛选条，并显示当前条件；切换范围后同步更新标题和图表/列表。
- 趋势数据同时提供表格或文本摘要，不能只依赖颜色和悬浮提示。
- 标签统计可从标签跳转到实体、来源包和触发记录；空标签、冲突标签和残留标签分别标注。
- “数据包贡献”默认只统计当前启用内容，并提供切换到历史导入内容的明确选项。

## 7.5 跨服务跳转

来源、错误和统计条目都支持带上下文的跳转：

```text
统计指标 → 相关实体 → 来源数据包 → 启用集问题 → 存档影响
图鉴条目 → 解锁记录 → 世界线 → 相关统计
存档残留 → modName → 数据包详情 → 导入或恢复
```

跳转后保留返回栈、筛选条件和原选择；目标不存在时说明是已停用、仅存于存档还是来源包未导入。

## 7.6 可访问性与窄屏策略

- 所有状态同时使用文字、图标和颜色；错误、警告和成功状态必须有可读标签。
- 键盘顺序遵循“导航 → 列表 → 主内容 → 详情 → 操作”；确认弹层打开后焦点锁定在弹层内。
- 窄屏时右栏变为可返回的详情页，左栏折叠为抽屉，中栏保留主要任务；关键操作不能只藏在悬浮提示中。
- 异步校验和应用显示进度、阶段和取消能力；结果通过文本提示并保留在操作记录中。

## 7.7 易用性验收场景

1. 新用户能从顶部进入数据包服务，在不误启用的情况下完成一次导入。
2. 玩家在有未保存变化时读取旧存档，能看懂覆盖范围并取消操作。
3. 缺包、Tag 冲突和悬空引用都能定位到具体来源。
4. 应用失败后，用户能确认旧配置仍在运行，并继续修复草案。
5. 图鉴和统计在切换世界线、启用集和残留状态后不会混淆口径。
6. 窄屏和键盘操作可以完成查看、筛选、确认和取消。

## 8. 服务间关系

```text
数据包工作区
   ↓ 当前启用集 / Registry
存档工作区 ←→ 残留检查
   ↓ 玩家状态
图鉴工作区
   ↓ 只读汇总
统计工作区
```

- 数据包变更影响存档兼容性；
- 存档残留影响图鉴和统计是否显示完整；
- 图鉴读取 Registry 和 PlayerState 的只读视图；
- 统计需要区分当前启用内容与历史累计数据；
- 任何服务都不能绕过 Runtime 或 StateMutationService 直接改 PlayerState。

## 9. UI Host 规则

每个正式工作区声明稳定的 Host：

```text
centerPanel.saves
centerPanel.datapack
centerPanel.contacts
centerPanel.archive
```

内部可继续细分：

```text
centerPanel.datapack.navigation
centerPanel.datapack.main
centerPanel.datapack.inspector
```

服务只声明 Host 并通过统一渲染入口接入；用户主题编辑器从 UI Host Registry 自动发现，不再手动维护目标映射。

## 11. 验收标准

- 顶部栏只切换服务，不直接执行高影响操作；
- 数据包、存档、图鉴和统计均可在三栏工作区中使用；
- 通讯录和档案不再是无主题接入的临时页；
- 数据包启用集支持编辑、校验、应用和失败回滚；
- 存档读取、新游戏、删除和残留清除均明确展示影响；
- 图鉴和统计明确区分当前内容、历史内容、本世界线和全局数据；
- 新服务只需声明 UI Host 即可被主题编辑器发现；
- UI 不直接修改 PlayerState；
- 所有高影响操作均能在确认前解释影响、确认后反馈结果、失败后保留可恢复上下文；
- 列表筛选、详情跳转、异步状态和窄屏/键盘操作满足统一工作区规则；
- `npm test`、`npx tsc --noEmit`、`npm run check:architecture` 通过。
