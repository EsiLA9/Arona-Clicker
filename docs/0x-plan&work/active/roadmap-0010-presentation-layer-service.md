# roadmap-0010 — 统一表现层服务优化

> 本文记录系统颜色层参与全局表现层排序，以及表现层服务从背景图层向区域、控件宿主泛化的实施结果与剩余方向。具体实现以 `src/ui/presentation-service.ts`、`src/ui/context.ts` 和 `src/ui/ui-host-registry.ts` 为准。

## 当前问题

当前编辑器已经能显示系统颜色层，但它仍是一个由颜色系统隐式生成的固定展示项；用户自定义层则保存在 `background[]` 中。两者存在两个列表，导致：

- 系统颜色层不能与用户层共同调整堆叠顺序；
- 编辑器中的顺序不一定等于运行时最终顺序；
- “背景”“区域表现层”“控件表现层”的概念边界仍不够统一；
- 图层的来源、是否可编辑、是否可移除等能力没有显式表达。

## 目标

建立统一的表现层服务，使颜色层、背景层、面板层、按钮层和控件层都使用同一套排序、解析、继承和渲染规则。

## 核心设计

### 1. 使用统一堆叠列表

运行时使用一个按底层到顶层排列的表现层列表：

```ts
interface ResolvedPresentationLayer {
  id: string;
  source: 'system-color' | 'theme' | 'user' | 'scene';
  target: 'global' | PresentationRegion | string;
  kind: 'solid' | 'gradient' | 'image';
  value: string;
  opacity: number;
  removable: boolean;
  reorderable: boolean;
  ignored: boolean;
}
```

系统颜色层使用稳定 ID，例如 `system-color-background`，不再只作为 fallback 存在。它应进入与用户表现层相同的排序管道，但仍保留 `removable: false`。

### 2. 系统颜色层的排序语义

- 默认位于全局背景堆栈最底部，为其他表现层提供色彩底板；
- 允许用户上移或下移，改变它与图片、装饰渐变之间的叠放关系；
- 不允许移出 `global` 目标，也不允许移动到按钮或局部区域；
- 忽略时仍保留在堆叠列表中，但标记 `ignored: true`，运行时不参与绘制；
- 忽略不应影响主题色 token、文字颜色、头像颜色或语义节点派生；
- 用户保存的只是排序位置与忽略状态，不保存系统颜色层的派生颜色值。

推荐将排序保存为来源无关的引用列表，而不是把系统层复制进 `background[]`：

```ts
interface PresentationLayerOrderEntry {
  id: string;
  source: 'system-color' | 'theme' | 'user' | 'scene';
}
```

这样可以避免系统层被误删，也能在颜色系统重新派生渐变后保持用户的层位置。

### 3. 合并与排序顺序

建议采用以下流程：

```text
颜色系统派生系统颜色层
        ↓
读取主题层、用户层、场景层
        ↓
按 target 分组
        ↓
按 layerOrder 合并排序
        ↓
过滤 ignored 层
        ↓
安全解析颜色、渐变、图片与定位值
        ↓
生成 BackgroundView / PresentationView / ControlView
```

未出现在排序列表中的新层，按照来源默认顺序追加，并在下一次保存时补入排序列表。失效的旧 ID应被忽略，而不是阻塞整个主题。

## 表现层服务可优化的地方

| 方向 | 当前风险 | 建议 |
| --- | --- | --- |
| 来源模型 | 系统层与用户层分离 | 所有层统一为带 `source` 的解析层 |
| 排序 | 各处依赖数组顺序 | 引入稳定 ID 和显式 `layerOrder` |
| 目标 | 背景、区域、控件概念分散 | 使用统一 `target`，再由渲染器决定挂载位置 |
| 继承 | 父区域与子区域覆盖规则容易重复 | 先解析父级，再解析子级，最后应用状态层 |
| 状态 | normal / active / disabled 尚未统一 | 增加 `state`，按状态选择或叠加表现层 |
| 安全 | 值、图片、定位分别校验 | 统一 `resolvePresentationLayer` 安全解析入口 |
| 透明度 | 容易与颜色亮度压制混淆 | 派生阶段输出颜色，表现阶段只处理 opacity |
| 预览 | 每次输入都完整重建 UI | 先更新解析缓存，再局部刷新目标容器 |
| 编辑 | 当前编辑器主要依赖 HTML data 属性 | 使用字段路径和统一事件分发器，减少重复监听器 |
| 删除 | 用户层删除后可能丢失顺序信息 | 删除层时同步清理 order entry；系统层只允许忽略 |
| 资源 | 图片引用错误时层直接消失 | 提供“资源失效”状态与安全占位显示 |
| 调试 | 很难判断最终颜色来自哪里 | 增加来源、顺序、透明度和忽略状态的调试视图 |

## 编辑器交互规划

全局表现层列表中的每一项应显示：

| 信息 | 系统颜色层 | 用户表现层 |
| --- | --- | --- |
| 来源 | 颜色系统 | 用户主题 / 主题数据 |
| 顺序 | 可调整 | 可调整 |
| 类型和值 | 只读派生信息 | 可编辑 |
| 透明度 | 系统默认或受控 | 可编辑 |
| 忽略 | 可用 | 不适用 |
| 移除 | 禁止 | 允许 |

移动按钮应直接操作统一排序列表，而不是直接交换某个来源数组中的元素。这样系统颜色层位于中间时，也能正确移动到用户层之前或之后。

运行时与存储的 `layerOrder` 继续按底到顶排列；编辑器按实际视觉层级从顶到底展示，因此编辑器中的“上移/下移”会分别映射为存储序列中的后移/前移。

## 暂不支持

- 任意 CSS 选择器或任意 CSS 代码注入；
- 系统颜色层被删除或移动到非全局目标；
- 系统颜色层反向修改主题色列表；
- 使用外部未注册图片 URL；
- 由表现层编辑器直接修改游戏状态；
- 复杂逐帧动画和依赖时间轴的图层排序。

## 验收标准

- 系统颜色层与用户表现层出现在同一全局列表中；
- 系统颜色层可上下移动，但不能删除或改变目标范围；
- 忽略系统颜色层后，颜色 token、文字判别和头像颜色仍正常；
- 保存并重新进入编辑器后，系统层顺序保持不变；
- 新增或失效图层不会破坏已有排序；
- 全局、区域和控件表现层使用相同的安全解析与透明度规则。

## 当前核验（2026-09-07）

`PresentationView`、`UIContext`、背景渲染器与 UI Host Registry 已形成首版闭环：区域/控件宿主支持父级回退、状态图层、系统颜色层与安全值解析，按钮、Tab、卡片和服务工作区通过统一宿主入口消费结果。剩余范围是调试视图、编辑器专用背景预览和跨尺寸浏览器视觉回归；选择页局部主题过渡另由 [[docs/0x-plan&work/active/task-0025-selector-dynamic-theme]] 跟踪。
