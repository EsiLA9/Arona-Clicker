# ADR 0006：UI 背景视觉层叠服务

**状态：🟡 已裁定，施工至 B3。**  
**日期：2026-09-02**

## 背景

当前 UI 的运行时主题只提供颜色 token，页面背景是单个 CSS 渐变；图片资源虽然已支持 SVG、PNG、JPG 等格式，但只服务头像和聊天图片。为支持蔚蓝档案风格的几何 SVG 装饰、场景图片和渐变组合，需要建立背景视觉层栈。

## 决策

1. 背景配置暂放入 ThemeDef.background，不新增独立背景注册表。图片仍通过现有 PicDef / ImageStore / PicService 解析。
2. 背景沿用 RuntimeThemeManager 的 player → area → student → ephemeral 层级。低优先级层先绘制，高优先级层后绘制。
3. 有 id 的背景层按 id 合并：高优先级定义覆盖同 id 层；无 id 的背景层按声明顺序追加。
4. 背景不进入 PlayerState，而是作为运行时主题结果的一部分提供给 UI。
5. UI 使用独立的 .console-background DOM 容器；背景层默认不接收指针事件，内容层保持原有交互优先级。
6. 背景图片只使用已解析的 Pic URL；非图片值和 CSS 属性经过白名单校验，失效图片层被跳过并回退到默认渐变。
7. setTheme 的临时演出值可以携带背景层，随现有剧情临时主题清理。

## 后果

- 一个主题可以同时表达渐变、JPG/PNG 场景图和多层 SVG 装饰。
- 颜色系统继续负责颜色，背景服务负责资源解析和表现层 CSS，职责清晰。
- 目前还没有独立背景资源表、动画 DSL 或编辑器专用预览；这些属于后续 B4/扩展范围。
