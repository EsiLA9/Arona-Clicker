# roadmap-0014 — 主题编辑器收敛与可理解性重构

> 本文整理 Terra 对主题编辑器的审查意见，并将其转化为后续可执行的重构路线。本文是产品与架构规划，不替代 `roadmap-0013` 的表现层编辑器施工记录。

## 一、审查结论

当前主题编辑器的核心问题不是“功能不足”，而是“编辑层级暴露过多”。它把选择主题、微调颜色、作用域覆盖、表现层和组件定位放在同一界面，使普通用户直接面对完整渲染系统。

因此后续目标应从“继续增加可编辑字段”调整为：

**默认简单、结果可见、来源可解释；高级能力保留，但必须主动进入。**

## 二、问题归纳

### 1. 信息架构失焦

颜色 Token、语义节点、簇覆盖、表现层和组件定位属于不同抽象层，目前被并列放在同一编辑器中。颜色页默认展开大量作用域，造成接近 120 个控件的认知负担。

### 2. 覆盖来源不可解释

“跟随上一层”“自动分配”“继承”虽然表达的来源不同，但当前界面没有同时展示：

- 当前最终生效值；
- 当前值来自主题色、父级、预设还是用户覆盖；
- 当前覆盖影响的目标范围。

空值颜色输入显示固定蓝色，会让用户误以为该颜色已经被设置。

### 3. 表现数据模型尚未收束

当前同时存在全局背景、旧区域表现层、控件宿主表现层、面板透明度和背景排序等路径。编辑器试图统一编辑，但数据来源仍然平行，容易造成排序、回退和写入目标不一致。

### 4. 结构操作存在真实错误

区域表现层新增图层时，存在把新图层固定写入 `shell`、忽略当前区域的问题。此类错误优先级高于界面美化，应先修正写入目标和测试覆盖。

### 5. 创建流程缺少引导

组件页无法创建目标；新增图层默认是“空 + 透明”，用户还要理解表现类型、颜色和透明度之间的关系。创建流程应产生一个可见且可继续编辑的安全初值。

### 6. 刷新粒度和可访问性不足

输入变化与结构操作混用全局重渲染，影响焦点、滚动和折叠状态。多个清空按钮名称相同，导航和目标选择器也缺少清晰的语义、焦点管理与窄屏布局。

## 三、目标信息架构

主题编辑器分为三层，默认只打开第一层：

```text
主题
├─ 预设
├─ 主题色列表 / 主色
├─ 浅色 / 深色模式
└─ 背景图与背景风格

微调
├─ 文字
├─ 强调
├─ 成功 / 警告 / 危险
├─ 当前生效色
└─ 来源与继承链

高级（默认折叠，标记为实验功能）
├─ 作用域覆盖
├─ 表现目标与图层
├─ 控件背景
└─ 组件定位
```

“高级”并不删除现有能力，而是把复杂能力从默认路径中移出。

## 四、统一表现模型方向

最终以 `PresentationHost` 作为唯一表现目标树：

```text
global
└─ cluster
   └─ region
      └─ control
```

每个 Host 拥有自己的图层列表，编辑器能力统一，但图层内容不跨目标共享。

后续逐步收束以下旧路径：

- `presentation.layers`：迁移到明确的 Host 目标；
- `backgroundLayerOrder`：收束为 Host 内部的图层顺序；
- `panels` 透明度：改为对应 Host 的表现属性或系统层属性；
- 平行的背景、区域、控件表单：统一使用同一套图层字段协议。

迁移期间禁止新增新的平行存储路径；项目当前不做旧存档迁移，结构调整可直接更新类型、测试和默认数据。

## 五、覆盖关系的表达方式

编辑器不再默认展示所有可能字段，而是采用“目标 → 已覆盖项目”的方式：

1. 用户先选择全局、簇、区域或控件目标；
2. 默认只显示该目标已经覆盖的项目；
3. 通过“覆盖 N 项”进入选择器；
4. 每个项目同时显示最终生效色、来源和来源链；
5. 空值显示为“未设置”，不再伪装成蓝色输入值；
6. 清除覆盖后明确显示回退目标。

首批默认开放 6–8 个最常用语义色，其余节点放入高级入口。

## 六、创建与预览流程

### 目标创建向导

```text
选择目标
→ 选择表现类型
→ 选择颜色 / 渐变 / 图片资源
→ 自动生成可见安全默认值
→ 进入目标卡片继续微调
```

空图层仍可作为高级操作使用，但不再作为普通创建流程的默认结果。创建后应立即在预览画布中产生可见反馈。

### 预览画布

编辑器内增加固定的小型预览区域，至少包含：标题、正文、按钮、卡片、状态、聊天气泡。点击预览元素即可切换当前编辑目标，避免用户必须返回游戏界面寻找变化。

## 七、实施阶段

### P0：修复正确性问题

- 修复区域新增图层错误写入 `shell` 的问题；
- 为新增、删除、排序和类型切换补充目标归属测试；
- 清理三份旧背景渲染器和重复事件绑定；
- 建立当前模型到统一 Host 模型的字段对照表。

### P1：收束表现数据模型

- 确定 `PresentationHost` 的唯一写入入口；
- 将背景、区域、控件的图层编辑统一为同一协议；
- 把面板透明度明确归入 Host 或系统表现层；
- 删除新增的平行排序和表现字段路径；
- 保持运行时解析在 TypeScript 服务侧完成，UI 只提交 draft。

### P2：重做主题编辑器信息架构

- 将界面拆分为“主题 / 微调 / 高级”；
- 默认折叠作用域覆盖、表现层和组件定位；
- 颜色项显示最终值、来源和继承链；
- 修正空值、清空和回退的视觉表达；
- 将“参与 UI”等状态词改为明确动作词。

### P3：创建向导与预览画布

- 提供组件与表现目标创建入口；
- 新建时生成可见安全默认值；
- 添加预览画布及目标反向选择；
- 让全局背景、左栏、按钮等目标在画布中可直接验证。

### P4：局部刷新、可访问性与窄屏适配

- 颜色变化只更新 CSS 变量和预览画布；
- 结构变化只更新当前目标卡；
- 保存前统一执行完整校验；
- 为清空、删除、排序按钮提供目标名称和动作名称；
- 使用语义 tab、dialog、fieldset 和焦点回收；
- 窄屏下改为可滚动分区和单层浮窗，避免二级浮层叠加。

## 八、非目标

- 不在本路线中重新设计主题色派生算法；
- 不开放任意 CSS 字符串和任意 CSS 属性；
- 不把不同表现目标改成共享图层数组；
- 不编写旧存档迁移兼容层；
- 不因追求 UI 简化而删除高级表现能力。

## 九、验收标准

- 普通用户进入主题编辑器时只看到少量可理解的主题选项；
- 每个颜色或表现覆盖都能看到最终值与来源；
- 区域新增图层写入当前选定目标，不再固定写入 `shell`；
- 任意 Host 都能使用同一套图层编辑能力；
- 新建表现目标具有可见安全默认值；
- 颜色修改不重建整个 Modal，结构操作不影响其他目标的焦点、折叠和滚动；
- 预览画布可以验证常用 UI 元素的实际效果；
- 类型检查、专项测试、全量测试和 Edge 验证均有记录。

## 当前裁定

Terra 建议整体采纳，但分两类处理：

- **立即纳入**：新增图层目标错误、数据模型收束、默认分层、来源可视化、空值表达、局部刷新和可访问性；
- **后续增强**：预览画布、创建向导、窄屏重排和完整 Host 迁移。

`roadmap-0013` 已完成的目标卡片与统一图层控件作为本路线的施工基础，不回退；后续重点从“继续添加表现字段”转向“隐藏复杂度、明确来源、统一数据模型”。

## P2-A：编辑器界面重排方案

本阶段只规划界面组织方式，不改变主题解析算法和数据模型。

### 1. 顶部由状态文案改为内容类型 Switch

当前的“编辑服务已开放 · 实时预览中”只表达权限状态，不帮助用户决定要编辑什么。后续顶部改为两层信息：

```text
用户自定主题                         [编辑权限：已开放]

[颜色] [控件背景图层] [其他内容]
```

- Switch 是编辑器的主内容导航，只允许同时激活一个内容类型；
- `颜色`：主题色、少量 Token、语义节点覆盖；
- `控件背景图层`：簇、区域、按钮、Tab、卡片、气泡等 Host 的表现层；
- `其他内容`：组件定位、动效、状态外观等暂不属于颜色或背景的高级内容；
- “编辑权限：已开放/只读”保留为次要状态徽标，不再占用主导航位置；
- 切换 Switch 只切换右侧内容区，不重建整个 Modal；
- 当前 Switch、筛选条件和展开状态属于编辑器临时 UI 状态，不写入用户主题数据。

### 2. 左栏改为语义筛选器

左栏不再列出“颜色 Token / 表现层 / 组件”三套平行入口，而是根据顶部内容类型显示对应的语义筛选器。

#### 颜色筛选器

```text
颜色
├─ 主题色
├─ 基础语义
│  ├─ 背景与面板
│  ├─ 文字与边框
│  └─ 点缀与强调
├─ 状态语义
│  ├─ 激活 / 高亮
│  ├─ 成功 / 警告 / 危险
│  └─ 玩家 / NPC 气泡
└─ 作用范围
   ├─ 根主题
   ├─ 左栏 / 中栏 / 右栏
   └─ 已配置的具体作用域
```

#### 控件背景图层筛选器

```text
控件背景图层
├─ 全局外部背景
├─ 簇
│  ├─ 顶部栏
│  ├─ 左侧栏
│  ├─ 中部栏
│  └─ 右侧栏
├─ 区域
└─ 控件
   ├─ 按钮
   ├─ Tab
   ├─ 信息卡片
   └─ 聊天气泡
```

其中“全局外部背景”是唯一的最外层背景入口，不作为普通 Host 混入簇、区域和控件树。

#### 其他内容筛选器

- 组件定位；
- 动效预设；
- 状态外观；
- 尚未配置的项目默认隐藏，只通过“添加覆盖/添加目标”进入。

### 3. 筛选结果采用“已配置优先”

- 左栏默认只显示当前已配置项目和少量推荐项目；
- 未配置项折叠在“添加覆盖”或“显示全部”中；
- 选择一个语义项后，右侧只显示该项的编辑器、最终生效值和来源链；
- 不再同时展开所有作用域和所有 Token；
- 当筛选结果为空时，显示空状态与下一步动作，而不是整页表单。

### 4. Switch 与筛选器的状态规则

| 操作 | 右侧内容 | 左栏状态 | 数据写入 |
| --- | --- | --- | --- |
| 切换内容 Switch | 切换对应编辑区 | 切换对应语义筛选器 | 不写入 |
| 选择筛选项 | 显示单个目标编辑器 | 保持选中项 | 不写入 |
| 修改颜色/图层 | 更新当前目标预览 | 保持选中项 | 写入 draft |
| 添加目标 | 追加目标并选中 | 更新已配置列表 | 写入 draft |
| 清除覆盖 | 回退父级/默认值 | 保持当前项 | 写入 draft |

### 5. 视觉与无障碍要求

- Switch 使用语义 `tablist` / `tab`，当前项明确标记；
- 左栏筛选器使用分组标题和可折叠分组，不使用大量无上下文按钮；
- 每个筛选项显示“已覆盖 / 继承 / 未设置”状态；
- 只读时 Switch 仍可浏览，但编辑控件禁用；
- 小屏下顶部 Switch 可横向滚动，左栏变为可收起抽屉，右侧只保留当前编辑器；
- 筛选和切换不改变 Modal 的滚动位置，不触发全局游戏 DOM 重建。

### 6. 实施顺序

1. 抽出编辑器临时视图状态：当前内容类型、当前筛选分组、当前目标；
2. 将现有三组导航映射为 Switch + 语义筛选器；
3. 保持现有字段选择器和事件协议，先只改变挂载位置；
4. 将目标渲染改为按选中项渲染，保留局部刷新；
5. 加入最终值、来源链和空状态；
6. 最后处理小屏、焦点和键盘导航。

### 7. 本阶段不做

- 不在本阶段新增颜色节点；
- 不改变 Host、背景或主题 Token 的运行时解析；
- 不把全局外部背景重新定义为普通 Host；
- 不实现完整预览画布；
- 不把所有高级选项一次性搬入“其他内容”。
